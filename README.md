# ◆ SavePoint

실리태번(SillyTavern)용 기억 확장이에요. **"무슨 일이 있었고, 그래서 지금 무엇이 달라졌는가"**를 함께 기록해요.

- 채팅방마다 기억을 따로 관리해요.
- 게임처럼 세이브 슬롯에 저장하고 불러올 수 있어요.
- **끝난 장면은 자동으로** 기록하고, 진행 중인 장면은 원문 그대로 둬요. 버튼으로 언제든 직접 세이브할 수도 있어요.


### 화면과 설정 (v0.5.4)

- 메뉴 탭이 창보다 길면 좌우 화살표가 나타나요. PC에서는 화살표나 탭 위의 마우스 휠로 이동하고, 모바일에서는 좌우로 밀 수 있어요.
- 채팅창의 💎 루팅 버튼은 마법봉 바로 오른쪽에 있어요.
- 확장 설정은 `연결·AI 요청`, `체크포인트·기록 확인`, `기억 주입`, `하이드·보관`, `화면`으로 접어 볼 수 있어요. 처음에는 연결 묶음만 펼치고, 이후에는 펼침 상태를 기억해요. 접힌 제목 아래에도 현재 설정 요약이 보여요.
- 기본값 안내는 평소에 숨겨 둬요. 설정을 바꾸면 그 칸에만 `↺`가 생기고(손가락을 올리거나 길게 누르면 기본값이 보여요), 묶음 제목에 `변경 N`이 붙어요. `↺`는 그 칸만, `↺ 이 묶음 되돌리기`는 해당 묶음의 설정만 기본값으로 되돌려요. 기억·세이브 슬롯·루팅 대기열은 유지해요. 체크포인트 묶음에는 기록 지침, 연결 묶음에는 요약 AI 선택도 포함돼요.


## 용어

| 이름 | 하는 일 |
|---|---|
| 체크포인트 | 장면이 끝나면 자동으로 기록 (새 메시지 20개마다 확인) |
| 퀵세이브 | 지금까지 바로 기록, 진행 중인 장면은 열어 둠 |
| 장면 클리어 | 진행 중인 장면까지 기록하고 닫음 |
| 세이브 슬롯 / 오토세이브 | 기억을 파일처럼 보관 / 방마다 최근 3개 자동 보관 |
| ⏪ 리와인드 | 마지막 작업 전으로 한 단계 돌아가기 |
| 불러오기 / ▶ 플레이 중 | 이 방의 기억을 슬롯으로 바꾸기 / 이 방에서 마지막으로 저장하거나 불러온 슬롯 표시 |
| 미기록 | 아직 기억에 기록되지 않은 메시지 |
| 💎 루팅 / ⏳ 대기열 | 꼭 남길 원문을 담기 / 다음 세이브에 반영할 항목 목록 |

## 설치

실리태번 → 확장 프로그램 → *Install extension*에 이 저장소 주소를 넣거나, `SavePoint` 폴더를 `public/scripts/extensions/third-party/` 아래에 넣으면 돼요.

설치 후 **마법봉 메뉴 → SavePoint**로 창을 열어요. 설정은 확장 설정 패널의 *◆ SavePoint*에 있어요.

## 화면 (상태창)

| 탭 | 내용 |
|---|---|
| 📜 저널 | 장면별 기록이에요. 제목, 장소, 등장 대상, 개요가 있고, 펼치면 포인트(◆ 상태 변화 / ◇ 기억할 순간)와 상세 노트가 보여요. ★는 메인 사건, 📌는 항상 핵심 한 줄을 주입한다는 표시예요. |
| ⏳ 대기열 | 루팅한 원문과 선택 메모예요. 다음 세이브에 반영되면 조용히 빠져요. |
| ❗ 퀘스트 | 약속, 목표, 빚, 수수께끼예요. 진행 중 / 완료 / 실패로 나뉘어요. |
| 👥 파티 | 인물별로 관계와 상태를 적어요. 관계는 점수가 아니라 실제로 한 행동으로 기록해요. |
| 🎒 인벤토리 | 누가 무엇을 가졌는지, 물건이 어떤 상태인지예요. |
| 🗺 월드 | 장소, 규칙, 별명, 비밀(누가 아는지 포함)이에요. |
| 💾 세이브 | 세이브 슬롯과 오토세이브 목록, 세이브 내보내기·가져오기, 백업 찾기·복구예요. |
| 👁 주입 | 지금 넣는 기억 전문, 영역별 토큰, **어떤 장면을 왜 회상했는지**를 보여 줘요. |

항목 옆의 `#123` 칩은 근거가 된 메시지 번호예요. 오른쪽 위 `EN/한` 버튼으로 한국어 보기를 켜고 끌 수 있어요. 한국어 보기는 `가 번역 채우기` 버튼으로 만들어요.

## 포인트 선택과 고정

저널의 포인트 앞 기호는 `● 선택됨 / ○ 선택 안 함 / 📌 우선 주입 고정`이에요. **선택한 내용은 기억 주입에 우선 반영해요.** 기호를 눌러 선택하거나 제외할 수 있고, 직접 고른 값은 이후 자동 판단으로 덮어쓰지 않아요. 선택 주체에 따라 기호나 테두리를 나누지 않아요.

포인트 옆 `📌`를 누르면 그 문장을 고정해요. 고정한 포인트는 앞쪽 기호도 `📌`로 바뀌고, 장면이 오래되거나 한 줄로 줄어도 영어 문장 전체를 우선 주입해요. 앞의 `📌`를 다시 누르면 고정 전 선택으로 돌아가요. 장면의 📌(핵심 한 줄 유지)와는 별개예요.

고정 문장은 같은 장면의 개요나 회상에 그대로 있으면 중복해서 넣지 않아요. 고정도 전체 주입 토큰 상한을 지키며, 들어가지 못한 고정 항목은 경고로 알려 줘요.

## 💎 루팅과 ⏳ 대기열

채팅창 왼쪽, 확장 메뉴(✦) 옆의 `💎`를 눌러요.

- **구절을 드래그한 채 누르면** 그 구절이 담긴 루팅 창이 열려요. 어느 메시지인지는 선택한 위치로 정해져요. `원문 전체` 탭으로 바꾸면 그 메시지 전체를 보거나 전체로 담을 수 있어요. 담기 버튼은 지금 열린 탭의 내용을 담아요. 선택이 여러 메시지에 걸치면 AI 답변별로 나눠 각각 담아요. 사용자 메시지 부분은 담지 않아요.
- **그냥 누르면** 가장 최근 AI 답변의 원문 전체가 열려요. `◀ ▶`로 다른 AI 답변을 고를 수 있어요.
- 루팅 창은 상태창과 같은 테마로 보여요. 창에서 구절을 고친 뒤 `⏳ 대기열에 담기`를 눌러요. 메모는 선택이고, 왜 중요한지 설명하는 용도예요. 이야기 속 사실의 근거로 쓰지 않아요.
- 휴대폰에서 버튼을 누르는 순간 선택이 풀려도 방금 고른 구절을 써요.
- 마크다운 기호와 공백 차이는 무시해 비교하고, 일치한 실제 구절을 저장해요. **담는 순간에는 AI를 호출하지 않아요.**

**번역 확장과 함께 쓸 때:** 원문은 두고 화면에만 번역을 보여 주는 번역 확장(실리태번의 `display_text` 방식)을 쓰면, 화면의 번역문에서 고른 구절도 담을 수 있어요. 이 항목은 번역문 구절로 표시되고, 세이브 때 요약 AI가 원문 메시지 전체를 읽고 그 번역이 가리키는 원문 부분을 찾아 기록해요. 번역문과 원문은 1:1로 맞지 않을 수 있어서 메모를 붙여 두면 더 정확해요. 번역문이 나중에 다시 번역돼도 원문이 그대로면 반영은 그대로 진행하고, 대기열에 `번역문이 바뀜`으로 알려만 줘요. 기록 확인도 번역문 구절은 글자가 아니라 뜻으로 원문과 비교해요.

- 대기열은 방의 채팅 파일에 저장돼서 새로고침해도 남아요. 상태 바의 `⏳ 대기열 N개` 또는 대기열 탭에서 발췌·메시지 번호·메모를 보고 삭제할 수 있어요. 세이브 슬롯을 불러와도 이 방의 대기열은 유지돼요. 대기열은 슬롯으로 다른 방에 옮기는 대상이 아니에요.
- 원문을 수정하거나 스와이프로 바꾸면 `원문이 바뀜`으로 표시하고 자동 반영을 보류해요. 저장된 발췌는 그대로 남아요. 새 원문으로 다시 루팅하고 이전 항목을 삭제할 수 있어요.
- 새 메시지의 루팅 항목은 다음 퀵세이브·체크포인트 수집 요청에 함께 보내요. 체크포인트는 끝난 구간의 항목만 반영하고, 진행 중인 장면의 항목은 대기열에 남겨요.
- 이미 기록된 메시지는 **해당 장면의 저널만 보충**해요. 이때 현재 물건·약속·인물 상태, 장면 개요나 열림/닫힘은 바꾸지 않아요. 장면별 보충 요청이 추가로 나갈 수 있어요. 새 대화가 없어도 퀵세이브로 처리할 수 있어요. 원문은 입력 한도에 맞춰 통째로 보내며, 한 메시지가 한도를 넘으면 자르지 않고 대기열에 실패 사유를 남겨요.
- 항목마다 고유 ID와 출처 방·메시지 번호, 메모와 당시 원문의 지문을 포인트에도 보존해요. 응답의 포인트가 항목 ID와 맞는 근거 메시지를 함께 가리키는지 코드로 확인해요. 같은 사건의 여러 발췌는 한 포인트로 묶을 수 있어요. **기록 확인을 켜 두면** 선택한 발췌의 뜻이 포인트에 맞게 담겼는지도 AI가 검토해요. 이 검토는 경고만 남기며 의미를 완전히 보장하는 검사는 아니에요.
- 반영한 포인트는 `●`로 저장하고, 이후 자동 판단이 선택을 덮어쓰지 않아요. 모든 상황에서 항상 주입하는 뜻은 아니에요. 압축 후에도 문장 전체를 우선 주입하려면 `📌`를 눌러요.
- 평소 포인트 목록에는 루팅 출처 표시가 없어요. 해당 포인트의 문장을 눌러 상세를 펼치면 `출처: 루팅`이 보여요. 내부 연결은 세이브·내보내기·방 이동 후에도 남아요.
- 리와인드는 그 뒤에 담거나 삭제한 대기열 항목을 유지해요. 되돌린 기억에서 빠진 루팅만 대기열로 돌려놓고, 복원된 기억에 이미 반영된 항목은 중복 대기시키지 않아요. 원문 수정으로 되감거나 예전 위치의 슬롯을 불러올 때도 같은 규칙으로 복원해요. 원문이 달라졌으면 `원문이 바뀜`으로 보류해요. 다른 방 출처는 원래 방을 유지하고 이 방 번호로 다시 연결하지 않아요.
- 기억과 대기열을 같은 저장 작업으로 기록해요. 저장 성공 뒤에만 반영된 항목을 제거해요. 실패·취소하면 항목은 남고, 반영을 요청했던 항목이 실패하면 `⚠ 반영 실패`와 알림으로 알려 줘요. 장면 경계 확인만 실패했거나 아직 요청에 넣지 않은 뒷구간의 항목은 실패로 표시하지 않아요. 다음 세이브 때 다시 시도하거나 직접 삭제할 수 있어요. 성공한 항목에는 별도 루팅 성공 알림을 띄우지 않아요.

## 세이브 버튼

- **⏺ 퀵세이브**: 마지막 메시지까지 바로 기록해요. AI가 장면을 나누고, 아직 끝나지 않은 마지막 장면은 **열린 장면**으로 남겨요.
- **■ 장면 클리어**: 마지막 메시지까지 기록하고 진행 중인 장면을 닫아요.

열린 장면은 다음에 기록할 때 **같은 장면에 새 구간으로 이어 붙어요.** 그래서 긴 장면도 여러 장면으로 나뉘지 않아요.

- 구간마다 **그 구간의 개요**(1~2문장)를 따로 저장해요. 장면 개요는 구간 개요를 순서대로 이은 거예요.
- 새 구간을 기록할 때 AI는 새 구간의 개요만 써요. **예전 구간의 개요와 포인트 선택은 다시 쓰지 않아서** 앞부분이 사라지지 않아요.

메시지가 많이 쌓였으면 원문 약 12,000자·최대 20개 메시지씩 작은 구간으로 나눠 순서대로 처리해요. 매 구간을 저장한 뒤에는 늘어난 기존 기억까지 포함해 **실제로 보낼 프롬프트 전체 길이**를 다시 계산하고, 설정의 입력 한도를 넘지 않게 다음 구간을 줄여요. 재요청도 보내기 전에 길이를 확인해요.

메시지 하나는 중간에서 자르지 않아요. 한 메시지가 12,000자를 넘더라도 전체 프롬프트가 입력 한도 안이면 그 메시지 하나를 통째로 처리해요. 메시지 하나와 수집 지침·기존 기억만으로 입력 한도를 넘으면 필요한 글자 수를 알리고 멈춰요. 입력 한도를 늘려 다시 시도할 수 있어요.

중간 구간이 실패하면 그 전까지만 저장하고, 실패한 구간부터는 원문을 그대로 남겨요. 다시 누르면 실패한 지점부터 이어서 처리해요. 진행 표시와 결과 복사에는 요청 입력의 글자 수도 나와요.


### 저장 중 안내

- 퀵세이브·장면 클리어·체크포인트(자동 저장)·기록 확인이 진행되는 동안 채팅 화면 위쪽에 게임 메시지 창처럼 `저장 중입니다…` 안내가 떠요. 상태창 테마를 따라가고, 채팅을 가리지 않아 계속 읽고 쓸 수 있어요. 누르면 SavePoint 창이 열려요. SavePoint 창이 열려 있을 때는 창 안에 진행 상황이 보여서 안내를 숨겨요.
- 끝나면 `✔ 저장 완료`로 잠깐 바뀌었다가 사라져요.
- 저장 중에 다른 채팅방으로 옮기면 그 저장은 취소돼요(다른 방 기억에 섞이지 않게 하는 안전장치예요). 옮긴 뒤 어느 방에서 어디까지 저장됐는지 알려 줘요. 그 방에 돌아오면 이어서 저장하라는 안내가 뜨고, 상태 칸의 `퀵세이브로 이어서`로 남은 부분을 기록할 수 있어요. 체크포인트는 그 방의 다음 답변 뒤에 알아서 다시 시도해요.

## 체크포인트 (자동 기록, 기본 켜짐)

- 마지막 자동 시도 이후 새 메시지(유저+캐릭터 합산)가 **20개** 쌓이면, 캐릭터 응답 생성이 끝난 뒤 시도해요. 사용자가 직접 숨긴 메시지는 세지 않고, 스와이프로는 개수가 늘지 않아요.
- 두 단계로 진행해요.
  1. 미기록 메시지에서 장면 경계만 확인해요. 응답 속 번호가 실제로 보낸 메시지인지, 범위 안인지, 순서가 맞는지 코드가 검사해요.
  2. **다음 장면이 시작된 것까지 확인된 장면**의 메시지만 넣고 기록해요. 진행 중인 장면의 원문은 이 단계에 들어가지 않아서, 그 장면의 물건·약속·관계 변화가 섞이지 않아요.
- 끝난 장면이 없으면 아무것도 기록하지 않고, 다음 20개가 쌓일 때까지 기다려요.
- `퀵세이브`로 중간 기록해 둔 장면의 끝을 체크포인트가 찾으면, **같은 장면에 이어 붙여 닫아요.** 새 메시지가 전부 다음 장면이면 추출 없이 그 장면만 닫아요.
- 미기록 내용이 입력 한도를 넘으면 자르거나 장면을 억지로 닫지 않아요. 대신 *"미기록 내용이 입력 한도를 넘어 체크포인트를 멈췄어요. `퀵세이브`를 눌러 주세요."*라고 안내해요. 퀵세이브나 장면 클리어가 성공하면 다시 켜져요.
- 체크포인트 기록 중에 새 생성이 시작되면(메인 API 사용 시) 그 시도는 취소되고, 생성이 끝난 뒤 다시 시도해요. 퀵세이브를 하면 체크포인트 카운터가 다시 0부터 세요.
- 상태 바에 다음 체크포인트까지 남은 개수와 마지막 체크포인트 결과가 보여요. 설정에서 끄거나 간격을 바꿀 수 있어요.
- AI가 장면 경계를 잘못 판단하면 장면이 나뉘어 기록될 수 있어요. 잠깐의 화제 전환이나 같은 외출 안에서의 짧은 이동은 장면 종료로 보지 않도록 프롬프트에 적어 뒀지만, 판단 오류를 완전히 막지는 못해요.

### 체크포인트가 실패하면

- 창을 닫아 둬도 짧은 알림이 떠요: `체크포인트 실패 (#40–#58) · 해당 구간 원문 유지`.
- 자세한 기록(실패 시각·단계·메시지 범위·이유·요청 횟수와 각 요청 결과)은 그 방의 채팅 파일에 저장돼서 새로고침이나 방 이동 뒤에도 상태 바의 `⚠ 체크포인트 실패 — 자세히`와 `📋 결과 복사`로 볼 수 있어요.
- 이 기록은 실패했던 구간이 실제로 기록·저장됐을 때만 지워져요. "끝난 장면 없음"으로 끝난 체크포인트는 지우지 않고, 퀵세이브가 일부만 저장했으면 남은 구간만 남겨요.
- 기록은 저장됐는데 그 뒤의 기록 확인(검토)만 실패한 경우는 따로 `저장 후 기록 확인 실패 · 기록은 저장됨`으로 표시해요.
- 다음 시도는 지금처럼 새 메시지가 체크포인트 간격만큼 쌓인 뒤에 해요.

## 기록 규칙

- AI는 먼저 체크리스트(약속, 물건, 부상·상태, 관계를 바꾼 행동, 비밀, 결정, 새 이름, 기억할 순간)를 훑고, 그다음 장면 → 대상 → 상태 변경 순서로 써요.
- **상태를 바꾼 일**은 시작과 결과를 함께 기록해요. 예: 주웠다 → 고쳐서 돌려줬다.
- **나중에 다시 꺼낼 만한 순간**은 한 줄로 남기고, 구체적인 내용은 상세 노트에 적어요.
- 캐릭터 카드와 페르소나에 이미 있는 정보는 기록하지 않아요.
- 응답 형식에 자리마다 뜻을 적어 둬요(인벤토리: `entity` = 물건, `holder` = 가진 사람). 검사에 걸리면 어느 변경이 왜 틀렸는지와 고치는 방법을 담아 다시 요청해요. 형식을 맞추려고 코드가 자리를 바꿔 넣지는 않아요.
- 코드가 응답을 검사해요. 근거 번호가 범위를 벗어나거나, 없는 항목을 참조하거나, 영어가 아니면 한 번 다시 요청해요. 그래도 통과하지 못하면 **저장하지 않아요.**
- 인물·물건·장소는 ID로만 가리켜요. 같은 별칭(예: 두 개의 `나침반`)을 가진 서로 다른 대상도 따로 기록하고, 이름이 같다는 이유만으로 합치지 않아요.
- AI가 ID 자리에 이름(`"Theo"`)을 쓰면, 그 이름이 등록된 대상 **딱 하나**의 이름·별칭과 같을 때만 코드가 그 ID로 연결해요. 둘 이상과 맞으면(예: 고양이와 교차로가 둘 다 `Pip`) 추측하지 않고 다시 요청해요.
- AI가 두 번째 이후 장면에 `continue`(앞 장면에 이어짐)를 적으면, 그 장면을 바로 앞 장면에 합쳐요(포인트·노트는 이어 붙이고 개요는 이어 씀). 합친 사실은 상태 바의 `자동 보정` 줄과 `결과 복사`에 남아요.
- 두 번째 이후 장면의 시작 번호는 근거가 분명할 때만 고쳐요: 직접 숨긴 메시지처럼 이번 요청에 없는 번호면 다음 실제 메시지로, 비어 있으면 그 장면 포인트가 처음 가리킨 메시지로 옮겨요. 이때 앞 장면 포인트는 모두 그보다 앞 메시지를, 이 장면 포인트는 모두 그 뒤 메시지를 가리켜야 해요. 그 밖의 경우(앞 장면보다 앞 번호, 형식이 잘못된 장면 등)는 고치거나 합치지 않고 AI에게 다시 요청해요. 고친 내용은 상태 바의 `자동 보정`에 남아요.
- 포인트의 근거 번호는 그 포인트가 속한 장면 안에 있어야 해요. 일부만 밖이면 밖의 번호를 빼고, 전부 밖이면 다시 요청해요. 같은 포인트가 두 장면에 겹쳐 들어가는 걸 막아요.
- 내기·벌칙·규칙은 원문이 말한 조건 그대로(이긴 쪽, 진 쪽, 무승부 각각) 기록해요. 둘 다 같은 걸 하기로 했으면 누구도 빚진 게 아니에요.
- 같은 구간 안에서 맺고 지킨 약속은 처음부터 `완료`로 기록해요.
- **빚·약속에는 조건 원문이 붙어요.** 새로 기록하거나 조건이 바뀔 때 AI가 조건을 정한 원문(메시지 번호 + 그대로 옮긴 문장)을 함께 내야 해요. 코드가 그 문장이 그 메시지에 실제로 있는지 확인하고(별표·따옴표·띄어쓰기 차이는 무시), 앞뒤 두 문장씩을 원문에서 직접 가져와 같이 저장해요. 그래서 조건의 한쪽만 따와도 바로 뒤에 이어지는 다른 쪽 조건이 같이 남아요.
- "약속을 지켰다", "빚을 갚았다"처럼 상태만 바꿀 때는 원래 조건을 그대로 두고 완료 근거만 더해요.
- 조건 원문은 퀘스트 탭의 `근거 원문`에서 볼 수 있고, **기억 주입에는 넣지 않아요.**
- 기록은 모두 영어로 해요. 이름과 별칭만 원문 표기를 그대로 둬요(예: `나침반`). 이 별칭 덕분에 한국어 대화에서도 관련 장면을 찾을 수 있어요.

## 기록 확인 (경고만)

기록이 저장된 뒤 AI가 근거 원문과 비교해요(설정에서 끌 수 있어요). 분량에 따라 여러 요청으로 나누므로 추가 호출 수가 늘 수 있어요.
- **원문과 다름:** 근거 원문을 다시 읽어 보니 다르게 해석된 경우. 예: 농담으로 한 말을 진짜 빚으로 기록함
- **충돌 · 판단 보류:** 기록과 저널이 서로 다른데 원문으로 어느 쪽이 틀렸는지 결정할 수 없는 경우
- 찾으면 상태 바에 `⚠ 확인 필요 N건`이 떠요. 펼치면 충돌한 두 문장과 원문 발췌가 보이고, `편집` 또는 `무시`를 고를 수 있어요.
- **기록을 자동으로 고치지는 않아요.** 검토가 실패해도 이미 저장한 기억은 유지돼요.
- 검토용 원문은 700자·2,000자·6,000자에서 자르지 않아요. 각 기록·포인트·개요를 판단하는 데 필요한 **메시지 전체**를 함께 보내고, 같은 사건의 항목은 가능한 한 같은 요청에 묶어요.
- 개요는 해당 구간의 메시지 전체를 근거로 보내요. 약속·빚에 조건 원문이 있으면 첫 근거부터 마지막 근거 사이 메시지도 함께 보내요.
- 한 항목의 근거 전체가 입력 한도를 넘거나 원문이 없으면 그 항목은 **검토 보류**로 표시해요. 일부만 읽고 `문제 없음`으로 표시하지 않아요. 다른 항목은 계속 검토해요.
- 확인 자체가 실패하거나 중단되면 `기록 확인 실패`로 따로 표시해요. 모든 요청을 마치기 전에는 전체 검토가 완료됐다고 하지 않아요.
- 실패 내용과 경고 목록이 길면 그 칸 안에서 스크롤돼요.

## 결과 복사

상태 바의 `📋 결과 복사`를 누르면 버전, 요약 AI, 마지막 실패, 기록 확인 결과(경고마다 종류·대상 문장·이유·AI 판단·판단 보류 이유·인용·근거 번호), 보낸 원문 범위(일부만 보냄 / 못 보냄)를 글로 복사해요. 캡처 대신 그대로 붙여 넣으면 돼요. 자동 복사가 막힌 환경에서는 글 상자를 띄워요.

## 요청 상태와 제한 시간

- 진행 표시: `퀵세이브 1/2구간 #0–#54 · 첫 요청 · 응답 대기 42초`, `재요청 (검사 실패 3건) · 응답 대기 …`, `응답 받음 (38초) · 검사 중`.
- 연결 프로필은 기본으로 **실시간 수신**을 사용해요. `수신 중 · 사고 N자 / 본문 N자`로 응답이 실제로 오는지 표시하고, 최종 응답과 검사가 끝나야 기억을 저장해요. API가 실시간 수신을 지원하지 않으면 설정에서 끌 수 있어요. 메인 API는 기존 일괄 응답 방식을 유지해요.
- `추론 강도`는 채팅 완성 연결 프로필에만 적용돼요. 기본은 프로필 설정을 따르며, 지원하는 API에서 `low / high / max`를 선택할 수 있어요. 모델에 따라 지원 값과 효과가 달라요. 연결 프로필 자체나 메인 채팅 설정은 바꾸지 않아요.
- `짧은 연결 시험`은 대화 원문을 보내거나 기억을 변경하지 않고 작은 요청 한 번으로 연결을 시험해요(응답 상한 1,024토큰, 최대 60초). 성공은 짧은 본문 응답을 받았다는 뜻이며, 긴 대화의 수집 성공을 보장하지 않아요.
- `📋 결과 복사`에는 마지막 요청의 입력 길이, 응답 상한, 실시간 수신 여부, 요청한 추론 강도, 사고·본문 수신 글자 수와 첫 내용 수신 시간이 포함돼요. 종료 사유는 API가 제공했을 때만 표시해요. 사고 원문은 저장하지 않아요.
- 첫 응답이 오기 전에는 모델이 생각 중인지 서버에서 대기 중인지 구분할 수 없어요. 실시간으로 내용이 와도 설정한 전체 요청 제한 시간은 그대로 적용돼요.
- 설정의 `요청 제한 시간`(기본 300초)이 지나면 그 요청을 취소하고, 그 구간은 저장하지 않고 원문을 그대로 둬요. 연결 프로필 요청과 메인 API 요청 모두 같아요.
- 제한 시간 뒤에 늦게 도착한 응답은 버려요. 저장되지도, 새로 시작한 작업의 진행 표시를 바꾸지도 않아요.
- 실리태번이 `API request failed`로 감싼 원래 오류도 꺼내서 보여 줘요. 예: `API request failed ← Request too large… (상태 413)`.
- 실패하면 `마지막 실패`에 시도마다 걸린 시간, 응답 길이, 결과(빈 응답 / 생각 부분만 있음 / JSON 해석 실패 / 검사 실패 N건 / 요청 오류 / 제한 시간 초과)가 남아요.

## 하이드와 원문 변경

- 세이브된 메시지만 숨겨요. **최근 10개**와 아직 세이브하지 않은 메시지는 항상 보이게 남겨요.
- 체크포인트·퀵세이브·장면 클리어로 저장할 때마다 **#0부터 기록 완료 위치까지** 다시 확인해요. 설정한 최근 N개를 제외하고, 하이드를 놓친 앞쪽 메시지도 함께 숨겨요.
- 직접 하이드를 풀어 읽은 메시지는 평소에는 펼쳐 둬요. 다음 세이브 때는 다시 하이드 대상에 포함돼요. 퀵세이브를 눌렀는데 새로 기록할 메시지가 없어도 하이드 상태를 다시 확인해요(추가 AI 호출 없음).
- 기억과 하이드 표시는 **같은 채팅 파일에 한 번에** 저장돼요. 그래서 파일 안에서 "기억은 없는데 메시지만 숨겨진" 상태는 생기지 않아요.
- 저장 요청이 오류를 내면 이번 변경(기억, 기록 위치, 하이드)을 모두 되돌리고 알려 줘요.
- 다만 실리태번은 서버 저장 실패를 대부분 자체 알림("Chat could not be saved")으로만 처리하고, 확장 쪽에는 실패를 알려 주지 않아요. 이 알림이 보이면 화면의 변경은 남아 있지만 아직 파일에 저장되지 않은 상태예요. 다음 채팅 저장 때 함께 저장되고, 새로고침하면 마지막으로 저장된 상태로 돌아가요.
- 💾 오토세이브는 서버 파일에 따로 남기는 **복사본**이에요. 하이드나 기억 저장이 오토세이브의 완료를 기다리지는 않아요.
- 세이브된 메시지가 수정·삭제되거나 스와이프로 바뀌면, 그 메시지가 들어 있던 구간부터 뒤의 기록을 모두 되감아요. 숨김도 그 지점부터 풀어요. 다시 세이브하려면 버튼을 눌러 주세요.
  - 세이브 직후 마지막 답을 리롤해도 마지막 구간이 되감겨요. 리롤을 마친 뒤 세이브하는 걸 추천해요.
- 기록 보관 범위보다 앞쪽의 원문이 바뀌면(세이브를 불러온 방 등) 창 위쪽에 안내가 떠요. 두 가지 중에서 고를 수 있어요.
  - `지금 원문 기준으로 인정`
  - `리셋`
- **⏪ 리와인드**는 마지막 작업(체크포인트, 퀵세이브, 장면 클리어, 편집, 불러오기, 비우기) 전으로 한 단계 돌아가요.

## 주입

**저장하는 기억과 매번 넣는 기억은 달라요.**
- 장면의 포인트는 모두 저장돼요. 그중 **주입 포인트(●)**만 개요와 함께 들어가요. 나머지(○)는 저널에서 볼 수 있고, 관련 대화가 나오면 상세 기억 회상에 쓰여요.
- 주입 포인트는 기록할 때 AI가 골라요. 기준은 "개요와 상태 목록에 이미 들어간 내용이 아닌, 중요한 결과·미해결 사항·회상 단서"예요. 더할 게 없으면 하나도 고르지 않아요.
- 주입 포인트는 그 구간의 개요 기준으로 골라요. 나중에 구간이 더 붙어도 다시 판단하지 않아요.
- ● 포인트가 개요에 **문장 그대로** 들어 있으면 그 주입에서만 빼요(`개요와 같음 · 주입 생략`). 저장된 선택은 바뀌지 않고, 직접 누른 ●는 빼지 않아요. 많이 겹치기만 하는 건 `중복 후보`로 표시만 해요.
- 📜 저널에서 포인트 앞 ●/○를 누르면 선택을 바꿔요. 직접 지정한 값은 주입 포인트를 다시 골라도 유지돼요. 다시 누르면 반대 선택이 되고, 자동 판단으로 되돌아가지는 않아요.
- 장면 카드의 `⟳ 주입 고르기`는 다시 수집하지 않고 그 장면의 주입 포인트만 다시 골라요.

- 전체 상한(기본 6,000토큰)을 넘지 않아요.
- 📌 항목은 최소 한 줄을 가장 먼저 자리 잡아요. 그래도 상한을 넘으면 빠진 개수를 상태 바와 👁 주입 탭에 표시해요.
- 그다음 넣는 순서: 지금 장면과 관련된 상태 → 상세 기억 회상 → 최근 장면 → ★ 장면 → 그 밖의 장면 → 오래된 장면 제목(별도 상한 600토큰)
- 영역별 배분(상태 35% / 저널 50% / 회상 15%)은 기본값이에요. 남는 몫은 다른 영역이 써요.
- **상세 기억 회상**: 최근 대화와 연결된 장면 1~2개에서, **이번 주입에 실제로 들어가지 않은 것**(○ 포인트, 예산 때문에 빠진 ● 포인트, 상세 노트)을 꺼내 넣어요. 최근 장면도 대상이에요.
  - 포인트 하나, 노트 문장 하나 단위로 대화와 잘 맞는 것부터 최대 6개(장면당 4개)를 넣어요.
  - 회상 몫(기본 15%)을 넘지 않고, 이미 주입문에 있는 문장은 다시 넣지 않아요.
  - 연결 기준: 이름·별칭, 겹치는 단어 세 개 이상, 숫자(점수, 시간 등).
  - 캐릭터 카드와 페르소나의 이름만으로는 회상하지 않아요(매번 나오니까요). 거의 모든 장면에 나오는 이름도 마찬가지예요.
  - 한국어 대화와 영어 기록은 별칭으로 이어져요. 별칭이 영어로만 기록된 물건은 한국어 대화에서 찾지 못할 수 있어요.
- **원문 회상**은 설정에서 따로 켤 수 있어요(기본 꺼짐). 원문이 한국어면 한국어가 섞여 들어가요.

## 세이브 슬롯

💾 탭은 이렇게 나뉘어요. 묶음마다 직접 만든 슬롯이 맨 위에, 만든 순서대로 고정돼요(이름을 바꾸거나 저장해도 자리가 그대로예요). 오토세이브는 그 아래예요.
- **이 방**: 이 방에서 만든 슬롯과 오토세이브(최신 / 이전 / 그 전)
- **(캐릭터)의 다른 방**: 같은 캐릭터의 다른 채팅방 슬롯, 방별로 묶임(📁 날짜·시각 채팅)
- **다른 캐릭터**: 캐릭터 카드별로 접혀 있어요


- **불러오기**: 이 방의 기억을 이 슬롯으로 바꿔요. 슬롯은 자동으로 갱신되지 않고, `저장`을 눌러야만 덮어써져요. 같은 슬롯에서 여러 방으로 갈라져 진행해도 원래 슬롯은 그대로예요.
- **▶ 플레이 중**: 이 방에서 마지막으로 저장하거나 불러온 슬롯에 붙어요. 이어서 저장할 슬롯을 찾기 쉽게 해 주는 표시예요. 오토세이브에는 붙지 않아요.
- **저장**: 직접 만든 슬롯(FILE)을 지금 기억으로 덮어써요. 확인을 한 번 거쳐요.
- 원문이 같은 방이나 분기(실리태번의 Branch 등)에서 불러오면, 저장 당시 위치와 하이드까지 그대로 돌아가요. 그 뒤 메시지는 미기록이 돼요.
- 원문이 다른 새 방에서는 기억을 가져오고 이 방의 메시지는 #0부터 전부 미기록으로 시작해요. **진행 중이던 장면은 열린 채로 유지**하고, 새 방의 수집도 같은 장면에 새 구간으로 이어 붙일 수 있어요. 실제로 이야기가 다음 장면으로 넘어가거나 장면 클리어를 눌렀을 때 닫아요.
- 근거는 구간별로 출처를 보관해요. 이전 방 번호는 `이전 방 #48`처럼 표시하고 현재 방의 #48로 조회하지 않아요. 여러 방을 거쳐도 원래 출처를 유지해요. 원문 회상도 현재 방 구간만 사용해요.
- 예전 약속을 새 방에서 지키는 등 상태 업데이트는 정상 저장돼요. 검토는 현재 방 근거와 저장된 조건 인용·문맥을 비교할 수 있지만, 이전 원문 전체를 읽은 것은 아니므로 `근거가 이전 방에 있음 · 판단 보류`로 확인 범위를 구분해요.
- **오토세이브**: 기억이 기록될 때마다 방마다 최근 3개(최신 / 이전 / 그 전)를 남겨요. 잘못 기록됐을 때 두 단계 전까지 돌아갈 수 있어요. 오토세이브에 이름을 붙이면 세이브 슬롯으로 따로 보관돼요.

## 저장 위치와 백업

세이브 슬롯과 오토세이브는 **실리태번 서버의 사용자 파일 폴더**(`data/<사용자>/user/files/`)에 파일로 저장돼요. 실리태번을 PC에서 돌리면 그 PC에 남고, 클라우드에 올라가지는 않아요.

| 파일 | 내용 |
|---|---|
| `savepoint-index.json` | 슬롯 목록 (정식 목록) |
| `savepoint-index.prev.json` | 바로 전 목록 |
| `savepoint-slot-<id>.json` | 직접 만든 슬롯 하나 |
| `savepoint-auto-<방>-0~3.json` | 방마다 오토세이브 (4개 이름을 돌려 쓰며 3개 보관) |

- 실리태번 설정 파일에는 목록의 **복사본**만 있어요. 화면을 빨리 보여 주기 위한 것이고, 서버 목록과 따로 바뀌지 않아요.
- 저장 순서는 항상 **새 파일 저장 → 목록 갱신 → 필요 없는 파일 삭제**예요. 중간에 실패해도 목록에 있는 파일이 지워지지 않아요.
- 서버에 쓸 수 없으면 그 슬롯은 설정에만 저장되고 `설정에만 있음`으로 표시돼요. 다음에 실리태번을 열 때 서버로 옮겨요.

**복구할 수 있는 경우**

| 상황 | 복구 |
|---|---|
| 실리태번 설정이 날아감 / 초기화 / 확장 재설치 | ✅ 서버 목록을 읽어서 슬롯이 저절로 다시 보여요 |
| 목록 파일만 없어짐 | ✅ `🔍 백업 찾기`가 이전 목록을 보여 주고, 고른 것을 `↩ 복구`해요 |
| 목록 파일 둘 다 없어짐 | 🔸 그 방을 열고 `🔍 백업 찾기`를 누르면 **그 방의 오토세이브**는 찾아요. 직접 만든 슬롯은 자동으로 찾을 수 없어요. 서버 폴더에서 `savepoint-slot-….json`을 찾아 `📥 세이브 가져오기`로 불러와야 해요 |
| 실리태번 데이터 폴더 전체가 사라짐 | ❌ `📤 세이브 내보내기`로 받아 둔 .json 파일만 남아요 |

- `🔍 백업 찾기`는 찾은 백업을 **보여 주기만** 하고 아무것도 바꾸지 않아요. 실제로 되살리는 건 `↩ 복구`예요.
- `📤 세이브 내보내기`(이 방 기억)와 슬롯 카드의 `📤`(그 슬롯)는 .json 파일을 내 기기로 내려받아요. `📥 세이브 가져오기`는 그 파일을 새 슬롯으로 불러와요. 데이터 폴더 전체를 잃는 경우에 대비하려면 가끔 내려받아 두세요.

## 설정

요약 AI(연결 프로필 / 메인 API), 응답 최대 토큰, 한 번에 보낼 입력 한도, 주입 상한과 위치, 하이드, 테마(클래식 JRPG / 네온 아케이드 / 글래스 사이버 / 다크 아카이브 / 파스텔 드림 / 터미널 / 딸기우유 / 듀얼 화이트 / 먹과 한지 / 크림 라테 / 바닐라 버터 / 스토리 콘솔 / 레몬 인형뽑기 / 실리 테마. 모두 CSS만 써서 이미지나 글꼴을 따로 불러오지 않아요), 기록 지침을 바꿀 수 있어요. 기록 지침 뒤에는 데이터 목록과 응답 형식이 자동으로 붙어요.

### v0.5.17 · 퀵세이브 응답 보완

제목·개요가 빠졌어도 포인트 형식이 정상이라면 임시 제목·포인트 기반 개요로 보완해요. 근거 번호와 상태 변경 검사는 그대로 거쳐요. 임시 제목은 이후 이어지는 기록의 정상 제목으로 교체할 수 있고, 직접 고친 제목은 보호해요. 임시 개요는 중복 판정의 기준에서 빼고, 주입할 때 같은 문장을 반복하지 않아요. 재요청에는 숨긴 메시지를 제외한 실제 사용 가능한 번호와 앞 장면 시작 번호를 알려 줘요.

날짜는 장면 안의 기록 구간(g1, g2…)에 저장해요. 인포박스는 필수가 아니고 본문에 나온 날짜·시간 진행을 기존 수집 요청에서 함께 읽어요. 시간만을 위한 추가 AI 호출은 하지 않아요.

- 날짜·시간대·시각과 원문 근거를 보관해요. 시간대는 새벽·아침·낮·오후·저녁·밤으로 표시해요.
- 장면 옆에는 구간들의 시간 범위, 상세에는 구간별 시작·끝 시간과 확인 수준을 보여 줘요.
- 확인된 날짜가 없으면 `기록 기준 N일째`를 사용해요. 이야기 자체의 시작일이라는 뜻은 아니에요. 명확한 `다음 날` 같은 진행 근거가 있어야 일 수가 증가해요.
- `몇 주 뒤` 같은 점프는 새로운 기준으로 남겨요. 그 뒤의 일 수는 새 기준 안에서만 이어지고, 전체 며칠째인지 숫자를 지어내지 않아요.
- 실제로 과거를 연기하는 `회상` 구간은 기록하되, 마지막 현재 시간은 움직이지 않아요. 미래 약속·단순 과거 언급·가정도 현재 시간을 진행시키지 않도록 수집 AI에 지시해요.
- 원문에 명시된 시간은 보낸 원문에서 인용이 확인돼야 해요. 이전 기준에서 연결하려면 그 기준과 시간 경과 근거가 필요해요. 잘못되거나 근거가 없는 시간은 `미확인`으로 두고 기억 내용은 계속 저장해요. 코드의 인용 확인은 문자열 존재 확인이며, 문맥의 의미 판단은 수집 AI가 담당해요.
- 구간을 펼쳐 `시작 ✎` 또는 `끝 ✎`로 수정할 수 있어요. 직접 지정은 AI가 덮지 않고, 이후 상대적으로 연결된 구간만 다시 계산해요. 그 뒤에 별도로 명시된 날짜와 다른 직접 지정은 보존해요.
- 기억 주입 맨 위에 `Last recorded story time:`을 넣어요. 마지막 기록 뒤의 대화가 더 최신일 수 있음을 함께 알려 줘요. 이 줄도 주입 토큰 상한에 포함돼요.
- 세이브·내보내기·다른 방에서 불러오기·리와인드에 시간 기준도 함께 보관해요. 이전 방의 시간 근거 번호로 현재 방 원문을 조회하지 않아요. 기존 날짜 미상 기록을 강제로 재수집하지 않아요.

정확한 달력 덧셈은 유효한 `YYYY-MM-DD` 날짜에만 적용해요. 작품 고유 달력은 원래 표현과 상대 일 수를 보존해요(예: `왕국력 312년 봄 3일 +1일`). 실제 컴퓨터 날짜와 메시지 작성 시각은 이야기 시간으로 쓰지 않아요.
