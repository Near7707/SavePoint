# ◆ SavePoint

실리태번(SillyTavern)용 기억 확장이에요. **"무슨 일이 있었고, 그래서 지금 무엇이 달라졌는가"**를 함께 기록해요.

- 채팅방마다 기억을 따로 관리해요.
- **체크포인트**가 새 메시지 N개마다 자동으로 퀵세이브해요. 진행 중인 장면은 열어 둔 채 기록하고, 최근 2개 메시지는 스와이프·수정에 대비해 남겨요.
- 기록한 메시지는 하이드해서 채팅 컨텍스트를 가볍게 유지하고, 대신 정리된 기억을 주입해요.
- 게임처럼 세이브 슬롯에 저장하고 불러올 수 있고, 기록할 때마다 오토세이브가 쌓여요.
- 장면마다 이야기 속 날짜·시간과 약속 기한을 함께 기록해요.

## 용어

| 이름 | 하는 일 |
|---|---|
| 체크포인트 | 새 메시지 N개마다 자동으로 퀵세이브 (기본 20개, 최근 2개는 여유분으로 남김) |
| 퀵세이브 | 마지막 메시지까지 바로 기록, 진행 중인 장면은 열어 둠 |
| 기록하고 장면 닫기 | 진행 중인 장면까지 기록하고 닫음 (📜 저널의 진행 중 장면에 있어요) |
| 미저장 | 아직 기억에 기록되지 않은 메시지 |
| QUICK / 오토세이브 / 세이브 슬롯 | 퀵세이브 시점 방마다 1개 / 기록할 때마다 방마다 최근 3개 자동 보관 / 이름 붙여 직접 보관 |
| 불러오기 / ▶ 플레이 중 | 이 방의 기억을 슬롯으로 바꾸기 / 이 방에서 마지막으로 저장하거나 불러온 슬롯 표시 |
| ⏪ 리와인드 | 마지막 저장·리셋·세이브 불러오기 전으로 한 단계 돌아가기 |
| 💎 루팅 / ⏳ 대기열 | 꼭 남길 원문을 담기 / 다음 세이브에 반영할 항목 목록 (💠 메인 위쪽 알림 칸에 있어요) |

## 설치

실리태번 → 확장 프로그램 → *Install extension*에 이 저장소 주소를 넣거나, `SavePoint` 폴더를 `public/scripts/extensions/third-party/` 아래에 넣으면 돼요.

설치 후 **마법봉 메뉴 → SavePoint**로 창을 열어요. 설정은 확장 설정 패널의 *◆ SavePoint*에 있어요.

## 화면 (상태창)

| 탭 | 내용 |
|---|---|
| 💠 메인 | 처음 여는 화면(STATUS)이에요. 알림(⏳ 대기열·📦 복귀 확인), 지금 장면과 짧은 개요, 진행 중 퀘스트, 현재 파티, 아이템, 접혀 있는 최근 변화를 한눈에 봐요. 화면용이라 주입과는 상관없어요. |
| 📅 타임라인 | 기록된 구간을 최근 기록부터 모아 봐요. 아래 [타임라인](#타임라인) 참고. |
| 📜 저널 | 장면별 기록이에요. 제목, 장소, 등장 대상, 이야기 시간, 개요가 있고, 펼치면 포인트(◆ 상태 변화 / ◇ 기억할 순간)와 상세 노트가 보여요. ★는 메인 사건, ⚓는 항상 핵심 한 줄을 주입한다는 표시예요. |
| ❗ 퀘스트 | 약속, 목표, 빚, 수수께끼예요. 진행 중 / 완료 / 실패로 나뉘고, 약속·빚에는 기한이 보여요. |
| 👥 파티 | 인물별로 관계와 상태를 적어요. 관계는 점수가 아니라 실제로 한 행동으로 기록해요. |
| 🎒 인벤토리 | 누가 무엇을 가졌는지, 물건이 어떤 상태인지예요. 아래 **📦 보관함**에 지금 이야기에 쓰지 않을 물건을 넣어 둘 수 있어요. |
| 🗺 월드 | 장소, 규칙, 별명, 비밀(누가 아는지 포함)이에요. |
| 💾 세이브 | 세이브 슬롯과 오토세이브 목록, 세이브 내보내기·가져오기, 백업 찾기·복구예요. |
| 🧿 주입 | 지금 넣는 기억 전문, 영역별 토큰, **어떤 장면을 왜 회상했는지**를 보여 줘요. |

- 파티·인벤토리·월드의 근거 메시지 번호는 본문 아래에 표시해요. 긴 본문도 카드 너비 전체를 사용해요. 인벤토리의 소지자는 오른쪽 위에 유지하고, 긴 물건 이름은 왼쪽에서 줄바꿈해요.

- 위쪽 상태 칸에는 진행 중인 장면, 진행 바, 세이브 버튼과 **요약 줄 하나**(`미저장 12 · 주입 844 / 6,000 토큰 · ⚠ 실패 1`)가 늘 보여요. 주입 토큰은 현재 사용량 / 설정한 상한이고, 긴 요약 줄은 줄바꿈해 표시해요. 요약 줄을 누르면 이야기 시간, 다음 체크포인트, 마지막 자동 저장 시도·실제 기록, 실패·확인 상세, `📋 결과 복사`가 펼쳐져요. 휴대폰 폭에서는 처음에 접혀 있고 넓은 화면에서는 펼쳐져 있어요. 한 번 바꾸면 그 선택을 기억해요. 실패나 확인할 일이 있으면 요약 줄이 경고색이 돼서 접혀 있어도 놓치지 않아요. 하이드 방식이 수동이면 진행 바 옆에 `👻 하이드 · N` 버튼이 떠요(숨길 게 있을 때만).
- 항목 옆의 `#123` 칩은 근거가 된 메시지 번호예요. `🌐 번역` 버튼 하나로 한국어 보기를 다뤄요: `🌐 번역`(한국어 보기 켜기, 빠진 번역이 있으면 채움) → `🌐 원문`(원문으로 돌아가기). 한국어로 보는 중에는 버튼이 켜진 색이에요. 번역이 빠진 항목(새 기록, 번역 실패)은 다시 `🌐 번역`을 켤 때 채워요. `🌐 원문`은 언제든 눌러져요.
- 💠 메인 맨 위 줄은 `마지막 저장 기준 #N · 미저장 N개`예요. 그 뒤 대화는 아직 반영 전이에요. 탭에 붉은 숫자가 있으면 대기열이나 복귀 확인할 물건이 있다는 뜻이에요. 최근 변화는 마지막 저장 한 번에서 추가·변경·사라짐·완료된 것들이에요.
- 창 위쪽 `⚙`는 **빠른 설정**이에요: 스킨, 주입 상한, 체크포인트·간격, 하이드 방식·하이드하지 않을 최근 메시지, 요약 AI, `더 보기`(보관함 방식·처음 여는 탭 등), `전체 설정 열기`. 저장 중에 바꾼 요약 AI·보관함 방식은 저장이 끝난 뒤 적용돼요.
- 처음 여는 탭은 설정 `처음 여는 탭`(기본 💠 메인)으로 바꿀 수 있어요. 방마다 마지막으로 보던 탭을 기억해요(다른 방에 다녀와도 그대로). 처음 여는 방에만 이 설정이 적용돼요.
- 탭이 창보다 길면 가려진 쪽에만 작은 동그라미 화살표가 뜨고, 그쪽 가장자리가 흐려져요. PC에서는 화살표나 탭 위의 마우스 휠로, 휴대폰에서는 좌우로 밀어서 이동해요.
- 본문 스크롤 위치는 현재 페이지에서 방·탭별로 따로 기억해요. 다른 탭을 보거나 창을 닫았다 열어도 보던 위치로 돌아와요. 처음 여는 탭은 맨 위에서 시작하고, 타임라인의 `저널에서 보기`처럼 특정 기록으로 이동하면 그 기록을 우선 보여 줘요.

## 세이브 버튼

- **⏺ 퀵세이브**: 마지막 메시지까지 바로 기록해요. AI가 장면을 나누고, 아직 끝나지 않은 마지막 장면은 **열린 장면**으로 남겨요. 방을 옮기기 전에 눌러 두면 좋아요.
- **⏪ 리와인드**: 마지막 저장(퀵세이브·체크포인트·기록하고 장면 닫기), 리셋, 세이브 불러오기 중 마지막 것을 되돌려요. 누르면 무엇을 되돌리는지 확인창에 보여요(예: `퀵세이브 #0–#5 전으로 되돌릴까요? 그 뒤에 한 편집 1개도 함께 되돌아가요`). 되돌릴 게 없으면 그렇게 알려요.
- **👻 하이드 N**: 하이드 방식이 수동일 때만 보여요(아래 [하이드와 원문 변경](#하이드와-원문-변경)).
- **🌐 번역 / 🌐 원문**: 한국어 보기 켜기·끄기.
- 버튼 줄은 `퀵세이브 · 리와인드 · 하이드 · 번역` 한 줄이에요. 휴대폰 폭에서도 줄바꿈하지 않고, 👻 숫자가 바뀌어도 버튼 폭이 그대로예요. 저장 중에는 퀵세이브 자리에 `■ 중지`가 떠요.
- **기록하고 장면 닫기**: 📜 저널의 진행 중 장면 카드에 있어요. 마지막 메시지까지 기록하고 그 장면을 닫아요. 보통은 AI가 장면 전환을 판단하니 퀵세이브로 충분하고, "여기서 장면을 끊고 싶다"할 때 써요. 새 메시지가 없으면 장면만 닫아요.

열린 장면은 다음에 기록할 때 **같은 장면에 새 구간으로 이어 붙어요.** 그래서 긴 장면도 여러 장면으로 나뉘지 않아요.

- 구간마다 **그 구간의 개요**(1~2문장)를 따로 저장해요. 장면 개요는 구간 개요를 순서대로 이은 거예요.
- 새 구간을 기록할 때 AI는 새 구간의 개요만 써요. **예전 구간의 개요와 포인트 선택은 다시 쓰지 않아서** 앞부분이 사라지지 않아요.
- 구간이 이야기 중간에서 끝나도 결말을 미리 단정하지 않아요. 물건을 건넸다가 나중에 돌려받으면, 건넨 사건은 그대로 두고 현재 소지자만 바뀌어요.

메시지가 많이 쌓였으면 원문 약 12,000자(설정 `한 번에 기록할 원문 분량`)·최대 20개 메시지씩 작은 구간으로 나눠 순서대로 처리해요. 작은 자투리 구간을 줄이도록 남은 원문 분량을 고르게 배분해요(예: 짧은 메시지 30개는 15+15). 현재 기억 기준으로 예상 요청 횟수가 늘어나는 분할은 피하며, 매 구간을 저장한 뒤에는 늘어난 기존 기억까지 포함해 **실제로 보낼 프롬프트 전체 길이**를 다시 계산하고, 설정의 입력 한도를 넘지 않게 다음 구간을 줄여요. 재요청도 보내기 전에 길이를 확인해요.

메시지 하나는 중간에서 자르지 않아요. 메시지 하나와 수집 지침·기존 기억만으로 입력 한도를 넘으면 필요한 글자 수를 알리고 멈춰요. 입력 한도를 늘려 다시 시도할 수 있어요.

중간 구간이 실패하면 그 전까지만 저장하고, 실패한 구간부터는 원문을 그대로 남겨요. 다시 누르면 실패한 지점부터 이어서 처리해요.

## 체크포인트 (자동 퀵세이브, 기본 켜짐)

- 마지막 저장 시도 뒤 새 메시지(유저+캐릭터 합산)가 기본 **20개** 쌓이면, 캐릭터 응답이 끝난 뒤 자동으로 퀵세이브해요. 수동 퀵세이브도 간격을 다시 세게 해요. 직접 숨긴 메시지는 세지 않고, 스와이프는 개수를 늘리지 않아요.
- 장면이 끝나기를 기다리지 않아요. 진행 중인 장면도 기록하고 열어 둬요.
- **체크포인트 여유분**은 자동으로 기록하지 않고 남겨 둘 최근 메시지 수예요(기본 2개, 0–20개). 스와이프·수정에 대비해요. 남겨 둔 메시지는 다음 체크포인트에서 순서대로 기록하고, 그 메시지에 담은 루팅도 그때 반영해요. 수동 퀵세이브는 여유분 없이 마지막 메시지까지 기록해요.
- 실패·일부 저장·취소 뒤에는 새 메시지가 다음 간격만큼 쌓였을 때 남은 범위부터 처리해요. 매 답장마다 다시 요청하지 않아요. 급하면 퀵세이브를 누르면 돼요.
- 기록할 대상이 여유분뿐이면 AI를 부르지 않고 그렇게 알려 줘요.
- 실제로 저장된 구간은 오토세이브에도 보관해요.

### 저장 중 안내와 결과

퀵세이브·기록하고 장면 닫기·체크포인트·기록 확인이 진행되는 동안 채팅 화면 위쪽에 게임 메시지 창 같은 안내가 떠요. 상태창 스킨을 따라가고, 채팅을 가리지 않아 계속 읽고 쓸 수 있어요. 누르면 SavePoint 창이 열려요. 창이 열려 있을 때는 창 안에 진행 상황이 보여서 안내를 숨겨요.

| 상황 | 안내 | 표시 |
|---|---|---|
| 진행 중 | `저장 중입니다… 0/30` / `체크포인트 저장 중… 0/18` | 도는 아이콘, 저장 완료 메시지 수 / 이번 대상 메시지 수 |
| 완료 | `체크포인트 완료 · #40–#57 기록 · 최근 2개 여유분` | ✔, 3.5초 (변화 줄이 있으면 6초) |
| 대상 없음 | `체크포인트 · 기록할 메시지 없음 · 최근 2개 여유분` | ◇, 3.5초 |
| 일부 저장 | `체크포인트 일부 저장 · #40–#49 완료 · #50부터 다음에 다시` | ⚠ 경고색, 누를 때까지 |
| 실패 | `체크포인트 실패 · 원문 유지 · 눌러서 자세히 보기` | ⚠ 경고색, 누를 때까지 |

- 실패·일부 저장 배너는 누르거나 ✕로 닫거나, 새 저장이 시작되거나, 방을 옮길 때까지 남아요. 누르면 SavePoint 창이 열리고 실패 상세가 펼쳐져요.
- **저장 결과의 변화 줄**: 저장 작업 하나가 끝나면, 바뀐 종류만 한 줄로 모아 보여 줘요. 예: `NEW 🎒 2 · 👥 1 · ❗ 수락 대기 1 · 완료 1`. 바뀐 게 없으면 평소 완료 배너만 떠요.
  - 🎒 = 바뀐 물건 수(새로 기록·갱신·보관·삭제를 합쳐 물건마다 한 번), 👥 = 관계나 상태가 바뀐 인물 수(새 인물 포함, 사람마다 한 번), ❗ = `자동 수락`(바로 등록된 퀘스트) / `수락 대기`(확인 후 수락) / `완료` / `실패`.
  - 여러 구간으로 나눠 저장해도 작업 전체를 합쳐 한 번만, 같은 항목을 여러 번 바꿔도 하나로 세요. 근거 번호만 늘었거나 같은 내용으로 다시 적은 것, 한 작업 안에서 바꿨다 되돌린 것은 세지 않아요.
  - 결과 배너를 누르면 💠 메인으로 가서 🆕 최근 변화를 펼쳐 보여 줘요(수락 대기 퀘스트가 있으면 그 목록도 함께). ✕는 배너만 닫아요. 저장 중 배너에는 ✕가 없어요.
  - 일부만 저장되면 그 안내가 맨 위에, 실제로 저장된 변화만 아래에 보여요(퀵세이브도 같은 배너).
  - SavePoint 창이 열려 있으면 떠 있는 배너 대신 상태칸 맨 위에 같은 한 줄이 떠요. 누르면 메인 최근 변화로 가고, ✕로 닫거나 6초 뒤 사라져요(실패는 닫을 때까지). 탭을 저절로 옮기지는 않아요.
- **NEW 배지**: 💠 메인의 아이템·현재 파티·진행 중 퀘스트에서 마지막 저장으로 새로 생기거나 바뀐 것에 `NEW`가 붙어요. 다음 저장이 실제로 기록될 때 바뀌고, 저장이 완전히 실패하면 이전 NEW가 그대로 남아요.
- 휴대폰이 잠겨 있거나 다른 앱에 있는 동안 끝난 결과는 화면이 다시 보일 때 배너로 보여 줘요. 키보드가 올라와 화면이 밀려도 배너는 보이는 영역 맨 위에 붙어요.
- 실패의 단계·범위·이유·요청 기록은 그 방의 채팅 파일에 남고, `📋 결과 복사`에도 포함돼요. **실패한 요청**과 **그때 저장하지 못한 범위**는 그때 번호 그대로 두고, **현재 재시도가 필요한 범위**를 따로 보여 줘요. 실패 범위가 모두 저장되면 기록이 지워져요.
- 기록은 저장됐는데 그 뒤의 기록 확인만 실패하면 `저장 후 기록 확인 실패 · 기록은 저장됨`으로 구분해요.
- 저장 중에 다른 채팅방으로 옮기면 그 저장은 취소돼요(다른 방 기억에 섞이지 않게 하는 안전장치예요). 이미 저장된 구간은 남고, 어느 방에서 어디까지 저장됐는지 알려 줘요. 퀵세이브는 그 방에 돌아오면 `퀵세이브로 이어서`로, 체크포인트는 다음 간격에 이어서 기록해요.

## ❗ 퀘스트 수락과 추적

설정 `퀘스트 수락`으로 새로 발견한 퀘스트를 어떻게 다룰지 정해요. 새로 설치하면 **확인 후 수락**, 이미 쓰던 설정은 **자동 수락**이에요.

| 방식 | 새로 발견한 퀘스트 |
|---|---|
| 자동 수락 | 바로 진행 중 목록에 넣어요 (예전과 같음) |
| 확인 후 수락 | 💠 메인의 `❗ 발견한 퀘스트`에 모아요. 카드마다 요약, 종류·기한, **근거 원문**(약속·빚은 확인된 인용, 그 밖에는 근거 메시지에서 가장 관련된 문장)과 `수락 / 거절`이 있어요 |

- 저장마다 창을 띄우지 않아요. 저장 결과 배너의 변화 줄에 `❗ 수락 대기 2 · 완료 1 · 실패 1`처럼 함께 보이고(자동 수락 방식이면 `자동 수락`), 누르면 메인의 후보 목록과 최근 변화가 펼쳐져요. 창이 열려 있으면 메인 탭의 붉은 숫자로 알려요.
- **수락**은 퀘스트 목록에 올려 추적한다는 뜻이에요. 이야기 속에서 약속에 동의했다는 뜻이 아니에요.
- **거절**은 퀘스트로 관리하지 않는다는 뜻이에요. 퀘스트 목록과 주입에서만 빠지고, 원문과 기존 저널은 유지돼요. 퀘스트 탭 아래 `추적하지 않는 퀘스트`에서 `다시 추적`할 수 있어요. 이미 추적 중인 퀘스트도 `추적 안 함`으로 뺄 수 있어요.
- 내 선택(대기 / 수락 / 거절)과 이야기 속 상태(진행 중 / 완료 / 실패)는 따로예요. 기다리는 동안 이야기에서 약속이 지켜지면 후보 카드도 `이미 완료`가 되고, 수락하면 완료 목록에 들어가요.
- 기다리는 후보는 자동 수락과 똑같이 주입돼요. 거절해야 빠져요.
- 거절한 것과 같은 일을 다른 말로 다시 적으면 자동으로 추적하지 않음에 넣고 `거절한 퀘스트와 비슷해서 자동으로 넘겼어요`라고 보여요. 같은 종류에 대부분의 단어가 겹치고, **관련 인물·지킬 사람·받는 사람·조건 인용·기한까지 모두 같을 때만**이에요. 하나라도 다르면 새 후보로 보여 줘요. 약속·빚의 조건이나 기한이 **실제로 바뀌면** 다시 후보로 올라와 배너에도 나와요. 같은 말을 다시 인용하거나 같은 문장에서 인용 범위만 달라진 것, 같은 날짜를 나중에 다시 말한 것은 바뀐 것이 아니에요. 예전 원문에 없던 조건이 붙으면("…열 닢을 준다면") 바뀐 거예요. 기한은 적힌 달력 날짜가 있으면 그 날짜로, 없으면 이야기 속 날짜로, 그것도 정할 수 없으면 원문 표현으로 비교해요. 거절 목록을 매번 요약 AI에게 보내지는 않고, 지금 이야기에 나오는 인물·장소에 관한 진행 중인 것만 짧게 알려 줘요.
- 저장하지 않은 사이에는 퀘스트를 판단하지 않아요. 다음 저장 때 그동안의 대화를 한꺼번에 읽어 갱신해요(그 사이 약속하고 지킨 일은 처음부터 완료로 들어와요).

### 약속·빚의 방향

약속·빚 카드에는 원문에서 확인될 때만 `Ari → 나`처럼 **지킬 사람 → 받는 사람**이 붙어요(사용자 페르소나는 `나`). 서로에게 한 약속이라고 원문에 나올 때만 `A · B 서로`이고, 여러 사람이 각자 지킬 맹세는 `A · B`예요. 확인되지 않으면 표시하지 않고, 편집 창에서 직접 고를 수 있어요. 완료·실패 문구는 종류와 상관없이 `완료` / `실패`이고, 방향 표시로 누구의 약속인지 구분해요. 기한이 지난 것만으로는 실패가 되지 않아요.

## 📦 보관함

인벤토리 아래 `📦 보관함`은 지금 이야기에 쓰지 않는 물건을 모아 두는 곳이에요.

- **📦 버튼**으로 넣고 `꺼내기`로 빼요. 보관한 물건의 **상태 기록은 주입에서 제외해요.** 그 물건이 나온 과거 사건(저널·포인트)은 그대로 유지돼요. 기록하는 AI는 같은 물건을 알아보도록 이름과 마지막 상태만 봐요.
- 넣고 빼는 건 주입 여부만 바꿔요. **이야기 속 소지자·위치는 바뀌지 않아요.** 꺼낸 물건에는 `마지막 기록: SCENE …`이 보이니, 그사이 상황이 달라졌다면 ✎로 고쳐 주세요.
- 이야기에서 **다 쓰거나 부서지거나 버린 물건**은 지우지 않고 마지막 상태(`사라짐`)로 보관함에 들어가요. 꺼내도 그 상태 그대로라 다시 쓸 수 있는 물건으로 돌아오지 않아요. 이야기에서 되찾거나 고쳤다고 기록될 때만(단순 언급은 제외) 다시 쓸 수 있는 물건이 되고, 자동으로 들어간 것이면 인벤토리로 돌아와요.
- 직접 넣은 물건이 이야기에서 **다시 쓰이거나 지니게 되면**(단순 언급 제외) 설정의 **보관함 방식**을 따라요.
  - **알림 받고 결정:** 보관함에 두고, 저장이 끝난 뒤 한 번 알려요. 카드와 상태창에 `📦 복귀 확인`이 남고 `꺼내기`·`그대로 두기`로 정해요. 기본값이에요(v0.6.55에서 `직접 관리`는 빠졌고, 쓰던 설정은 이걸로 바뀌어요).
  - **자동 관리:** 인벤토리로 꺼내요.
  - **🔒 직접 보관 유지:** 그 물건만 방식과 상관없이 보관함에 두고 알림도 띄우지 않아요.
  - 방식을 바꿔도 이미 보관함에 있는 물건을 한꺼번에 꺼내지 않고, 그 뒤에 기록된 복귀부터 적용해요.
- 세이브(QUICK·AUTO·FILE), 새 방 이어하기, 리와인드에서 함께 보존돼요.
- 기록 기준: 나중에도 추적할 이유가 있는 물건(소유·빌림·반납, 소모·파손 가능, 단서·선물·도구, 약속 관련)만 인벤토리에 넣어요. 그 장면에서만 쓰는 소품은 저널에만 남아요. 장면이 끝났다는 것만으로 물건이 없어졌다고 보지 않아요.

### 자동 보관 (이야기가 넣은 것)

| 표시 | 언제 | 다시 돌아올 때 |
|---|---|---|
| `자동 보관 · 사라짐` | 다 쓰거나, 깨지거나, 잃어버림 | 되찾거나, 고치거나, 돌려받았을 때 |
| `자동 보관 · 정리됨` | 그 장면에서 쓰고 끝난 소품 (끝난 식사, 식기, 아무도 챙기지 않는 남은 음료) | 새로 챙기거나 쓸 이유가 생겼을 때 (병에 담아 챙김, 누군가에게 주기로 함, 단서가 됨) |

- 정리됨은 사라짐이 아니에요. 마지막 상태(예: "식탁에 음료가 반 남아 있음")가 그대로 남고, 주입에서만 빠져요.
- 다시 언급되거나 조금 쓰인 정도로는 어느 쪽도 돌아오지 않아요. 기록하는 AI가 같은 물건을 새로 추가하는 형태로 보내도 기록만 갱신하고, "되찾음·다시 챙김"이라고 표시했을 때만 돌아와요. 사용자는 언제든 `꺼내기`로 꺼낼 수 있어요.
- ⚓ 고정한 물건과 직접 추가한 물건은 자동으로 정리되지 않아요.
- 인벤토리 기준: 남아 있다거나 먹어서 없어질 수 있다는 것만으로는 등록하지 않아요. 나중에 쓰거나, 전달하거나, 돌려주거나, 챙겨 둘 이유가 있을 때만 추적해요(여행 식량·내일 줄 도시락·단서인 음료는 추적, 식탁에 반 남은 평범한 음료는 저널). 이 기준은 고정 형식에 있어서 기록 지침을 고쳐도 적용돼요.
- 주입 머리말에 "물건 상태는 연속성을 위한 배경 정보이고, 남아 있다는 이유만으로 계속 꺼내 쓰거나 먹게 하지 않는다"는 안내가 들어가요.

## 👥 파티 대기 멤버

파티 탭의 인물 카드마다 `활성 / 대기 / 주입 제외`를 고를 수 있어요. 대기·제외 인물은 아래 `🪑` 묶음으로 모여요.

- **활성:** 관계·상태 기록이 일반 주입 후보예요.
- **대기:** 평소엔 넣지 않아요. 진행 중이거나 최근 장면에 다시 등장하면 전부 넣고, 최근 대화에 이름만 나오면 가장 최근 기록 한 줄만 넣어요. 잠깐 들어갔다고 활성으로 바뀌지는 않아요.
- **주입 제외:** 관련돼도 그 인물의 관계·상태 기록은 넣지 않아요. ⚓ 고정한 기록은 들어가요.
- 세 경우 모두 대화에서 생긴 변화는 계속 기록해요. 바뀌는 건 본편 주입뿐이고, 그 인물이 나온 저널·퀘스트·캐릭터 시트는 그대로예요.

## 하이드와 원문 변경

- **하이드 방식**(설정 `하이드·보관`)은 세 가지예요.
  - **자동**(기본): 세이브할 때마다 기록된 메시지를 숨겨요. 아래 설명이 자동 기준이에요.
  - **수동**: 기록은 평소처럼 하고, 원문은 위쪽 상태 칸 버튼 줄의 **👻 하이드 N**을 누를 때만 숨겨요. N은 이번에 새로 숨길 개수예요(0이어도 버튼은 늘 보이고, 누르면 숨길 게 없다고 알려 줘요). 원문을 오래 남겨 본편 AI가 말투·세부를 직접 읽게 하고, 원할 때 한 번에 정리할 때 써요.
    - 누르면 확인을 받고, 파일 저장까지 끝난 기록 중 **하이드하지 않을 최근 메시지** 바깥만 숨겨요. 미저장 메시지는 숨기지 않고, AI도 부르지 않아요.
    - 숨긴 범위는 방마다 따로 기억해요. 다음 세이브나 방을 다시 열 때 저절로 늘어나지 않아요. 누른 뒤 새로 기록한 메시지는 다음에 누를 때까지 보여요.
    - 저장이 진행 중이거나 쓰는 중이면 버튼이 흐려지고, 끝나면 누를 수 있어요. 버튼 저장이 실패하면 숨김을 모두 되돌려요.
    - 리와인드나 원문 변경으로 미저장이 된 메시지는 다시 보이고(기록 전체가 되감겨도 마찬가지), 다시 기록돼도 다음에 누를 때까지 보여요.
    - 직접 펼쳐 본 메시지는 다음 세이브에도 그대로 보이고, 다음에 👻를 누를 때 다시 숨겨요. 실리태번에서 직접 숨겼다가 다시 펼친 메시지도 마찬가지예요. 수동에서는 👻 버튼만 새로 숨겨요.
    - `하이드하지 않을 최근 메시지`는 새로 숨길 때만 지켜요. 늘려도 이미 숨긴 메시지는 다시 보이지 않아요(v0.6.74).
    - 확인 창이 열린 사이 체크포인트가 끝나거나 새 메시지가 오면 숨기지 않고 다시 누르라고 알려요(물어본 개수만 숨겨요).
    - 자동에서 수동으로 바꾸면 그때 실제로 숨겨져 있는 범위를 방마다 한 번 정해 두고, 더 숨기지 않아요. 수동에서 자동으로 바꾸면 바로 자동 규칙대로 맞춰요.
    - 원문과 그 구간의 저널이 함께 들어가므로 그만큼 토큰을 더 써요(주입문은 자동과 같아요).
  - **끔 · 기존 하이드 유지**: 앞으로 새로 숨기지 않아요. 이미 숨긴 메시지는 그대로 둬요.
- **한 번 숨긴 원문은 풀지 않아요**(v0.6.74). 하이드 끔, SavePoint 끄기, `하이드하지 않을 최근 메시지` 변경, 메시지 삭제로는 다시 보이지 않아요. 다시 보이는 건 리와인드·불러오기·리셋·원문 변경으로 **더 이상 기억에 들어 있지 않은 구간**의 SavePoint가 숨긴 메시지뿐이에요(그래야 AI가 그 내용을 놓치지 않아요). 그 구간이 다시 기록되면 그때의 하이드 설정을 따라요. 직접 숨기거나 펼친 메시지, 🔶 하이드 제외는 그대로예요. 다시 보이게 하고 싶은 원문은 실리태번 눈 버튼이나 🔶로 펼쳐요.
- **🔶 하이드 제외**(v0.6.74까지 🔖 원문 유지): 특정 메시지(첫 인사말, 중요한 대화, 문체 참고용 답장 등)를 계속 원문으로 남기고 싶을 때 메시지의 `…` 메뉴에서 🔶를 눌러요(꺼져 있으면 회색, 켜지면 제 색).
  - **SavePoint의 하이드(자동·👻)에서만 빼요.** 실리태번 `/hide`나 눈 버튼으로 직접 숨기는 건 막지 않아요.
  - 자동·수동 하이드 모두에서 그 메시지는 숨기지 않아요. 저널·파티·퀘스트 기록은 평소처럼 해요.
  - 켜면 SavePoint가 숨긴 메시지는 바로 보여요. 실리태번에서 직접 숨긴 메시지는 펼치지 않아요.
  - 끄면 자동 모드는 바로 하이드 규칙대로, 수동 모드는 다음 👻 하이드 때 숨겨요. 👻 개수에는 하이드 제외 메시지가 빠져 있어요.
  - 표시는 그 메시지에 붙어요(그 방에만, 스와이프·수정해도 유지, 채팅을 분기하면 함께 가요). 메시지 이름 옆에 작은 🔶가 붙고, 상태칸을 펼치면 `🔶 하이드 제외 N개`가 보여요.
  - 표시와 숨김 상태는 채팅 파일에 함께 저장되고, 저장이 실패하면 둘 다 되돌아가요.
  - ⚓(요약한 기억을 우선 주입)와는 달라요. 하이드 제외는 확장이 숨기지 않게 지키는 것이라, 실리태번 컨텍스트 한도를 넘어서까지 전달을 보장하지는 않아요.
- 기록된 메시지만 숨겨요. **하이드하지 않을 최근 메시지**(기본 10개)는 전체 대화에서 숨기지 않을 최근 N개예요. **미저장 메시지는 이 설정과 관계없이 항상 보여요.** 예: 최근 4개·여유분 2개라면 보통 기록된 2개와 미저장 2개가 보여요.
- 저장할 때마다 **#0부터 기록 완료 위치까지** 다시 확인해서, 하이드를 놓친 앞쪽 메시지도 함께 숨겨요. 직접 하이드를 풀어 읽은 메시지는 다음 세이브 때 다시 숨겨요.
- 기억과 하이드 표시는 **같은 채팅 파일에 한 번에** 저장돼요. 저장 요청이 오류를 내면 이번 변경(기억, 기록 위치, 하이드)을 모두 되돌리고 알려 줘요.
  - 실리태번은 서버 저장 실패를 대부분 자체 알림("Chat could not be saved")으로만 처리하고 확장에는 알려 주지 않아요. 그래서 퀵세이브·체크포인트·불러오기·리셋·리와인드는 저장한 뒤 서버의 채팅 파일을 다시 읽어 확인해요. 파일이 그대로면 이번 변경을 되돌리고, 읽지 못했거나 다른 변경이 섞여 있으면 `저장 여부를 확인하지 못했어요`라고 알리고 되돌리지 않아요. 확인될 때까지 SavePoint는 새로 저장하지 않고(체크포인트·QUICK 백업 포함), 잠시 뒤 다시 읽어 확인되면 평소대로 돌아가요. 하이드·🔖·편집 같은 작은 저장은 다시 읽지 않아요.

### 방이 다 열렸는지·다른 기기와 어긋났는지 (v0.6.58)

실리태번은 채팅 파일을 화면의 내용으로 통째로 다시 써요. 그래서 SavePoint는 쓰기 전에 서버의 채팅 파일을 읽어 봐요.

- 방을 열면 서버의 채팅 파일을 읽어 화면과 맞춰 본 뒤에야 그 방에서 하이드·이어하기·저장을 해요. 열리는 중이거나(메시지가 아직 안 온 상태) 실리태번이 불러오기에 실패한 방에서는 아무것도 바꾸지 않아요.
- 저장할 때마다 서버의 파일에 화면에 없는 내용(더 많은 메시지, 다르게 고친 메시지·스와이프·첨부, 다른 확장의 정보)이 있는지 봐요. 있으면 쓰지 않고 `방을 다시 열거나 새로고침해 주세요`라고 알려요. 폰과 PC에서 같은 방을 열어 두었을 때 오래된 화면이 새 내용을 덮어쓰지 않게 하려는 거예요.
- (v0.6.59) 다른 기기에서 지운 메시지가 이 화면에 남아 있거나, 다른 기기가 이 방의 SavePoint 기억을 저장했으면 그것도 덮어쓰지 않고 알려요. 실리태번이 방을 열면서 바꿔 보여 주는 것(예전 형식의 첨부, 비어 있는 작가 노트 값)은 다른 내용으로 치지 않아요.
- (v0.6.59) 한 방의 저장은 한 줄로 차례대로 해요. 🔖 같은 표시도 서버 파일 확인이 끝난 뒤에 붙어요(아주 잠깐 늦게 보일 수 있어요).
- (v0.6.60) 차례를 기다리는 사이 화면이 바뀌면(이어하기를 승인한 뒤 첫 메시지를 고침, 퀵세이브 중 기록할 메시지를 고침) 그 변경은 하지 않고 `다시 해 주세요`라고 알려요. 방을 열 때 서버의 SavePoint 기억이 화면에 불러온 것과 다르면(그 사이 다른 기기가 저장함) 덮어쓰지 않아요.
- (v0.6.61) 미리 정해 두고 차례를 기다리는 모든 변경(리와인드, 불러오기, 번역, 주입 포인트 다시 고르기, 퀵세이브·체크포인트)은 차례가 왔을 때 아직 유효한지 같은 규칙으로 다시 봐요. 아니면 하지 않고 `다시 해 주세요`라고 알려요. QUICK 백업도 서버 확인을 통과했을 때만 바꿔요.
- 한계: 서버를 읽은 바로 그 순간 다른 기기가 저장하는 아주 짧은 틈은 확장에서 막을 수 없어요(실리태번 서버가 해야 하는 일이에요).
- (v0.6.76) 실리태번이 저장하는 중이면 끝날 때까지 기다린 **뒤에** 서버 파일을 확인해요(기다리는 사이 다른 기기가 저장한 내용을 덮지 않게). SavePoint 저장이 가는 사이 화면이 바뀌어서 한 번 더 보낼 때도 먼저 서버를 읽어요. 그사이 이 화면에 없는 내용이 생겼으면 보내지 않고 방을 멈추고, 읽지 못하면 `저장 여부를 확인하지 못했어요`로 멈춰요. 첫 저장이 이미 들어간 뒤에 난 오류로는 화면의 변경을 되돌리지 않고, 서버 파일을 읽어 판단해요.
- **알려진 문제(v0.6.76 기준, 열린 문제):** SavePoint 저장이 이미 출발한 뒤 실리태번이 더 새 대화를 저장하고, SavePoint 요청이 늦게 도착하는 순간 다른 방으로 옮기면, 원래 방 파일이 SavePoint가 보낸 조금 전 내용으로 남을 수 있어요(그 사이 생긴 최신 메시지가 빠짐). 같은 방에 있으면 바로 다시 보내서 맞춰요. 실리태번 저장과 순서를 맞추는 방법은 보류 중이에요. 실리태번 백업(`data/<사용자>/backups/`)에는 그 메시지가 남아 있어요.
- 긴 방에서는 저장할 때마다 채팅 파일을 읽어서 조금 느려질 수 있어요.
- 기록된 메시지가 수정·삭제되거나 스와이프로 바뀌면, 그 메시지가 들어 있던 구간부터 뒤의 기록을 되감고 숨김도 풀어요. 다음 체크포인트나 퀵세이브 때 다시 기록돼요.
- 기록 보관 범위보다 앞쪽의 원문이 바뀌면(세이브를 불러온 방 등) 창 위쪽에 안내가 떠요. `지금 원문 기준으로 인정` 또는 `리셋`을 고를 수 있어요.
- **⏪ 리와인드**는 마지막 저장(체크포인트, 퀵세이브, 기록하고 장면 닫기)·리셋·세이브 불러오기 전으로 한 단계 돌아가요. ★·⚓·●·✎·🗑 같은 편집은 리와인드 지점을 바꾸지 않아요(저장 뒤에 한 편집은 저장을 되돌릴 때 함께 되돌아가고, 확인창이 개수를 알려 줘요). 🗑 삭제는 확인창을 거쳐요.

## 포인트 선택과 고정

저널의 포인트 앞 기호는 `● 선택됨 / ○ 선택 안 함 / ⚓ 우선 주입 고정`이에요. **선택한 내용은 기억 주입에 우선 반영해요.** 기호를 눌러 선택하거나 제외할 수 있고, 직접 고른 값은 이후 자동 판단으로 덮어쓰지 않아요.

포인트 옆 `⚓`를 누르면 그 문장을 고정해요. 고정한 포인트는 장면이 오래되거나 한 줄로 줄어도 영어 문장 전체를 우선 주입해요. 앞의 `⚓`를 다시 누르면 고정 전 선택으로 돌아가요. 장면의 ⚓(핵심 한 줄 유지)와는 별개예요.

고정 문장은 같은 장면의 개요나 회상에 그대로 있으면 중복해서 넣지 않아요. 고정도 전체 주입 토큰 상한을 지키며, 들어가지 못한 고정 항목은 경고로 알려 줘요.

## 💎 루팅과 ⏳ 대기열

채팅창 왼쪽, 확장 메뉴(✦) 옆의 `💎`를 눌러요.

- **구절을 드래그한 채 누르면** 그 구절이 담긴 루팅 창이 열려요. `원문 전체` 탭으로 바꾸면 메시지 전체를 담을 수 있어요. 선택이 여러 메시지에 걸치면 AI 답변별로 나눠 각각 담아요. 사용자 메시지 부분은 담지 않아요.
- **그냥 누르면** 가장 최근 AI 답변의 원문 전체가 열려요. `◀ ▶`로 다른 AI 답변을 고를 수 있어요.
- 창에서 구절을 고친 뒤 `⏳ 대기열에 담기`를 눌러요. 메모는 선택이고, 왜 중요한지 설명하는 용도예요. 이야기 속 사실의 근거로 쓰지 않아요. **담는 순간에는 AI를 호출하지 않아요.**
- 휴대폰에서 버튼을 누르는 순간 선택이 풀려도 방금 고른 구절을 써요. 마크다운 기호와 공백 차이는 무시해 비교해요.

**번역 확장과 함께 쓸 때:** 화면에만 번역을 보여 주는 번역 확장(실리태번의 `display_text` 방식)을 쓰면, 번역문에서 고른 구절도 담을 수 있어요. 세이브 때 요약 AI가 원문 메시지 전체를 읽고 그 번역이 가리키는 원문 부분을 찾아 기록해요. 번역문과 원문은 1:1로 맞지 않을 수 있어서 메모를 붙여 두면 더 정확해요.

- 대기열은 방의 채팅 파일에 저장돼서 새로고침해도 남아요. 상태 바의 `⏳ 대기열 N개` 또는 대기열 탭에서 보고 삭제할 수 있어요. 세이브 슬롯을 불러와도 이 방의 대기열은 유지돼요.
- 원문을 수정하거나 스와이프로 바꾸면 `원문이 바뀜`으로 표시하고 자동 반영을 보류해요. 새 원문으로 다시 루팅하고 이전 항목을 삭제할 수 있어요.
- 새 메시지의 루팅은 다음 퀵세이브·체크포인트 수집 요청에 함께 보내요. 이미 기록된 메시지의 루팅은 **해당 장면의 저널만 보충**하고, 현재 상태나 장면 개요는 바꾸지 않아요. 새 대화가 없어도 퀵세이브로 처리할 수 있어요.
- 루팅도 다른 포인트처럼 핵심을 영어 한 문장으로 요약해요(핵심이 둘이면 두 문장까지). 메모가 가리킨 특징과 중요한 조건·부정·불확실함은 남기고, 부수적인 동작과 묘사는 줄여요. 기존에 저장한 포인트는 다시 쓰지 않아요.
- 반영한 포인트는 `●`로 저장돼요. 압축 후에도 문장 전체를 우선 주입하려면 `⚓`를 눌러요. 포인트를 펼치면 `출처: 루팅`이 보이고, 이 연결은 세이브·내보내기·방 이동 후에도 남아요.
- **기록 확인을 켜 두면** 담은 발췌의 핵심과 메모가 가리킨 부분이 포인트에 맞게 담겼는지도 AI가 검토해요(경고만 남겨요). 부수적인 묘사를 줄인 것은 누락으로 보지 않고, 메모 자체는 이야기 속 사실의 근거로 쓰지 않아요.
- 기억과 대기열은 같은 저장 작업으로 기록해요. 저장 성공 뒤에만 항목을 제거해요. 반영에 실패하면 대기열 카드와 알림, `📋 결과 복사`에 **이유**가 남아요: AI 응답에서 반영 연결을 찾지 못함 / 연결한 포인트가 그 메시지를 근거로 적지 않음 / 요청 오류 등. 실패 횟수는 세이브 한 번에 한 번만 세요.
  - 이미 기록된 메시지: 다음 세이브 때 저널 보충으로 다시 시도해요. 카드의 `↻ 다시 반영`으로 그 항목만 바로 보충할 수 있어요(현재 물건·약속 상태는 바꾸지 않아요).
  - 아직 기록 안 된 메시지: 다음 퀵세이브·체크포인트 때 함께 보내요. 카드에서 `⏺ 퀵세이브로 반영`을 누를 수 있어요.
  - 채팅 파일 저장 자체가 실패해도 이유는 화면에 남고, 다음에 저장이 될 때 함께 저장돼요.
  - 원문이 바뀐 항목·다른 방 항목·장면이 없는 항목은 자동으로 다시 시도하지 않고, 다시 담거나 삭제하라고 안내해요. 리와인드하면 되돌린 기억에서 빠진 루팅만 대기열로 돌아와요.

## 기록 규칙

- AI는 먼저 체크리스트(약속, 물건, 부상·상태, 관계를 바꾼 행동, 비밀, 결정, 새 이름, 기억할 순간)를 훑고, 그다음 장면 → 대상 → 상태 변경 순서로 써요.
- **상태를 바꾼 일**은 시작과 결과를 함께 기록해요. 예: 주웠다 → 고쳐서 돌려줬다.
- **나중에 다시 꺼낼 만한 순간**은 한 줄로 남기고, 구체적인 내용은 상세 노트에 적어요.
- 캐릭터 카드와 페르소나에 이미 있는 정보는 기록하지 않아요.
- 구간이 장면 도중에 끝나면 마지막으로 확인된 이야기 속 상황을 적고, 미완료·미결정 상태는 그대로 둬요. "마지막 메시지에서 아직 진행 중" 같은 기록 과정 설명은 쓰지 않아요. 앞 구간 기록은 고치지 않아요.
- **기록에서 뺄 부분**: 설정에 태그 이름(`thoughts`)이나 `시작 ~ 끝` 표시를 한 줄에 하나씩 적으면, 그 부분은 기록·기록 확인·루팅 보충 때 요약 AI에게 보내지 않아요. 채팅 원문은 그대로예요. 끝 표시가 없으면 자르지 않고 둬요.
- 기록은 모두 영어로 해요. 이름과 별칭만 원문 표기를 그대로 둬요(예: `나침반`). 이 별칭 덕분에 한국어 대화에서도 관련 장면을 찾을 수 있어요.
- 코드가 응답을 검사해요. 근거 번호가 범위를 벗어나거나, 없는 항목을 참조하거나, 영어가 아니면 이유를 담아 한 번 다시 요청해요. 그래도 통과하지 못하면 **저장하지 않아요.** 형식을 맞추려고 코드가 자리를 바꿔 넣지는 않아요.
- 인물·물건·장소는 ID로만 가리켜요. 같은 별칭(예: 두 개의 `나침반`)을 가진 서로 다른 대상도 따로 기록해요. AI가 ID 자리에 이름(`"Theo"`)을 쓰면, 그 이름이 등록된 대상 **딱 하나**와 맞을 때만 그 ID로 연결하고, 둘 이상과 맞으면(예: 고양이와 교차로가 둘 다 `Pip`) 다시 요청해요.
- 장면 경계는 근거가 분명할 때만 코드가 보정해요(앞 장면에 `continue`로 이어진 장면 합치기, 숨긴 메시지를 가리킨 시작 번호 옮기기 등). 보정한 내용은 상태 바의 `자동 보정`과 `결과 복사`에 남아요. 서로 다른 장면을 억지로 합치지는 않아요.
- 제목·개요가 빠졌어도 포인트 형식이 정상이면 임시 제목·포인트 기반 개요로 보완해요. 임시 제목은 이후 정상 제목으로 바뀔 수 있고, 직접 고친 제목은 보호해요.
- 내기·벌칙·규칙은 원문이 말한 조건 그대로(이긴 쪽, 진 쪽, 무승부 각각) 기록해요. 같은 구간 안에서 맺고 지킨 약속은 처음부터 `완료`로 기록해요.
- **빚·약속에는 조건 원문이 붙어요.** AI가 낸 인용이 그 메시지에 실제로 있는지 코드가 확인하고, 앞뒤 두 문장씩을 원문에서 직접 가져와 같이 저장해요. 조건 원문은 퀘스트 탭의 `근거 원문`에서 볼 수 있고, **기억 주입에는 넣지 않아요.**

## 이야기 시간

날짜는 장면 안의 기록 구간마다 저장해요. 인포박스가 없어도 본문에 나온 날짜·시간 진행을 기존 수집 요청에서 함께 읽어요. 시간만을 위한 추가 AI 호출은 없어요.

- 날짜·시간대(새벽·아침·낮·오후·저녁·밤)·시각과 원문 근거를 보관해요. 장면 옆에는 시간 범위, 구간 상세에는 시작·끝 시간과 확인 수준이 보여요.
- **인포박스**: 답장마다 `📅 Date: 2026-10-25 (Sun) | 🕒 Time: 14:38` 같은 상태 줄이 있으면 그 날짜·시각을 원문에 명시된 시간으로 읽어요. 날짜 뒤의 요일(`(Sun)`, `(일)`, `(일요일)`)은 날짜 계산에서만 떼고, 근거 인용은 원문 그대로 보관해요. `2026-02-30`처럼 없는 날짜는 받지 않아요. 앞 구간이 미확인이어도 인포박스를 정확히 인용한 구간은 다시 확인돼서 미확인이 뒤로 번지지 않아요. 이때도 마지막으로 확인된 날짜보다 과거로는 돌아가지 않고, 시각만 인용됐으면 날짜를 만들지 않아요.
- 인포박스는 확장이 직접 읽는 게 아니라 수집 AI가 옮긴 날짜를 원문과 대조해 확인하는 방식이에요. AI가 날짜를 빠뜨리면 그 구간은 미확인이 될 수 있어요.
- 예전 버전 기록은 처음 열 때 한 번, 원문 인용이 남아 있는 날짜만 새 규칙으로 다시 확인해요. 이미 확인된 시간이나 직접 지정한 시간은 바꾸지 않아요. AI가 날짜를 보내지 않았거나 인용이 없는 구간은 자동으로 복구할 수 없어요.
- 확인된 날짜가 없으면 `기록 기준 N일째`를 써요. 이야기 자체의 시작일이라는 뜻은 아니에요.
- 시간이 흐르려면 원문 근거가 필요해요. `다음 날`·`그다음 날`·`이튿날`은 +1일, `사흘 뒤` +3일, `일주일`·`a week` +7일, `보름` +15일처럼 **인용에서 읽은 일 수와 AI가 낸 일 수가 같을 때만** 확정해요.
- `며칠 뒤`·`일주일쯤`·`거의 사흘`·`over 12 days`처럼 모호하거나 대략적인 표현, 과거·범위·분수는 확정하지 않고 `미확인`으로 둬요. 기억 내용은 그대로 저장돼요.
- `몇 주 뒤` 같은 점프는 새 기준으로 남겨요. 그 뒤의 일 수는 새 기준 안에서만 이어지고, 전체 며칠째인지 숫자를 지어내지 않아요.
- 실제로 과거를 연기하는 `회상` 구간은 기록하되, 현재 시간은 움직이지 않아요. 미래 약속·단순 과거 언급·가정도 현재 시간을 진행시키지 않아요.
- 시간 인용은 원문에 그대로 있어야 하고, 글자·숫자 두 자 이상이어야 해요(`밤`보다 `밤이 깊었다`). 코드는 문자열이 있는지만 확인하고, 문맥의 의미 판단은 수집 AI가 맡아요.
- 달력 덧셈은 유효한 `YYYY-MM-DD` 날짜에만 해요. 작품 고유 달력은 원래 표현과 상대 일 수를 보존해요(예: `왕국력 312년 봄 3일 +1일`). 실제 컴퓨터 날짜는 이야기 시간으로 쓰지 않아요.
- 장면 시간 줄의 `✎`를 누르면 미확인인 구간의 편집 창이 열려요. 미확인 구간이 여러 곳이면 고를 목록이 떠요. 구간을 펼쳐 `시작 ✎`·`끝 ✎`로 직접 고를 수도 있어요. 직접 지정은 AI가 덮지 않고, 고친 지점부터 뒤쪽만 다시 계산해요. 앞 장면을 지워도 남은 장면의 날짜는 유지돼요.
- 기억 주입 맨 위에 `Last recorded story time:`을 넣고, 마지막 기록 뒤의 대화가 더 최신일 수 있다고 알려 줘요.

## 타임라인

📅 타임라인 탭은 구간별 날짜·시간을 **최근 기록이 위에 오도록** 모아 보여 줘요. 화면용이라 AI에게 따로 주입하지 않아요.

- 실제 날짜, `기록 기준`(날짜 없음), `“몇 주 뒤” 이후`처럼 **서로 다른 시간 기준은 합치지 않고** 따로 묶어요. 같은 날의 구간은 날짜 머리 하나 아래에 시각만 보여요.
- 시간 미확인 구간과 회상도 최근에 기록된 것부터 보여요. 미확인은 빨간색, 회상은 `↩ 회상`으로 들여 써서 현재 흐름과 구분해요. 이야기 날짜로 재정렬하거나 저장된 기록 순서를 바꾸지는 않아요.
- `저널에서 보기`는 그 장면을 펼쳐 해당 구간으로 이동하고, `✎ 시간`은 그 구간의 시간 편집 창을 바로 열어요(미확인이면 미확인인 쪽부터).
- 진행 중인 약속·빚의 기한은 맨 위에, 그리고 약속한 구간 아래에도 보여요. `퀘스트 보기`로 그 퀘스트로 이동해요.

### 시작 날짜 연결

날짜가 없는 기준(`기록 기준 1일째`, `“몇 주 뒤” 이후` 등)의 머리에서 `📅 날짜 연결`을 누르면 그 기준의 첫 날에 실제 날짜를 연결할 수 있어요. 예: `기록 기준 1일째 = 2026-10-25`.

- 그 기준의 날들이 `2026-10-25`, `2026-10-26`처럼 날짜로 보이고, 약속 기한과 마지막 기록 시간 주입에도 반영돼요. 저장된 일 수와 메시지 번호는 그대로예요.
- 고른 기준에만 적용돼요. 뒤에 `몇 주 뒤`처럼 새로 시작된 기준은 자동으로 이어 붙이지 않아요. 따로 연결해야 해요.
- 원문에 적힌 날짜와 직접 지정한 시간은 바꾸지 않아요. 연결한 날짜가 원문 날짜와 어긋나면(예: 연결로 계산된 날보다 원문 날짜가 이르면) 연표 위쪽에 알려 주기만 해요.
- 비워서 저장하면 연결이 풀려요(편집이라 리와인드 대상은 아니에요). 이미 날짜가 있는 기준과 작품 고유 달력은 연결 대상이 아니에요.

## 약속·빚의 기한

- 퀘스트 카드에는 확인되는 `📅 약속한 때`(목표·수수께끼는 `생긴 때`)와 AI가 기록한 `완료한 때`·`실패한 때`도 작게 보여요. 여러 날에 걸친 근거는 한 날짜를 고르지 않고 `약속 기록 구간`처럼 범위로 표시해요. 같은 날이어도 시간대가 서로 다르면 날짜만 보여요.
- 새 기록은 생성과 상태 변경의 근거를 따로 보존해요. 예전 기록은 생성 시점을 단정할 수 없어서 `관련 기록 구간`으로만 보여요. 시간 미확인이나 출처 구간이 없으면 줄을 생략하고, 다른 방 번호를 이번 방 번호로 해석하지 않아요. 버튼이나 편집 창에서 직접 완료·실패로 바꾼 경우에는 이야기 날짜를 만들지 않아요.
- 날짜는 저장 시각이 아닌 구간의 이야기 시간을 따라가며, 타임라인의 날짜 수정·연결에도 함께 바뀌어요. 이 날짜 줄은 화면용이고 **AI 주입문에는 추가하지 않아요.**
- 약속과 빚에 기한이 있으면 퀘스트 카드에 `⏰ 기한 “내일” (2026-10-25) · 1일 남음 (마지막 저장 기준)`처럼 보여요. 기한은 **그 말을 한 구간의 이야기 시간**에서 계산해요. 3일째에 “내일 만나자”라고 했다면 4일째가 기한이에요.
- `내일` 1일, `모레` 2일, `글피` 3일, `오늘 밤` 0일, `사흘 뒤` 3일처럼 정확한 표현만 계산해요. `며칠 안에`·`이번 주말`·`곧`·`내일모레`처럼 모호하거나, 말한 시점이 확실하지 않으면(회상, 여러 날에 걸친 구간, 시간 미확인) 원문 표현만 보존해요.
- **기한이 지난 것과 약속을 어긴 것은 따로 봐요.** 기한이 지나도 퀘스트는 진행 중 그대로 두고 `기한 지남 (마지막 저장 기준, 약속을 어겼다는 뜻은 아니에요)`라고만 표시해요. 주입에도 같은 뜻으로 들어가요.
- `몇 주 뒤`처럼 기준이 끊긴 뒤에는 지금과 비교할 수 없어서 `확인 필요`로 표시해요. 실제 날짜가 있는 기록끼리는 기준이 달라도 날짜로 비교해요. 완료·실패한 약속은 기한 표현만 보여요.
- 편집 창에서 기한을 직접 정할 수 있어요. 실제 날짜가 있으면 `YYYY-MM-DD`(기록 첫날보다 앞선 날짜도 가능), 아니면 지금 기준의 `N일째`로 적어요. 직접 정한 기한은 AI가 다시 읽어도 바뀌지 않아요.
  - 직접 지정 칸만 비우면 원문 계산으로 돌아가요. 기한 표현까지 지우면 기한이 없어져요. 표현을 다른 말로 바꾸면 그 표현만 남기고 예전 계산은 버려요.
- 약속·빚을 직접 추가할 때도 기한을 함께 적을 수 있어요.

## 기록 확인 (경고만)

기록이 저장된 뒤 AI가 근거 원문과 비교해요(설정에서 끌 수 있어요). **켜 두면 체크포인트마다 확인 요청이 따라 나가요.** 분량에 따라 여러 요청으로 나누므로 추가 호출 수가 늘 수 있어요.

- **원문과 다름:** 근거 원문을 다시 읽어 보니 다르게 해석된 경우. 예: 농담으로 한 말을 진짜 빚으로 기록함
- **충돌 · 판단 보류:** 기록과 저널이 서로 다른데 원문으로 어느 쪽이 틀렸는지 결정할 수 없는 경우
- 찾으면 상태 바에 `⚠ 확인 필요 N건`이 떠요. 펼치면 충돌한 두 문장과 원문 발췌가 보이고, `편집` 또는 `무시`를 고를 수 있어요.
- **기록을 자동으로 고치지는 않아요.** 검토가 실패해도 이미 저장한 기억은 유지돼요.
- 각 기록·포인트·개요를 판단하는 데 필요한 **메시지 전체**를 함께 보내요. 근거 전체가 입력 한도를 넘거나 원문이 없으면 **검토 보류**로 표시하고, 일부만 읽고 `문제 없음`으로 표시하지 않아요.
- 예전 방에서 맺은 약속처럼 근거가 이전 방에 있으면 `근거가 이전 방에 있음 · 판단 보류`로 확인 범위를 구분해요.

## 주입

**저장하는 기억과 매번 넣는 기억은 달라요.**

- 장면의 포인트는 모두 저장돼요. 그중 **주입 포인트(●)**만 개요와 함께 들어가요. 나머지(○)는 저널에서 볼 수 있고, 관련 대화가 나오면 상세 기억 회상에 쓰여요.
- 주입 포인트는 기록할 때 AI가 골라요. 기준은 "개요와 상태 목록에 이미 들어간 내용이 아닌, 중요한 결과·미해결 사항·회상 단서"예요. 장면 카드의 `⟳ 주입 고르기`로 다시 수집하지 않고 다시 고를 수 있어요.
- ● 포인트가 개요에 **문장 그대로** 들어 있으면 그 주입에서만 빼요(`개요와 같음 · 주입 생략`). 직접 누른 ●는 빼지 않아요.
- 전체 상한(기본 6,000토큰)을 넘지 않아요. ⚓ 항목이 가장 먼저 자리 잡고, 그래도 넘으면 빠진 개수를 알려 줘요.
- 넣는 순서: 지금 장면과 관련된 상태 → 상세 기억 회상 → 최근 장면 → ★ 장면 → 그 밖의 장면 → 오래된 장면 제목(별도 상한 600토큰)
- **시간 표시는 반복하지 않아요.** 장면 머리에 날짜를 한 번 쓰고, 구간에는 바뀐 것만 써요(`[2026-10-25]: [10:00–11:30] … [12:00–13:30] …`). 날짜가 바뀔 때, 시간 미확인 뒤, 회상, 다른 시간 기준에서는 날짜를 다시 써요. 장면 머리의 날짜 범위는 현재 흐름만으로 계산하고, 회상이 섞이면 `includes flashback`, 전부 회상이면 `flashback`으로 표시해요(짧은 개요에서도 유지). 내용은 줄이지 않고 같은 뜻의 반복만 없애요.
- **남으면 오래된 장면에도 ● 포인트를 넣어요.** 모든 장면을 먼저 넣은 뒤, 남는 상한 안에서 최신 장면부터 포인트를 하나씩 더해요(주입 탭에 `개요+포인트 일부`). ●는 주입 후보라 상한이 모자라면 빠질 수 있고, ○와 상세 노트는 최근 대화와 관련될 때 회상으로 들어와요.
- **넘칠 때는 오래된 장면부터 단계적으로 줄여요:** 개요 → **짧은 개요** → 제목 → 빠짐. 짧은 개요는 첫 구간의 첫 문장과 마지막 구간의 첫 문장이에요(같으면 한 번). 장면을 새로 요약한 것이 아니고, 진행 중인 장면은 `[in progress]` 표시가 그대로 붙어요. 문장을 글자 수로 자르지 않아요. 먼저 모든 장면에 짧은 개요 자리를 잡고, 남는 예산으로 최신 장면부터 개요로 올려요. 최근 장면·⚓·★의 우선순위는 그대로예요.
- 줄어드는 건 주입문뿐이에요. 저장된 기록·포인트는 그대로이고, 자세한 내용은 최근 대화와 관련되면 회상 후보가 돼요. 회상은 검색 결과와 회상 몫 안에서 골라요.
- 🧿 주입 탭에 장면별 단계(자세히·개요+포인트 일부·개요·짧은 개요·제목만·빠짐)와 **필요한 상한 두 가지**(모든 장면 개요까지 / ● 포인트까지)가 보이고, 빠진 장면이 있으면 **주입 상한** 때문인지 **제목 목록 상한** 때문인지 알려 줘요. 줄어든 장면이 있으면 "모든 장면의 개요를 포함하려면 주입 상한 약 N토큰"을 실제 주입 계산을 다시 돌려서 보여 줘요(선택 포인트·상세 노트까지 모두 포함하는 수치는 아니에요).
- 영역별 배분(상태 35% / 저널 50% / 회상 15%)은 기본값이에요. 남는 몫은 다른 영역이 써요.
- **상세 기억 회상**: 최근 대화와 연결된 장면 1~2개에서, 이번 주입에 들어가지 않은 것(○ 포인트, 예산 때문에 빠진 ● 포인트, 상세 노트)을 대화와 잘 맞는 것부터 최대 6개(장면당 4개) 넣어요.
  - 연결 기준: 이름·별칭, 겹치는 단어 세 개 이상, 숫자(점수, 시간 등). 캐릭터 카드·페르소나 이름처럼 매번 나오는 이름만으로는 회상하지 않아요.
  - 별칭이 영어로만 기록된 물건은 한국어 대화에서 찾지 못할 수 있어요.
- **원문 회상**은 설정에서 따로 켤 수 있어요(기본 꺼짐). 원문이 한국어면 한국어가 섞여 들어가요.

## 세이브 슬롯

| 종류 | 언제 바뀌나 | 보관 |
|---|---|---|
| **QUICK** | 직접 누른 퀵세이브·기록하고 장면 닫기가 끝까지 성공했을 때 (새 메시지가 없어도 지금 기억으로) | 방마다 1개. 확인 없이 갱신, 직접 지울 때까지 남음 |
| **AUTO** | 체크포인트·퀵세이브·기억 편집 등 기억이 바뀔 때 | 방마다 최근 3개(최신 / 이전 / 그 전), 보관할 방 수 설정만큼 |
| **FILE** | `＋ 새 세이브 슬롯`으로 만들거나 `저장`으로 직접 덮어쓸 때 | 직접 지울 때까지 |

💾 탭은 **이 방 / (캐릭터)의 다른 방 / 다른 캐릭터**로 나뉘어요. 묶음마다 QUICK → 직접 만든 FILE(만든 순서로 고정) → AUTO 순서예요. 탭 숫자는 **이 방**의 슬롯 수예요.

- **불러오기**: 이 방의 기억을 이 슬롯으로 바꿔요. 슬롯은 덮어쓰지 않아요. 같은 슬롯에서 여러 방으로 갈라져 진행해도 원래 슬롯은 그대로예요.
- **▶ 플레이 중**: 이 방에서 마지막으로 저장하거나 불러온 FILE 슬롯에 붙어요.
- **저장 / 이름**: FILE 슬롯만 있어요. 덮어쓰기는 확인을 한 번 거쳐요.
- **사본 저장**: QUICK·AUTO 카드에 있어요. 그 시점을 이름 붙인 FILE 슬롯으로 따로 저장하고, 원래 카드는 그대로 둬요.
- 카드의 🎬 줄은 **저장 당시** 장면 제목이에요. 방 폴더(🗝️)에는 방 이름과 그 방의 가장 최근 저장본 장면 제목이 붙어요. 다른 캐릭터(👾)는 방이 둘 이상이면 방별 폴더로 나뉘어요.
- QUICK이 실패·일부 저장·취소로 끝나면 이전 QUICK은 그대로 두고, 저장된 일부는 AUTO에 남아요. 서버에 쓰지 못하면 `기록 완료 · QUICK 백업 실패`로 알려요.
- 같은 방이나 분기(실리태번의 Branch 등)에서 불러오면 저장 당시 위치와 하이드까지 그대로 돌아가요. 그 뒤 메시지는 미저장이 돼요.
- 원문이 다른 새 방에서는 기억을 가져오고 이 방의 메시지는 #0부터 미저장으로 시작해요. **진행 중이던 장면은 열린 채로 유지**하고, 새 방의 기록도 같은 장면에 이어 붙어요.
- 근거는 구간별로 출처 방을 보관해요. 이전 방 번호는 `이전 방 #48`처럼 표시하고 현재 방의 #48로 조회하지 않아요.

### 새 방에서 이어하기

세이브에는 저장 당시 **마지막 캐릭터 메시지**(원문, 이전 방 번호, 기억에 기록됐는지)가 함께 담겨요.

1. 이전 방에서 **퀵세이브**를 눌러요.
2. 새 채팅을 열고 💾 탭을 보면 맨 위 `이어하기` 칸에 같은 캐릭터 다른 방의 최근 QUICK이 있어요.
3. (또는 새 채팅을 열면 위쪽에 뜨는 `이어서 할까요?`에서 `▶ 불러오기` → 목록에서 고르기. `✦ 새로 하기`를 고르면 그 방에서는 다시 묻지 않아요. 설정 하이드·보관의 `새 채팅에서 이어하기 물어보기`로 끌 수 있어요. 그 방 자신의 세이브가 하나라도 있으면 묻지 않아요.)
3. `불러오기`를 누르고 확인하면, 첫 인사말이 그 메시지로 바뀌고(인사말이 없으면 새로 넣어요) 기억이 그 지점부터 이어져요. `아니요`를 누르면 한 번 더 물어요: 기억만 불러올지, 아무것도 바꾸지 않을지.

- 그 메시지가 **이미 기록된 것으로 확인될 때만** #0을 기록된 메시지로 연결하고, 새 기록은 #1부터 해요. 같은 일이 두 번 기록되지 않아요.
- 체크포인트 여유분 때문에 아직 기록 전이었거나 그 뒤에 메시지가 더 있었다면 불러올 때 알려 줘요. 그대로 진행하면 #0은 새로 기록해요. 이전 방에서 퀵세이브한 뒤 QUICK으로 불러오면 빠지는 내용이 없어요.
- 마지막 메시지를 직접 붙여 넣어 #0으로 만든 방도, 글이 같고 캐릭터 메시지면 똑같이 연결해요. 고쳐 쓴 글이나 사용자 메시지로 붙여 넣은 경우는 새 메시지로 기록해요.
- 이미 다른 대화가 있는 방은 메시지를 바꾸지 않고 기억만 불러와요. 스와이프·이미지는 가져가지 않고, 바뀐 인사말의 대체 인사말·이미지·번역 정보도 함께 지워요. 이 채팅은 수정된 대화로 표시돼서, 캐릭터 카드를 고쳐도 실리태번이 인사말로 되돌리지 않아요.
- 새 #0과 기억은 채팅 파일에 한 번에 저장돼요. 저장한 뒤 서버의 채팅 파일을 다시 읽어 확인하고, 반영되지 않았으면 첫 메시지·기억·수정된 대화 표시를 모두 되돌려요(실리태번은 서버 저장 오류를 스스로 처리하고 정상 종료해서, 이렇게 확인해야 알 수 있어요). 확인할 수 없을 때는 되돌리지 않고 그렇다고 알려 줘요. 불러오는 도중 채팅방을 옮기면 어느 방도 바꾸지 않아요.
- (v0.6.58) 첫 메시지를 바꾸는 건 방이 비었거나, 메시지 하나가 **캐릭터 카드의 인사말(대체 인사말 포함)과 같을 때만**이에요. 시스템 메시지나 다른 글 하나만 있는 방은 기억만 불러와요. 확인창에 답한 뒤 방의 메시지가 하나라도 바뀌었거나(편집·스와이프 포함), 서버의 채팅 파일에 메시지가 더 있거나 서버를 읽지 못하면 아무것도 바꾸지 않아요. 서버가 빈 응답을 주면(새 방인지 읽기 실패인지 알 수 없어서) 이어하기를 묻지 않아요.
- QUICK을 .json으로 가져오면 FILE 슬롯이 돼요.

## 저장 위치와 백업

세이브 슬롯과 오토세이브는 **실리태번 서버의 사용자 파일 폴더**(`data/<사용자>/user/files/`)에 저장돼요. 실리태번을 PC에서 돌리면 그 PC에 남고, 클라우드에 올라가지는 않아요.

| 파일 | 내용 |
|---|---|
| `savepoint-index.json` | 슬롯 목록 (정식 목록) |
| `savepoint-index.prev.json` | 바로 전 목록 |
| `savepoint-slot-<id>.json` | 직접 만든 슬롯 하나 |
| `savepoint-auto-<방>-0~3.json` | 방마다 오토세이브 (4개 이름을 돌려 쓰며 3개 보관) |
| `savepoint-quick-<방>-0~1.json` | 방마다 QUICK (2개 이름을 번갈아 쓰며 1개 보관, 새 파일과 목록을 쓴 뒤 이전 파일 삭제) |

- 저장 순서는 항상 **새 파일 저장 → 목록 갱신 → 필요 없는 파일 삭제**예요. 중간에 실패해도 목록에 있는 파일이 지워지지 않아요.
- 서버에 쓸 수 없으면 그 슬롯은 설정에만 저장되고 `설정에만 있음`으로 표시돼요. 다음에 실리태번을 열 때 서버로 옮겨요.

| 상황 | 복구 |
|---|---|
| 실리태번 설정이 날아감 / 초기화 / 확장 재설치 | ✅ 서버 목록을 읽어서 슬롯이 저절로 다시 보여요 |
| 목록 파일만 없어짐 | ✅ `🔍 백업 찾기`가 이전 목록을 보여 주고, 고른 것을 `↩ 복구`해요 |
| 목록 파일 둘 다 없어짐 | 🔸 그 방을 열고 `🔍 백업 찾기`를 누르면 그 방의 오토세이브와 QUICK은 찾아요. 직접 만든 슬롯은 서버 폴더의 `savepoint-slot-….json`을 `📥 세이브 가져오기`로 불러와야 해요 |
| 실리태번 데이터 폴더 전체가 사라짐 | ❌ `📤 세이브 내보내기`로 받아 둔 .json 파일만 남아요 |

`🔍 백업 찾기`는 찾은 백업을 **보여 주기만** 하고, 실제로 되살리는 건 `↩ 복구`예요. 데이터 폴더 전체를 잃는 경우에 대비하려면 가끔 `📤 세이브 내보내기`로 내려받아 두세요.

## 설정

확장 설정은 여섯 묶음으로 접혀 있어요. 접힌 제목 아래에 현재 설정 요약이 보이고, 펼침 상태를 기억해요.

| 묶음 | 내용 |
|---|---|
| 연결·AI 요청 | 요약 AI(연결 프로필 / 메인 API), 실시간 수신, 추론 강도, 응답 최대 토큰, 입력 한도, 한 번에 기록할 원문 분량, 요청 대기 제한, 전체 최대 시간, 짧은 연결 시험 |
| 체크포인트·기록 확인 | 기록 후 확인, 체크포인트 켜기, 간격, 여유분, 퀘스트 수락 방식, 기록에서 뺄 부분 |
| 기억 주입 | 주입 상한, 오래된 제목 상한, 최근 장면 수, 회상, 원문 회상, 주입 위치·깊이·역할 |
| 하이드·보관 | 하이드 방식(자동·수동·끔), 하이드하지 않을 최근 메시지, 오토세이브를 보관할 방 수, 보관함 방식, 새 채팅에서 이어하기 물어보기 |
| 화면 | 스킨, 처음 여는 탭, 한국어 보기 |
| 🛠 고급 | 기록 지침 (고치면 이후 버전의 기본 지침 개선이 자동으로 적용되지 않아요. 고친 뒤 기본 지침이 바뀌면 묶음 제목에 `⚠ 새 기본 지침 있음`) |

- 설정을 바꾸면 그 칸에만 `↺`가 생기고(손가락을 올리거나 길게 누르면 기본값이 보여요), 묶음 제목에 `변경 N`이 붙어요. `↺ 이 묶음 되돌리기`는 그 묶음만 기본값으로 되돌려요. 기억·세이브 슬롯·대기열은 그대로예요.
- 스킨: 클래식 JRPG / 네온 아케이드 / 글래스 사이버 / 다크 아카이브 / 파스텔 드림 / 터미널 / 딸기우유 / 듀얼 화이트 / 먹과 한지 / 크림 라테 / 스토리 콘솔 / 레몬 인형뽑기 / 진저브레드 하우스 / 크리스마스 니트 / 라일락 미드나잇 / 실리태번 테마 따라가기. 바닐라 버터는 v0.6.24에서 빠졌고, 쓰던 설정은 크림 라테로 바뀌어요. 모두 CSS만 써서 이미지나 글꼴을 따로 불러오지 않아요.
- 기록 지침 뒤에는 데이터 목록과 응답 형식이 자동으로 붙어요. 그래서 지침을 고쳐도 저장 형식은 깨지지 않아요.
- 설정에서 눌러서 고르는 칸에는 `▾` 표시가 붙어요.

## 문제가 생겼을 때

**📋 결과 복사**: 상태 바의 버튼을 누르면 버전, 요약 AI, 마지막 실패, 기록 확인 결과, 보낸 원문 범위를 글로 복사해요. 캡처 대신 그대로 붙여 넣으면 돼요. 자동 복사가 막힌 환경에서는 글 상자를 띄워요.

**요청 상태와 제한 시간**

- 진행 표시: `퀵세이브 1/2구간 #0–#54 · 첫 요청 · 응답 대기 42초`, `재요청 (검사 실패 3건) · 응답 대기 …`, `응답 받음 (38초) · 검사 중`.
- 연결 프로필은 기본으로 **실시간 수신**을 써서 `수신 중 · 사고 N자 / 본문 N자`로 응답이 실제로 오는지 보여 줘요. API가 지원하지 않으면 설정에서 끌 수 있어요.
- **새 출력이 들어오는 동안 대기 제한을 연장해요. 전체 최대 시간에 도달하면 중단해요.** 실시간 수신 중에는 `요청 대기 제한`(기본 300초)을 새 사고·본문 글자가 실제로 들어올 때마다 다시 세요. 같은 내용이 반복되거나 연결 유지 신호만 오는 건 출력으로 치지 않아요. 출력이 계속 와도 `전체 최대 시간`(기본 20분)이 지나면 중단해요.
- 실시간 수신을 확인할 수 없는 요청(메인 API, 실시간 받기 끔)은 `요청 대기 제한`이 요청 전체의 제한 시간이에요. 진행 표시에 `대기 5분 · 출력 중 연장 · 최대 20분` 또는 `전체 제한 5분`으로 지금 방식이 보여요.
- 중단하면 그 요청을 취소하고 원문을 그대로 둬요. 늦게 도착한 응답은 버려요. 실패 기록에는 이유를 **새 출력 없음 / 전체 최대 시간 초과 / 제한 시간 안에 응답 없음 / 요청 오류**로 나눠 남겨요.
- 실리태번이 `API request failed`로 감싼 원래 오류도 꺼내서 보여 줘요. 예: `API request failed ← Request too large… (상태 413)`.
- 실패하면 `마지막 실패`에 시도마다 걸린 시간, 응답 길이, 결과(빈 응답 / 생각 부분만 있음 / JSON 해석 실패 / 검사 실패 N건 / 요청 오류 / 제한 시간 초과)가 남아요.
- `📋 결과 복사`의 요청 기록에는 **입력 내역**이 있어요: 지침·출력 형식 / 카드·페르소나 / 상태·인물·시간 / 진행 장면 / 최근 장면 / 루팅·안내 / 새 원문 / 재요청 안내. 합계는 전체 입력 글자 수와 같아요. 확장이 만든 요청 기준이라, 연결 프로필이나 프리셋이 덧붙이는 내용은 포함되지 않아요. 실패한 요청의 기록은 실패 기록에 따로 남아서 이후 요청에 덮이지 않아요.
- 입력 한도 검사에서 전송 전에 멈추면 **`요청 전 입력 검사에서 중단 · AI 호출 없음`**으로 표시해요. 이전에 성공한 요청은 실패 기록에 붙이지 않아요. 요약 줄의 실패 건수도 시각이 아니라 같은 실패인지로 구분해요.
- 수신 기록은 **첫 사고 수신**과 **첫 본문 수신**을 나눠 보여 줘요. 생각만 하다 끊긴 요청은 `첫 본문 수신 없음`으로 남아요.
- `Load failed`는 주로 아이폰·아이패드 브라우저에서 요청이 끊겼을 때 나와요. 긴 세이브 중 화면이 꺼지거나 다른 앱으로 가면 생길 수 있어요.
- `짧은 연결 시험`은 대화 원문을 보내지 않고 작은 요청 한 번으로 연결만 시험해요.
