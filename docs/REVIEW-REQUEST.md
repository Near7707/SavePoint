## 무엇을 바꾸려는지 (설계안)

### 🔴 1. 화면 기억의 자리 (b1)
- 지금: 화면 기억 = `ctx().chatMetadata[MODULE]`. 실리태번 자체 저장이 이걸 채팅 파일에 씀.
- 바꿀 것: 방마다 SavePoint가 따로 쥔 보관함(방 주소 + `roomEpoch`에 묶음, 기억 파일의 `{ rev, wid }`와 `memLine` 함께). `state()`·`ensureState()`·`restoreEntry()`·`tidyNow()`·`pageState()`·리셋·불러오기 등 `chatMetadata[MODULE]`를 직접 읽고 쓰는 곳(약 17곳: `grep -n "chatMetadata\(?\.\)\?\[MODULE\]" index.js`)을 모두 이 보관함으로.
- 검사 모드(`checkQueue`의 `memSig`)도 이 보관함을 감시.
- `chatMetadata[MODULE]`(예전 사본)은 방을 열 때 읽은 그대로 두고 SavePoint는 쓰지 않음. 판정에는 그 사본의 해시만 씀.

### 🔴 2. SavePoint의 채팅 파일 쓰기에서 예전 사본 (b1)
- `sendMeta`: 지금은 `OWN_META`(`MODULE` 포함)를 화면 값으로 보냄 → b부터 `MODULE`은 **파일 값 그대로**(파일에 없으면 보내지 않음). `PAGE_KEYS`는 지금처럼.
- 그래서 b 뒤에 SavePoint가 채팅 파일에 쓰는 것은 메시지의 숨김·🔖·🔶 표시뿐(+ #0 이어하기).

### 🔴 3. 채팅 저장이 들어갔는지 확인하는 근거 (b1~b2)
- 지금: 채팅 파일 속 기억의 영수증(`proofOf`: wid + 기록), 다른 기기 기억 발견은 `foreignMemory`(`why: 'mem'`), 상태 표시만 바뀐 저장(`status`)도 기억 값으로 판단.
- 바꿀 것: 채팅 파일에는 기억이 없으므로 **기억 없는 방의 규칙**(`proof = null` → 보낸 사본·`marksInFile`)을 모든 방에 씀. `foreignMemory`·`status` 경로는 채팅 파일에선 없어지고, "다른 기기가 기억을 썼음"은 기억 파일의 (rev, wid) 충돌(`memfile.js` `conflict`·`overwritten`)이 대신.
- `serverCovered`·`covers`가 `MODULE`을 비교하는 부분: 예전 사본은 SavePoint가 더는 바꾸지 않으므로, 파일과 화면의 예전 사본 차이는 "구버전 기기가 다시 씀" 단서로만 씀(판정 2번 보류와 같은 결론, 쓰기 중에 발견하면 그 방 기억 쓰기 멈춤 + 안내).

### 🔴 4. 방 열기 (b1)
- 순서: `CHAT_CHANGED` → 지금의 채팅 파일 확인(`verifyRoom`, 채팅 저장 0회) → 통과하면 `decideRoom`(입력: 방 주소, 서버 파일의 고유값, `main_chat`, 예전 사본 해시, SavePoint 흔적, 원문 지문, 이 기기에서 확인된 이름 변경) → 결과별:
  - 연결·연결 복구: 기억 파일을 읽어 보관함에(`relinkMemory`는 빠진 단서·이름표만 씀).
  - 이전: `placeMemory`(예전 사본 → 기억 파일, 사본은 지우지 않음).
  - 분기: `branchRestore` → `placeMemory`.
  - 새 방: 보관함에 빈 기억만, **기억 파일은 첫 실제 변경 때** 만듦(고유값이 서버 파일에 있을 때만).
  - 보류·읽기 실패: 아무것도 쓰지 않음, 자동 기록 멈춤, 이유 한 줄(`why`) + `다시 확인`.
- `roomOpened()`의 "분기 복사본 `roomKey` 고치기"는 없어짐(분기 판정이 대신).
- 판정 중에는 방이 아직 안 열린 것으로 봄(`gateOpen()` 거짓). 판정 중 방이 바뀌면 결과 버림.
- 이름 변경(`CHAT_RENAMED`): 이 기기 설정에 적어 두고, 다시 연 방에서 판정 5번에 넘김.

### 🔴 5. 기억만 바꾸는 작업 (b1, 합격 1)
- 대기열 차례(`writeEntry`)에서 `hides === false`이고 숨김 표시가 하나도 안 바뀐 변경(`changedMarks` 빈 목록)은 **기억 파일만 씀**(채팅 파일 확인·저장 0회). 실패 처리: `refused` → 화면 되돌림, `pending`·`overwritten`·`conflict` → 그 방 기억 쓰기 멈춤 + 안내(되돌리지 않음), `unread` → 성공으로 보고 다음 쓰기의 첫 읽기가 다시 확인.
- 자동 저장 슬롯(AUTO)은 방금 쓴 기억 파일 내용으로.

### 🔴 6. 기억 + 숨김이 함께 바뀌는 작업의 순서 H1 (b2)
- 자동 하이드(체크포인트·퀵세이브·장면 닫기·👻): 기억 파일 → 성공(`ok`·`unread`)일 때만 화면 숨김 → 채팅 저장. 기억 실패 = 아무것도 안 바뀜. 기억 불명 = 화면 숨김 없이 멈춤. 기억 OK·채팅 저장 실패 = 기억은 그대로, 숨김만 되돌림(원문이 같이 들어감, 토큰만 더) + 안내.
- 리와인드·리셋·같은 방 불러오기·원문 변경 되감기: 새 기억 미리 계산 → 더는 안 덮는 메시지 숨김 풀기 → 채팅 저장 → 다시 읽기 → 기억 파일 → 새로 덮는 메시지 숨김(→ 채팅 저장). 숨김 풀기 실패 = 화면 되돌림, 불명 = 기억 안 바꾸고 멈춤, 기억 실패 = 원문 보임 + 예전 기억(겹침) + 안내.
- 한 대기열 차례 안에서 두 저장을 묶음. a에서 정한 원칙(시작한 방에 묶기, `liveState` 사본 계산, "변경이 남았는지"는 실제 기억 지문, 영수증으로 "이 저장이 쓴 기억", AI 요청 뒤는 `pageState`)을 그대로 이어 감.

### 🔴 7. 어긋남 H2 + `원문과 기억 맞추기` (b3)
- 방을 열 때 계산만: "숨겼는데 기억에 없음", 분기로 복사돼 온 숨김, 보류, 구버전 기기가 다시 쓴 사본, `#0` 미확정, 원문 변경 되감기 대기 → 안내 + 자동 기록 멈춤(채팅 저장 0회). "보이는데 기억에 있음"은 안내만.
- 버튼을 누르면 6의 순서로 맞추고 자동 기록 다시 시작. 이때만 채팅 저장 허용.
- 새 방 이어하기 #0: 계획의 ①②③.

### 🔴 8. 두 기기 (b4)
- 방을 열 때 그 방 AUTO 중 기억 파일의 (rev, wid) 목록에 없는 것이 있으면 "덮였을 수 있어요"(`maybeOverwritten`). README 알려진 한계 문구.

## 특히 봐 줄 곳

1. **나누기(b1~b4)가 안전한지.** 브랜치에서만 쌓으니 사용자에겐 안 가지만, 각 조각 끝에서 검사 전체가 통과할 수 있는 경계인지. 예: b1에서 6(하이드 순서)을 아직 안 바꾼 동안 자동 하이드는 "기억 파일 → 채팅 저장"만 임시로 하는데, 이 임시 상태로 검사를 통과시키는 게 의미가 있는지, 아니면 b1·b2를 합쳐야 하는지.
2. **3번(채팅 쓰기 확인 근거).** 기억 영수증 없이 표시(`marksInFile`)와 보낸 사본만으로 확인할 때 a 이전에 막았던 경우(실리태번 자체 저장이 먼저 씀, 응답 끊김, 다른 기기 삭제)가 다시 열리지 않는지. 숨김 표시가 하나도 안 바뀌는 채팅 저장(🔖 고치기 등)의 확인 근거.
3. **보관함으로 옮기는 범위(1번).** `chatMetadata[MODULE]`를 쓰는 곳 중 빠뜨리기 쉬운 곳, 실리태번이 채팅 정보 객체를 바꿔 끼우는 때(방 열기·분기·체크포인트 저장)에 보관함과 어긋날 수 있는지.
4. **방 열기 판정 중(4번)의 상태.** 판정·이전 중에 사용자가 메시지를 보내거나 방을 옮기거나 다른 기기가 같은 방을 여는 경우. 판정 결과를 언제 버리고 언제 다시 판정하는지.
5. **6번 H1 순서의 단계 사이마다** 실패·응답 없음·실리태번 자체 저장이 끼어들 때 "숨겼는데 기억에 없음"이 생기지 않는지. 특히 자동 하이드에서 기억 파일 `unread`(써졌다고 했지만 다시 못 읽음) 뒤 숨김을 해도 되는지.
6. 기억 파일 쓰기 요청이 응답 없이 끝난 뒤(합격 10·11) 같은 화면에서 이어지는 작업이 모두 막히는지, 다시 열 때 (rev, wid)로 판단하는 흐름에 빈틈이 없는지.
7. 이 설계에서 빠졌거나 계획과 다른 점, 더 작고 안전한 대안.

결과는 P1/P2/P3로, 가능하면 "어떤 순서로 하면 무엇이 깨지는지"와 함께 주세요. 코드는 아직 없어요(설계만).
