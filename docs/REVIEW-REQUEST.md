## 특히 봐 줄 곳
1. `writeEntry`의 새 흐름: 기억 파일 결과별 처리(되돌림 / 표시만 되돌림 / 계속)와, 채팅 쓰기 실패 시 표시만 되돌리는 것. 같은 대기열의 뒤 변경 취소 규칙이 맞는지.
2. b1 임시 순서의 위험: 범위가 줄어드는 변경(리와인드·리셋·불러오기)에서 채팅 쓰기가 실패하면 "기억은 줄었는데 숨김은 그대로"가 남음. b2 전까지 이 상태로 둬도 되는지, 아니면 b1에서 줄어드는 변경만 지금 순서(채팅 먼저)로 둘지.
3. `linkHome`: 판정 뒤 채팅 파일을 다시 읽어 `sameInput`으로 확인하는 것으로 충분한지(판정 중 방 이동·메시지 추가·다른 기기 저장). 실패·보류 때 `home.st`를 비우는 것(화면에 기억이 안 보임)이 맞는지.
4. `homeWrite`의 새 방 첫 생성: `placeMemory` 결과(done·adopted·hold·stop)와 `memLine` 처리.
5. `renameHome`: 단계별 "먼저 읽고 이미 된 건 건너뜀"과, 알림 이름 ≠ 실제 주소일 때 `{from, to: 실제 주소}`를 더하는 조건(10초·같은 범위).
6. `syncHide`의 `ranged`와 저장 차례 안 `saveChatSoon` 생략: 표시가 바뀌었는데 채팅에 안 쓰이는 길이 생기지 않는지.
7. `sendMeta`에서 `MODULE`을 파일 값으로 바꾼 뒤 `foreignDiff`·`foreignMemory`·`covers`가 예전 사본을 다루는 방식.
