## 고친 것 (실제 사고)

방을 옮기는 순간 SavePoint의 작은 저장이 실리태번 `saveMetadata()`(0.1초 뒤 그때 열린 방을 저장)를 거쳐, 옮겨 간 방 이름 + 메시지 0개 + 고유값 없는 메타데이터를 보냄 → 서버가 덮어씀 → 그 방이 그리팅만 남음. 이제 SavePoint가 부르는 순간의 방·메시지·메타데이터(고유값 포함)를 직접 `/api/chats/save`(그룹은 `/api/chats/group/save`)로 보내고, 여는 중인 방(메시지 0개 또는 고유값 없음)은 보내지 않음.

## 특히 봐 줄 곳

1. `writeChatFile`이 "부른 순간의 방"만 보내는지: 대기(`isChatSaving`) 뒤 담기 전까지 다른 방이 끼어들 틈, 담기~보내기 사이에 await가 없는지.
2. 늦게 도착한 사본 대책(쓰기 뒤 다시 담아 다르면 한 번 더 보내기): 실리태번 자체 저장·다른 기기 저장과 겹칠 때 더 나빠지는 경우가 있는지, 다시 보내기가 `serverCovered` 확인 없이 나가는 것이 괜찮은지.
3. 실리태번 `saveChat`이 하던 것 중 빠진 것(`date_last_chat`, 요청 압축, 고유값 거절 확인창)이 문제를 만드는지. 특히 1.9MB 같은 큰 채팅에서 압축 없이 보내는 것.
4. 고유값 거절(400 `integrity`) 처리: 방을 막고 되돌리는 것이 `transact`·`guardedSave`·QUICK·`verify` 흐름 전부에서 맞는지.
5. 그룹방: `chatId`(그룹의 `chat_id`)로 보내는 것, 그룹 파일 읽기와 같은 이름인지.
