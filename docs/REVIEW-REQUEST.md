## 일부러 이번에 안 고친 것 (열린 문제)

- **P1** (실리태번 저장이 기다리는 사이 방이 바뀌면 다른 방 파일에 씀), **P2-3** (대기열 밖에서 기억을 바꾸는 길). 확인 결과 확장만으로는 실리태번 저장에 대상을 고정해 맡길 방법이 없고, 직접 쓰기는 같은 방에서 실리태번 저장과 순서가 엇갈리면 새 답변·다른 기기의 삭제를 덮을 수 있어서 보류. 다음 단계로 "기억을 채팅 파일 밖(사용자 파일 공간)으로 옮겨 SavePoint의 채팅 파일 쓰기를 하이드 수준으로 줄이는" 설계를 검토 중. 자세한 건 REVIEW.md v0.6.62의 "열린 문제".
- 이 두 건은 이번 리뷰에서 다시 보고하지 않아도 돼요. 대신 위 설계 방향에 대한 의견(빠진 위험, 더 나은 저장 위치)이 있으면 따로 적어 주세요.

## 특히 봐 줄 곳

1. `line`(v0.6.62): 기억을 통째로 바꾸는데 `freshState`를 거치지 않는 길이 있는지(그러면 예전 편집이 새 기억에 들어갈 수 있음).
2. `writeEntry`의 적용 오류 처리: 되돌린 뒤 하이드 다시 맞추기, 일부러 멈춘 변경(`Stale`)의 문구, 대기 중인 다른 변경에 미치는 영향.
3. 휴대폰 빠른 설정(v0.6.63): 스킨별 모양, 열린 동안 다시 그려질 때(저장 결과 배너 등) 본문이 잠깐 보였다 숨는지, 닫은 뒤 스크롤 위치.
