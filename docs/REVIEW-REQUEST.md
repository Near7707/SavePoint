## 바뀐 것
- **P1 삭제 표시:** 그룹 방의 `MESSAGE_DELETED`가 `sendCut = { key, epoch }`를 적어요(후보도 버림). 생성 시작·끝은 표시를 안 건드려요. 다음 `GROUP_WRAPPER_STARTED`가 후보와 표시를 함께 꺼내 지우고, 같은 방·회차 표시였으면 그 묶음은 `sendGroup = null`(전체 알림만). 방 이동(`sendEnd`)도 지워요. 손으로 지운 뒤 첫 전송도 알림만이에요(README 알려진 한계 v0.7.0-c1b).
- **P2 사본 확인:** 생성 시작 때 숨김마다 그때의 `extra` 참조도 적어요(`[i, m, extra]`). `sendHas(copy, x)` = `x`가 객체 · 지금 채팅에서 그 `extra`를 쓰는 메시지가 하나 이하 · 확인 단계가 받은 사본(`copy`)에 그 `extra`가 정확히 하나.
  - `startHeld`: 같은 자리·같은 객체이면서, 아직 숨김이거나 시작 때 `extra`가 사본에 확실히 있으면 통과. 자리 메시지가 바뀐 건 그대로 멈춤.
  - `sendGuard`: 지금 숨김 중 지금 `extra`가 사본에 확실히 있는 것(사본 뒤 다시 숨김)은 빠진 구간에서 빼요.
  - 짝을 못 찾으면 예전처럼 멈추거나 물어요. "사본에서 빠짐 확정 → 진행/확인창" 길은 만들지 않았어요(⚪).

## 특히 봐 줄 곳
1. **표시는 그룹 방이면 묶음 중 삭제에도 적어요.** 묶음 중엔 재생성이 시작될 수 없지만, 우리 `groupOn`과 실리태번의 `is_group_generating`이 풀리는 순서 차이를 피하려고 늘 적었어요. 그 대가로 묶음 중 삭제 뒤 다음 전송 하나가 알림만이 돼요.
2. **사본 뒤 다시 숨긴 원문은 지금 `extra`로 짝지어요.** 그 사이 `extra`가 바뀌면 못 찾아 예전대로 물어요.
3. **앞 interceptor**가 사본에서 메시지를 빼거나 깊게 복사하면 짝을 못 찾아 예전대로 멈춰요.
4. **겹 장치:** `sendEnd`에서 표시를 안 지워도 다시 열면 회차가 바뀌어 표시가 안 맞아서 검사가 못 잡아요.
5. **공유 확인은 지금 채팅 기준**이에요. 사본에도 정확히 하나여야 해서 두 메시지가 같은 원문을 가리킬 때만 통과한다고 봤어요.
