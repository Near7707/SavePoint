## 바뀐 것
- 방 열기(`다시 확인`의 재연결·충돌 복구 포함)는 채팅 파일을 쓰지 않아요. 풀어야 할 표시만 화면에서 정리하고 다음 정상 저장에 실려요. 새 숨김은 다음 세이브·체크포인트·👻 때. 사용자 숨김은 그대로.
- 구형 기억 형식 정리(`tidyNow`)는 하이드 계산을 안 돌려요(기억 업로드는 예전처럼).
- 멈춘 방(H2)에서는 `persistSoon`·`saveChatSoon`이 타이머를 만들지 않고, 이미 잡힌 타이머도 `mainBusy()`를 보기 전에 멈춰서 1.5초 재예약이 없어요. 보류·충돌 방은 그대로.
- 그대로 둔 것: 답변 생성 쪽 하이드 계산(방을 연 직후 첫 답변에 원문과 브리핑이 함께 갈 수 있음 → README 알려진 한계, c에서), 원문 변경 예외, 열기의 `reconcile()`.

## 특히 봐 줄 곳
1. 열기에서 화면만 정리한 표시(🔖 정리·`savepointVisible`·`HELD` 떼기)는 다음 저장까지 화면과 서버가 표시만 달라요. 다음 저장 전 확인(`serverCovered`)이 이 차이를 문제로 보지 않는지(검사 12·13·11f·29는 그 뒤 세이브까지 통과).
2. `tidyNow`의 `hides: false`를 빼도 안 잡혔어요. 열기에선 `roomOpened`의 화면 정리가 정리 작업 차례보다 먼저 돌아서(정리 작업은 `homeSettled`·대기열을 거침) 그 차례엔 바뀔 표시가 안 남아요. 정리 작업이 먼저 도는 순서가 실제로 있는지.
3. `saveChatSoon` 콜백의 `h2Here()`를 빼도 안 잡혔어요(답변 중 `saveChatSoon` 타이머가 잡힌 뒤 방이 멈추는 장면을 못 만듦). 입구는 14, `persistSoon` 콜백은 15가 지켜요.
4. 15는 멈춤을 손으로 걸어요(`home().h2 = …`). 답변 중 `다시 확인`은 채팅 파일 확인이 `busy`로 미뤄서 답변 안에서 방을 멈출 수 없었어요. 실제로 답변 중에 H2가 생기는 길이 있는지(없으면 콜백 확인은 겹 장치).
5. 기대가 바뀐 기존 검사: `b2b-race` 11f(열 때는 그대로·저장 0 → 다음 세이브가 다시 숨기고 화면·서버에서 다른 탭 값 지움), `home-link` 29(다시 확인으로 연결돼도 숨김은 다음 세이브에서).
