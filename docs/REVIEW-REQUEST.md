## 바뀐 것
- 구형 기억 정리 차례는 방금 읽은 서버 채팅과 화면 기억을 `h2Of`로 비교해, 어긋나면 그 차례만 보류해요(채팅·기억 파일 쓰기 0). 방은 멈추지 않고, 정식 판정은 `다시 확인`·방 열기에 맡겨요.
- 자동 정리는 기존 로그에 이유가 남고, 사용자가 누른 세이브(와 `pageState`를 쓰는 동작)는 "채팅과 기억이 맞지 않아요. `다시 확인` 후 다시 시도해 주세요."만 보여 줘요.
- 그대로 둔 것: 그 뒤 자동 체크포인트가 기존 숨김 해제 경로를 타는 것(README 알려진 한계 v0.7.0-b3b2a), 타이머 두 곳.

## 특히 봐 줄 곳
1. `h2Of`를 통째로 써서 `source`(기록 원문이 서버와 다름)도 정리를 보류해요. 화면에서 원문을 고친 직후 되감기 저장 전에 정리 차례가 오는 경우도 미뤄지는데, 되감기 차례가 적용 중에 정리를 함께 해서 괜찮다고 봤어요. `hides`만 봐야 하는지.
2. 보류는 `Stale`이라 그 차례만 끝나고 대기열 다음 변경은 그대로예요. 같은 열기에서 다음 `state()` 읽기가 정리를 다시 예약할 수 있고, 어긋남이 남으면 또 보류(쓰기 0). 반복 예약이 문제가 될 길이 있는지.
3. 비교 대상이 `pageMem()`(화면의 원래 기억, 정리 전)이에요. `h2Of`가 구형 형식에서도 `lastIndex`·`hashes`·`mem`을 같은 뜻으로 읽는지.
4. `pageState` 쪽 문구 갈래는 검사가 없어요(세이브 경로만 16이 지킴).
