## 정한 기준 (그대로 봐 주세요)

- **v0.6.87:** 저장 뒤 다시 읽은 파일(실패 판단 `settleWrite`, 다시 읽기 `verify`, 나중 확인 `confirmUnsure`)이 다음 저장의 기준(`gate.seen`)이 되는 규칙 = 저장 전 확인과 같음(`fileBase`: 지금까지의 기준에 대해 `covers` + 다른 기기 기억 아님). "이번 변경이 파일에 있음"과 "다음 저장 허락"은 따로. 다시 읽기에서 `gone`·`mem`은 방을 막고(이번 변경은 유지), 기다리면 풀릴 수 있는 것(`more`·`diff`)은 기준만 그대로.
- **v0.6.87:** 저장 차례 밖의 확인(불러오기 질문 뒤)은 기준을 바꾸지 않음(`adopt: false`).
- **v0.6.88:** 이어하기가 가는 사이 첫 메시지 뒤에 새 메시지가 생기면, 거절돼도 첫 메시지는 남기고 기억만 되돌림. 화면이 #1부터면 #0을 그 앞에 제 번호로 그림(화면만).

## 특히 봐 줄 곳

### v0.6.87 (저장 쪽)
1. `fileBase`를 쓰지 않고 파일을 기준으로 삼는 곳이 더 남았는지(`setSeen`을 부르는 곳 전부).
2. 다시 읽기에서 `more`·`diff`를 막지 않는 것: 그 파일이 다른 기기 것일 때 다음 저장 전 확인이 반드시 잡는지.
3. `confirmUnsure`에서 `gate.seen`과 `u.written` 중 더 새 기준을 "기준이 쓰기 전 파일 그대로인가"로만 가리는 것이 틀리는 순서.

### v0.6.88 (동작)
4. "목록이 길어짐"으로만 새 메시지를 봄. 그사이 메시지가 생겼다 지워진 경우, 실리태번이 다른 방식으로 메시지를 넣는 경우(그룹 자동 진행 등).
5. `addOneMessage`의 `forceId`·`insertBefore`가 실리태번 버전별로 같은지(1.19 소스 확인).
