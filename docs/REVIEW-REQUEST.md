## 바뀐 것
- **P1 그룹:** `GENERATION_AFTER_COMMANDS`(미리 계산 아님 · 그룹 묶음 밖 · 그룹 방 · `'normal'`/없음)에서 보내기 후보 `{ key, epoch, n: genCount }`. 다음 `GROUP_WRAPPER_STARTED`가 같은 방·회차·생성 번호이고 묶음 종류가 `'normal'`/없음일 때만 한 번 받아 `sendGroup`(이 묶음은 물음). 안 쓴 후보는 새 실제 생성 시작·`MESSAGE_DELETED`·생성 끝·방 이동에서 버림. `FINISHED`에서 `groupOn`·`sendGroup`·이번만 지움. 그룹 재생성·자동 진행은 1:1 재생성처럼 경고만.
- **P2-1:** 실제 생성 시작 때 기존 `syncHide`·`refreshInjection` 뒤 숨김 목록(번호 + 메시지 객체)을 적고, 확인 단계에서 "숨김 없음 → 통과"보다 먼저 비교해요. 빠지거나 그 자리 메시지가 바뀌었으면 `changed`로 멈춰요. 늘어난 숨김은 보지 않아요.
- **P2-2:** `genDry`를 없앴어요. 미리 계산은 `onGenerationStarted`에서 바로 돌아가요. 모의 검사도 미리 계산에는 확인 단계를 안 불러요.

## 특히 봐 줄 곳
1. **후보가 남는 길:** 묶음이 `try` 전에 돌아가면(연결 없음 등) 후보가 남아요. 그 뒤 답변을 하나도 안 지운 그룹 재생성(마지막이 사용자 글)이 바로 오면 그 묶음은 물을 수 있어요. 지운 게 없어서 손실은 없다고 봤어요.
2. **시작 뒤 늘어난 숨김은 무시:** 보내기 뒤 150ms 타이머의 자동 하이드가 기록 범위 안 숨김을 늘리는 평범한 경우에 멈추지 않게 했어요. 늘어난 숨김이 기억 범위 밖일 수 있는 길이 있는지 봐 주세요(이건 사본엔 원문이 들어 있어 빠진 게 아니라고 봤어요).
3. **캐릭터 답하기 버튼:** `Generate('normal', { force_chid })`는 바깥 `Generate`를 거쳐서 보내기로 봐요(c 설계대로 물음).
4. **겹 장치:** 새 생성 시작의 후보 버리기와 후보 생성 번호 비교는 서로 막아서, 하나만 빼면 안 잡혀요(둘 다 빼면 9가 잡음). `AFTER_COMMANDS`의 `groupOn` 확인은 묶음 안 캐릭터의 `ENDED`가 후보를 버려서 안 잡혀요.
5. **예전 판 실리태번:** `GENERATION_AFTER_COMMANDS`가 없으면 그룹은 아예 안 물어요. 손실 쪽은 아니에요.
