## 바뀐 것
- 맞추기가 첫 요청을 보내기로 한 순간부터 검증이 끝날 때까지 `home.fitCheck`(확인 대기). 기억 읽기 실패·기억 충돌·마지막 채팅 읽기 실패 등 어떻게 끝나도 남고, 아무것도 안 보냈으면 지워요. 같은 방을 열어 둔 동안 새 기억에 연결돼도 유지, 다시 열면 사라짐. 그동안 저장·자동 기록 멈춤, 창에 `다시 확인`.
- `다시 확인`(맞추기 중 미뤄진 것 포함)은 `linkRounds`의 마지막 채팅 읽기(`again`)로 판정: 멈춤·H2가 없을 때 고유값·`fileBase`가 맞아야 진행(아니면 대기 유지), 숨김·🔖 차이면 다시 열 때까지 멈춤, 같으면 화면에만 남은 예전 SavePoint 숨김(새 기억 범위 밖)만 걷고 이어 감.

## 특히 봐 줄 곳
1. 표시는 `guard` 첫 호출이 참일 때 세워요. "들어가지 않음"이 확인된 실패(`'revert'`, `'failed'`)도 표시를 남겨요(H2가 다시 걸려 있어 다음 확인도 안전하다고 봄). 지우는 게 나은지.
2. `fitChecked`는 연결 직후 H2가 없을 때만 돌아요. `recheckHome('auto')`가 `linkRounds` 뒤에 H2를 지우는 b3b1 예외 갈래에서는 표시만 남아 사용자 `다시 확인`을 기다려요.
3. 고유값·`fileBase`가 안 맞으면 대기 유지만 하고 따로 "다시 열기" 안내는 없어요.
4. 표시가 있어도 H2가 남아 있으면 맞추기를 다시 할 수 있고, `fitEnd`의 같은 비교를 지나야 표시가 지워져요.
5. 망가뜨리기로 못 지킨 곳: `fitChecked`가 새 기억 대신 기억 없음으로 범위를 계산해도 안 잡힘(장면을 못 만듦).
