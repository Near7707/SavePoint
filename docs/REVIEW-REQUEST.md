## 무엇을 막으려 했나

실리태번은 저장할 때 화면의 채팅 전체로 파일을 다시 써요. 그래서 아래 경우에 SavePoint가 쓰면 기존 대화를 덮어쓸 수 있었어요.

1. 방이 열리는 중(새 방 ID, 메시지 없음, CHAT_CHANGED 전) — 이어하기·기억만 불러오기가 12개짜리 대화를 1개·0개로 저장
2. 빈 방으로 보고 확인창을 띄운 뒤 메시지가 도착 — 처음 계획대로 #0 교체
3. 시스템 메시지 하나짜리 방을 인사말로 보고 교체
4. 오래된 화면(다른 기기가 더 진행) — 서버 22개를 화면 20개로 덮어씀
5. 실리태번이 저장 실패를 화면에만 알리고 정상 반환 — 성공으로 보고 위치 전진·QUICK 백업

## 합의한 규칙 (구현이 이걸 지키는지 봐 주세요)

- CHAT_CHANGED는 확인 시작 신호일 뿐. 서버 파일을 실제로 읽어 화면이 파일을 덮을 때만 그 방을 연 것으로 봄.
- 관문은 파일 쓰기만이 아니라 **화면을 바꾸기 전**에 걸림(#0 교체, 하이드 표시, 🔖).
- 쓰기 전 비교는 SavePoint가 바꾸기 전 상태로. 맞지 않으면 다시 **읽어서** 판단하고, 시간이 지났다는 이유로 허용하지 않음.
- 비교 범위: 본문, 다른 스와이프 본문, `swipe_info`, 첨부·번역 등 `extra`, 다른 확장의 메타데이터. (SavePoint 몫과 `is_system`만 뺌)
- 빈 응답(새 방인지 읽기 실패인지 모름)이면 이어하기를 막음.
- 이어하기: 답한 뒤 방 전체를 다시 확인. 카드 인사말로 확인되지 않는 메시지 하나짜리 방은 교체하지 않음.
- 저장 뒤 결과: 그대로면 이번 변경만 되돌림 / 확인 불가면 되돌리지 않고 "확인하지 못했어요", 성공 안내·QUICK 백업 보류.
- 확인 불가 뒤에는 서버를 다시 확인할 때까지 체크포인트와 다음 쓰기를 보류. 같은 방에 작업이 연달아 오면 앞 작업 결과를 확인한 뒤 다음 쓰기를 판단.

## 특히 봐 줄 곳

1. **관문을 우회하는 길이 남았는지.** 채팅 파일에 쓰는 길은 `writeEntry`(대기열), `guardedSave`(`persistSoon`·`saveChatSoon`) 두 갈래로 모았어요. 화면을 바꾸는 길 중 `transact`를 거치지 않는 것(`syncHide`, `repairKeep`, `reconcile`, `unhideAll`, `state()` 안의 업그레이드)이 관문 밖에서 불리는 곳이 없는지.
2. **`pageBase`와 불러오기의 `base`.** 대기열에 불러오기와 다른 변경이 섞였을 때, 쓰기 전 비교가 "SavePoint가 바꾸기 전 화면"을 맞게 만드는지.
3. **`writeResult`의 세 갈래 판단.** 저장 직후 실리태번이 또 저장해서 파일이 더 앞서 있으면 `ok`, 다른 것이 섞이면 `unsure`로 가는지. `failed`로 잘못 판정해서 이미 들어간 내용을 되돌릴 경우가 없는지.
4. **확인 불가 처리.** `gate.unsure` 동안 퀵세이브 실행 흐름(`summarize`)의 남은 구간, 루팅 보충, `autosave`, `quickSave`, `noteAuto`가 위치를 앞으로 보내거나 백업하지 않는지. `confirmUnsure`가 `rev`만으로 확인하는 게 충분한지.
5. **오탐.** 실리태번이 방을 열면서 메타데이터를 바꾸고 바로 저장하지 않으면 `meta` 불일치로 막힐 수 있어요. 실리태번 코드 기준으로 그런 키가 있는지.
6. **그룹 채팅.** `/api/chats/group/get` 응답 형식(머리줄 유무)을 맞게 다뤘는지. 모의 환경에 그룹이 없어요.
7. **동시성.** 방 확인 중(`checking`) 사용자가 누른 작업, 대기열 쓰기 도중 CHAT_CHANGED, 방 이동 뒤의 저장 뒤 읽기(`moved` → `Unconfirmed`)가 다른 방에 쓰거나 잘못 되돌리지 않는지.

## 알고 있는 한계

- 서버를 읽은 직후~쓰기 사이에 다른 기기가 저장하는 틈은 확장에서 못 막음.
- 다른 기기에서 `/hide`만 바꾼 차이는 비교하지 않음.
- 긴 방은 저장마다 파일을 읽어서 느려질 수 있음(작은 저장 1번, 큰 저장 2번).
- 인사말 없는 캐릭터의 새 방은 파일이 없을 수 있어 이어하기를 묻지 않음.
