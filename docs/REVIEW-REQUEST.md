## 회귀
숨긴 옛 원문을 고치고 답변 시작 → SavePoint가 화면에서 임시로 펼침 → 실리태번이 그 화면을 저장(서버도 펼침) → 원문을 되돌려 화면이 다시 숨김 → 다음 차례의 `releasedOf`가 "마지막으로 본 파일은 숨김 · 지금 파일은 아님 · 화면은 숨김"으로 다른 곳의 해제로 봄 → 숨김을 모두 펼치고 `freed`, 잘못된 안내.

## 특히 봐 줄 곳
1. 예외 조건(`pageHid && !user && tok && r.snap.live?.[i] === tok && st && !st.review && st.lastIndex >= i`)이 다른 기기의 해제를 놓치는 길이 없는지. 특히 다른 기기가 이 탭이 펼친 사이 저장된 파일(값이 들어 있음)을 그대로 두고 기억만 바꾸거나, 그 파일을 읽어 리셋을 진행하면서 값을 남기는 경우.
2. 기억이 덮는지를 화면 기억으로 보는 것: 11c(다른 기기가 기억 파일만 리셋)는 기억 쓰기의 충돌이 먼저 막아서 이 조건이 직접 검사되지 않음. 화면 기억만으로 충분한지, 아니면 마지막 기억 확인(`homeStill`) 뒤에만 예외를 줘야 하는지.
3. 값 정리 시점: 다시 숨길 때 화면 값만 떼고 `liveTok`은 남기는 것, 확정된 해제(`!live && i > floor && !m.is_system`)에서 다른 탭의 값까지 화면에서 떼는 것.
4. `LIVE_KEY`를 `OWN_KEYS`에 넣어 비교(`plain`)에서 뺀 영향: 서버엔 값이 있고 화면엔 없을 때 다른 검사(`serverCovered`·`fileAllows`·확인용 사본)가 같은 메시지로 보는지.
