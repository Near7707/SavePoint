## 바뀐 것
- 스와이프·새 답변 이벤트의 🔖 고치기는 화면을 바로 바꾸지 않고 요청만 남겨요. 메시지 객체당 하나, 시작 전이면 마지막 스와이프로 합쳐요. 답변 중이면 기다렸다가 대기열에 넣어요.
- 차례에서: 같은 방·열기 회차·같은 메시지 객체·요청한 스와이프·스와이프 중 하나의 🔖 근거·아직 🔖 없음을 다시 봐요 → 기억 파일 읽기 확인 → 채팅 비교 → 서버 그 메시지의 🔖 근거·다른 곳 직접 숨김 확인 → 화면에 🔖 + 그 메시지의 SavePoint 숨김만 풂 → 채팅 파일만 저장. 서버에 이미 있으면 화면만.
- 요청 직전·다시 보낼 때 `guard`가 같은 것을 그 라운드 파일로 다시 봐요(보낸 뒤 다르면 `'stop'`).
- 기다리는 동안 그 메시지는 `syncHide`의 새 숨김에서 빠져요. 요청이 더 유효하지 않으면(방·메시지·스와이프 바뀜, 근거 사라짐, 방 멈춤) 보호도 사라져요.
- 멈춘 방은 요청을 안 받고, 기다리던 요청도 버려요(풀려도 자동 실행 없음).

## 특히 봐 줄 곳
1. 화면의 🔖가 차례에서 붙어요(예전엔 즉시). 🔖였던 메시지는 숨김이 없어 보호만으로 원문이 남는다고 봤어요.
2. 서버 판단은 그 자리 메시지만 봐요. 다른 메시지의 🔖 차이는 안 봐요(저장 안 한 스와이프가 있는 메시지도 다르게 보여서).
3. 성공 응답 뒤 다시 읽어 확인하지 않아요(예전 백그라운드 저장과 같음).
4. 겹 장치: 차례의 서버 근거 확인(요청 직전 `guard`가 막음), 답변 중 기다림 두 곳(하나만 빼면 다른 하나가 막음). 요청 합치기를 빼도 결과는 같고 요청 수만 늘어요.
5. 차례의 채팅 비교가 답변 때문에 다르면(`busy`) 방을 막지 않고 요청을 다시 기다리게 했어요. 예전 백그라운드 저장처럼 `gate.held`로 넘기면 그 저장엔 🔖가 없어서 사라졌어요(`save-adopt` 4가 잡음). 방을 `busy`로 막지 않는 것이 괜찮은지 봐 주세요.
