## 바뀐 것
- **조기 해제 없앰(P2):** `sendGuard` 입구의 `sendPrep.release()`와 `onGenerationStarted`의 생성 번호 기록(`sendPrep.n`)을 지웠어요. 준비 창은 버튼이 부른 `generate()`가 돌아올 때(답변 저장까지 끝남·중지·조기 반환·오류)만 닫혀요. `automatic_trigger: true`는 그대로예요.
- **`중지 요청`:** 준비 창의 `customButtons`에 결과 없는 버튼 하나(`action`만, 창 유지). `ctx().stopGeneration()`을 부르고 문구를 "중지를 요청했어요. 준비 중에는 요청이 적용되지 않을 수 있어요. 작업이 끝나면 이 창이 닫혀요."로 바꿔요. 여러 번 누를 수 있어요. 10초 안내는 중지를 누른 뒤엔 문구를 덮지 않아요.
- **버튼 호출 끝의 '답변 중' 정리:** 생성 번호 대신, 호출 중 시작이 정확히 하나이고 실리태번 생성 표시(`body.dataset.generating`)가 없을 때만 `mainGenerating`을 꺼요(끝 신호 없이 일찍 돌아온 경우).
- **P3:** "확인 단계가 멈추면 끝 신호 없음" 설명을 바로잡았어요(REVIEW.md c2a 항목·주석). 모의 환경도 기본으로 끝 신호를 보내고, 없는 경우는 `M.genNoEnd`로 따로 검사해요(19).

## 특히 봐 줄 곳
1. **'답변 중' 정리 조건**(`genCount === n0 + 1` + 생성 표시 없음)이 다른 생성과 겹칠 때 잘못 끄는 길이 있는지 봐 주세요. 틀려도 기존 "어떤 끝 신호든 끔"과 같은 정도라고 봤어요.
2. **실리태번 `Popup`의 Enter:** 포커스된 결과 없는 버튼에서 Enter를 누르면 `complete(NaN)`이 불릴 수 있는데, `onClosing`이 거짓이라 창은 그대로라고 봤어요.
3. **덮는 창 위의 확인창:** 버튼 답변이 다시 확인창에 걸리면 `callGenericPopup`이 준비 창 위에 떠서 누를 수 있어야 해요. 실리태번에서 두 모달이 겹칠 때 위 창이 눌리는지 확인 부탁해요.
4. **검사 27 장면:** a) `onFirst`로 SavePoint보다 먼저 도는 시작 처리기에서 일반 자동 생성, b) 누르기 전부터 서버 확인을 기다리던 일반 생성(그사이 취소된 전송의 끝 신호로 '답변 중'이 꺼진 뒤 누름)이 내 시작 뒤 확인 단계에 도착. 실제 순서와 맞는지 봐 주세요.
5. 10초 안내가 중지 문구를 덮지 않는 건 검사가 없어요.
