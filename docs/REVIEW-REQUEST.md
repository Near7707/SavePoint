## 특히 봐 줄 곳

### v0.6.71 (`home.js`, v0.7.0 준비)
1. 6번 `relink` 결과를 `relinkMemory`로 실행할 때 **빠진 단서(`moved-`·`copy-`·`int-`)를 먼저, 이름표를 마지막에** 쓰고, 본체는 절대 다시 쓰지 않는지.
2. 사본은 **기억 파일에 적힌 것**(`d.copy`)을 쓰는데, 채팅에서만 사본이 사라졌을 때 연결되는 것이 안전한지(고유값이 같은 방을 증명할 때만). 채팅에 다른 사본이면 보류.
3. "본체가 그대로일 때만": 판정 때 본 (rev, wid)(`seen`)와 재시도 처음·이름표 직전에 비교 → `memGone`·`memChanged`·`read`로 멈춤. 빠진 경로가 있는지.
4. 이름표 직전(`recheckStart`)의 `copy-` 재확인이 처음 이전과 `writeCopy`가 없는 재시도 모두에서 도는지.
5. 되감기 이력 확인(`usableEntry`): `before`·`after`·순서 목록 일치·`nextBefore`/`nextAfter` 검사가 정상 이력(`before: null` 등)을 잘못 막지 않는지, 손상을 놓치지 않는지.

### v0.6.72 (저장 쪽, 가장 중요)
6. `writeChatFile`이 "부른 순간의 방"만 보내는지: `isChatSaving` 대기 뒤 담기 전까지 다른 방이 끼어들 틈, 담기~보내기 사이에 await가 없는지.
7. 늦게 도착한 사본 대책(쓰기 뒤 다시 담아 다르면 한 번 더 보내기): 실리태번 자체 저장·다른 기기 저장과 겹칠 때 더 나빠지는 경우, 다시 보내기가 `serverCovered` 확인 없이 나가는 것이 괜찮은지.
8. 실리태번 `saveChat`이 하던 것 중 빠진 것(`date_last_chat`, 요청 압축, 고유값 거절 확인창)이 문제를 만드는지. 특히 1.9MB 같은 큰 채팅에서 압축 없이 보내는 것.
9. 고유값 거절(400 `integrity`) 처리: 방을 막고(`gate.why='integrity'`) 되돌리는 것이 `transact`·`guardedSave`·QUICK·`verify` 흐름 전부에서 맞는지.
10. 여는 중인 방(메시지 0개·고유값 없음)은 보내지 않는 규칙이 정상 방(모든 메시지를 지운 방 등)을 잘못 막는 경우.
11. 그룹방: `chatId`(그룹의 `chat_id`)로 `/api/chats/group/save`에 보내는 것이 그룹 파일 읽기와 같은 이름인지.

### v0.6.73 (화면)
12. 결과 재사용 열쇠(`방|st.rev|주입 옵션`)와 `st.mem` 객체 비교로 충분한지 — rev를 안 올리고 기억을 제자리에서 고치는 길이 있으면 숫자가 오래됨.
13. 탭을 떠나거나 방을 바꿀 때 계산이 확실히 멈추는지, 다른 방 결과가 섞이지 않는지.

### v0.6.74 (하이드 동작)
14. 다시 보이는 길이 하나뿐인지: SavePoint 하이드 표시가 있고 숨겨져 있고 `i > floor`(기억이 있고 검토 중이 아니면 `lastIndex`, 아니면 -1). 끔·전원 끔·최근 N개 변경·메시지 삭제로는 풀리지 않는지.
15. 사용자가 직접 숨긴 것과 펼친 것(`VISIBLE`)은 어떤 경우에도 건드리지 않는지. 예전 `HELD` 표시 정리가 맞는지.
16. 메시지를 지워 번호가 당겨질 때: 기록된 원문을 지우면 원문 변경(되감기/검토)으로 가고, 기록 안 된 최근 메시지만 지우면 하이드가 그대로인지.

### v0.6.75 (화면)
17. 전원 버튼이 전체 설정 `사용`과 같은 설정을 바꾸고, 끄면 주입·체크포인트가 멈추되 숨긴 원문은 그대로인지.
18. 🔶 하이드 제외가 SavePoint의 하이드만 막고 `/hide`·눈 버튼은 막지 않는지. 이름만 바뀐 곳에서 예전 문구가 남은 곳.
19. 스킨 16개에서 `.sp-power .sp-btn.sp-power-btn`이 스킨별 `.sp-btn` 규칙을 이기는지(그림자·눌림 효과 없음).
