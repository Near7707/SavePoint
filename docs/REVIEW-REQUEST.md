## 이번에 더한 것 (사용 중 오경고)

- 생성을 취소하고 바로 다시 보내면, 취소가 부른 백그라운드 저장이 파일을 읽는 사이 이어쓰기가 화면의 마지막 메시지만 늘려 `diff` → 방이 멈추고 경고. 답변 중(`mainBusy()`)에는 `more`·`diff`·`meta`를 `busy`로: 쓰지 않고, 멈추지 않고, 답변이 끝나면 다시 확인(`recheckAfterReply`).
- 막을 때 이유 표시(`whyDetail`).

## 특히 봐 줄 곳

1. `writeBase`: 성공 응답 없이 `written`을 기준으로 삼는 전제(그 뒤 파일에 들어간 사본은 `written`의 메시지를 모두 가짐, 이 화면 삭제는 `delLog`로 예외)가 틀리는 순서.
2. `busy`: 답변 중에 진짜 다른 기기 변경이 있을 때 미루는 사이 무엇이 쓰이는지(SavePoint는 쓰지 않음). `recheckAfterReply`가 끝나기 전 방 이동·새 답변 시작 같은 순서에서 `busy`가 풀리지 않거나 잘못 `ready`가 되는 경우.
3. `delLog`와 `gate.cuts`가 다른 값을 줄 수 있는 순서(`seenSent`가 이제 `delLog`를 씀).
