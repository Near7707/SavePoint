## 바뀐 것
- **P2:** 추가 읽기는 없어요. `guard`는 첫 요청 전엔 차례 읽기를 쓰고, 다시 보낼 때는 그 라운드에 읽은 파일(`file`)만으로 🔖 해제를 판단해요. `writeChatFile`의 `landed` 처음 호출(파일 없음)에서는 판단하지 않아요. 그 자리 메시지가 같은 메시지(`snapshot(...).plain`: 본문·작성자·스와이프, 🔖·숨김 제외)이고 메시지·모든 스와이프에 🔖가 없을 때만 화면에서 지워요. 같은 메시지가 아니면 🔖는 남기고 다시 보내기만 멈춰요. 차례 첫 읽기의 `keepOff`도 같은 조건이에요.
- **P3:** `putHeldHides`가 복구 대기로 건너뛴 숨김을 `stale`이 아닌 `wait`로 세요. 보낼 게 없고 `wait`(또는 설정)뿐이면 세이브 성공이에요. 원문·연결 변경이 섞이면 기존 안내예요.

## 특히 봐 줄 곳
1. 화면 메시지와 서버 메시지를 스와이프 목록까지 비교해요. 실리태번이 아직 저장 안 한 스와이프가 있으면 "같은 메시지 아님" → 🔖 남김(안전한 쪽). 이 엄격함이 문제 되는 장면이 있는지.
2. 첫 요청 뒤엔 늘 `landed`라 다시 보내기 전에 `fileAllows` 읽기가 있다고 봤어요. 파일 없이 `sent`인 채로 판단해야 하는 길이 남았는지.
3. 첫 읽기의 `keepSame`은 검사가 없어요(`serverCovered`가 위치를 맞춰서 어긋난 장면을 못 만듦).
4. P3에서 대기 메시지의 표시가 그사이 바뀐 경우는 예전처럼 `stale`(오류 안내)로 둬요.
