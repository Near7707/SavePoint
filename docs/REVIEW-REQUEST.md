## 지난 리뷰(v0.6.69 + v0.6.70)에서 고친 것

- P2 끝나지 않은 이전을 이름표만 붙여 복구 → 6번 `relink`는 `relinkMemory`로 남은 쓰기를 이어서(빠진 `moved-`·`copy-`·`int-` 먼저, 이름표 마지막, 본체 안 씀). 사본은 기억 파일의 것. 판정 때 본 본체(rev·영수증)가 그대로일 때만, 아니면 멈춤. 6번의 `copy-`는 본체를 읽은 뒤 새로 읽음. 이전이면 이름표 직전에 `copy-` 다시 확인(`writeCopy`가 없는 재시도 포함)
- 같은 원인: `int-` 단서 쓰기 실패 뒤 이름표만 복구 → 가져온 복사본이 8번 보류 대신 새 기억 → 같은 수정으로 막힘
- P3 손상된 되감기 기록 → 변경마다 `before`·`after` 존재·형식·순서 목록과 일치, `nextBefore`·`nextAfter` 네 번호 확인 → `noHistory`(슬롯 또는 보류). 같은 원인: `nextBefore` 누락으로 `next`가 비던 것

## 특히 봐 줄 곳

1. `relinkMemory`의 본체 확인을 (rev, wid) 일치로 한 것: 다른 기기가 그사이 같은 방을 연결하고 기억을 고친 경우 멈추는데, 그 뒤 다시 열기가 항상 3번으로 가는지.
2. 이름표 직전 `copy-` 재확인이 모든 이전 경로(처음·재시도·연결 복구)에 걸리는지, 그리고 분기·새 방 본체의 `relink`에서 놓치는 단서가 없는지.
3. 되감기 확인이 너무 엄격해 정상 기록을 막는 경우가 있는지(예전 버전 기억, 이력이 잘린 기억, 시간 고정점 `timeAnchors`가 있는 기록).
4. 채팅에 사본이 있지만 `copy.ok`가 아닌 경우(읽을 수 없는 예전 사본)의 6번·재시도.
