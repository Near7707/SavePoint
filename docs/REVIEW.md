# v0.6.24 · 출력 중 대기 연장, 타임라인 탭, 크리스마스 테마

기준: v0.6.23 `e7cbeed`. 수집 지침·분량·저장된 기억·주입은 변경하지 않음.

- `llm` 시간 제한: 실시간 수신(연결 프로필 + 실시간 받기)이면 `timeoutSec`(기본 300초)을 **새 출력 대기 제한**으로 사용. 처음 대기도 같은 시간이고, 사고·본문 글자 합계가 실제로 늘었을 때만 그 시점부터 다시 셈(같은 누적 응답 반복·빈 유지 신호는 제외). 별도로 `timeoutTotalMin`(기본 20분, 1–120) 전체 상한은 본문 작성 중에도 적용. 실시간 수신을 확인할 수 없는 요청(메인 API, 실시간 끔, 짧은 연결 시험처럼 시간을 지정한 요청)은 기존처럼 요청 전체 제한 하나.
- `RequestTimeout.kind`: `idle`(새 출력 없음) / `total`(전체 최대 시간 초과) / `limit`(제한 시간 안에 응답 없음). 요청 기록에 `limitMode`·`idleMs`·`totalMs`·`lastOutputMs`·`timeoutKind`, 결과 복사에 `시간 제한:` 줄과 중단 이유. 수집·기록 확인의 시도 줄도 이유별 문구. 요청 오류는 그대로 `요청 오류`.
- 진행 표시: `대기 5분 · 출력 중 연장 · 최대 20분` 또는 `전체 제한 5분`. 실시간 수신 중 30초 이상 새 출력이 없으면 `새 출력 없음 N초` 추가.
- 설정: `요청 대기 제한 (초)`, `전체 최대 시간 (분)`, 안내 "새 출력이 들어오는 동안 대기 제한을 연장해요. 전체 최대 시간에 도달하면 중단해요."
- 탭: 연표 → 📅 타임라인, 탭 줄 맨 앞(기본으로 열리는 탭은 여전히 저널).
- 테마: `gingerbread`(진저브레드 하우스), `xmasknit`(크리스마스 니트) 추가. 기록바 장식(리본·별·채움 끝 쿠키 / 전구 줄·호랑가시·채움 끝 벨), 하단 장식 줄, 세이브 배너 오른쪽 작은 장식, 루팅 창은 테두리만. 폰 폭에서 장식 줄 축소. `vanilla`는 `RETIRED_THEMES`로 `cream`에 연결.
- 중지 버튼: 폭 390–560에서 저장 중 동작 줄을 한 줄로 유지(글자 12px·여백 축소)해 모든 테마에서 `중지`가 같은 줄 끝. 390 미만의 작은 폰은 글자가 잘리지 않도록 기존처럼 줄바꿈.
- 검사: Node 333개, 브라우저 17묶음. `request-transport`에 출력 중 연장·반복 출력 무시·전체 상한·무출력 첫 대기·비실시간 단일 제한, 새 `wait-limit.cjs`(실제 스트리밍 프로필 흉내: 대기 제한보다 오래 사고해도 저장, 멈추면 이유와 결과 복사, 메인 API 표시, 테마별 중지 위치), 설정 화면 검사에 바닐라 버터 전환.

재검토할 것:
1. 실시간 수신 중 사고만 길게 이어지다 본문이 시작되는 요청이 대기 제한에 걸리지 않는지, 출력이 멈추면 대기 제한 뒤 `새 출력 없음`으로 끝나는지.
2. 전체 최대 시간이 출력 중에도 적용되고, 실패 기록·결과 복사에서 세 가지 이유가 구분되는지.
3. 바닐라 버터를 쓰던 설정이 크림 라테로 바뀌고, 새 테마의 배너·루팅 창·폰 폭 화면이 깨지지 않는지.

# v0.6.10 · 인포박스 날짜, 미확인 번짐, 루팅 실패 이유

기준: v0.6.9 `c72ae2a`. v0.6.8·v0.6.9는 Claude가 검토함(Node 278개·브라우저 14묶음 통과, 균등 분할 계획 시간은 큰 기억 + 200개 메시지에서 요청당 약 0.1초로 측정, 막는 문제 없음).

## 인포박스 날짜 (temporal.js)
- `normalizeStoryDate`: 유효한 ISO 날짜 뒤에 요일만 붙은 표현(`(Sun)`, `Sun.`, `, Sunday`, `(일)`, `(일요일)`)을 ISO로 줄임. 작품 고유 달력·잘못된 날짜·요일 아닌 꼬리는 그대로. 모델 주장, 기준점(cleanTimeAnchors), 직접 편집에 적용. 인용 확인은 원래 인용으로 함.
- 원인: 요일이 붙은 날짜가 고유 달력으로 저장되어, 같은 날의 `2026-10-25`와 글자가 달라 `same` 끝이 미확인이 됨. 다음 구간 시작이 미확인을 상속해 번짐. 날짜 덧셈도 끊김.
- `resolveStamp`의 `same`: 인용이 확인된 날짜/시간대/시각을 가진 `same`은 앞 구간이 미확인이거나 날짜가 다르면 explicit 규칙으로 처리함. 과거로 돌아가는 날짜 차단과 인용 없는 주장 거부는 그대로.
- `upgradeStoryTimes`: 저장된 주장을 현재 규칙으로 다시 계산(recomputeStoryTimes). 바뀐 경우에만 저장 예약. index.js state()에서 기억 객체마다 한 번, 실행 중이 아닐 때만. 직접 지정과 삭제된 앞부분의 경계 보존은 recompute 규칙을 따름.
- 수집 지침: 인포박스 줄은 explicit로, 날짜가 같아도 보고하도록 한 줄 추가.
- 화면: 장면 시간 줄에 ✎. 첫 미확인 가장자리(없으면 마지막 끝)의 편집 창을 열고 구간 목록을 펼침.

## 루팅 반영 실패 이유 (loot.js, index.js)
- `attachLoot`가 연결 못 한 id마다 `evidence`(포인트에 붙였지만 그 메시지를 근거로 안 적음) / `unlinked`(어디에도 안 붙임)를 반환(`used.why`). 수집 데이터에는 열거되지 않는 속성으로 보관해 검사·저장에 섞이지 않음.
- `settleLoot`는 이유 문장으로 `반영 실패 · …`을 남기고 `fails`를 셈. 응답에는 연결됐는데 저장 후 없으면 "검사에서 빠졌어요". 요청 오류·장면 없음도 같은 `failLoot` 경로.
- 대기열 카드: 이유, 2번째 이상 실패 횟수, 다음 세이브 재시도 안내(원문이 바뀐 항목 제외). 알림: 첫 이유 + 재시도 안내. 결과 복사: `[루팅 반영 실패 N개]` 항목별. 결과 복사 버튼은 반영 실패가 있어도 보임. 연결 규칙(근거 번호 일치)은 그대로.

## 검사
- Node 285개 통과(신규 infobox-time 6개, loot 이유 1개, 기존 loot 2개 기대 문구 갱신, state() 샌드박스 2곳 스텁 추가).
- 브라우저 14묶음 통과. story-time 16: 장면 ✎가 미확인 구간 편집을 엶. loot-bar 8: 대기열 카드·알림·결과 복사의 이유.
- 실제 모델 미확인: 인포박스를 쓰는 대화에서 각 구간이 explicit로 오는지, 요일 차이를 넘어 날짜가 이어지는지, 예전 미확인 구간이 열 때 살아나는지.

## 재검토 권장
1. `same` → explicit 전환이 회상·과거 날짜 인용·여러 기준점에서 잘못 확정하지 않는지.
2. `upgradeStoryTimes`가 직접 지정, 삭제된 앞 장면, 다른 방에서 불러온 기억에서 기존 확정값을 바꾸지 않는지.
3. 루팅 이유가 보충(supplement) 경로와 실패·취소 경로에서 맞게 남는지.

# v0.6.9 · 메시지 분량 균등 분할

기준: v0.6.8 `921e18197c624d2db3b8ed1ce4c7eaeee792b2af`.

## 적용 내용

- 기존 fill-first 계획을 안전 기준으로 보존하고, 매 요청 직전에 남은 메시지를 현재 기억으로 계획함. 메시지 개수보다 원문 글자 수(번호·화자·구분자 포함)를 균등하게 배분함.

## v0.6.4 · 2단계 약속·빚 기한, 대략 표현 차단

기준 커밋: b27215b6acf44740182e9648dfa68b4b3bd3c5dd (v0.6.3). 연표·시작 날짜 지정·실패 응답 임시 보관은 3단계로 남김.

대략 표현 수정 (v0.6.3 리뷰 후속):
- `temporal.js readElapsed`가 쯤/정도/가량/남짓/얼추/거의/안팎, 단위 뒤 넘게/이상/이내/여, nearly/almost/around/more than/less than/or so/over·under+수량을 만나면 일 수를 읽지 않음(null). `advanceQuoteMatches`는 읽은 일 수가 정확히 하나이고 응답과 같을 때만 통과. `다음 날 밤과 그다음 날`처럼 두 단계가 보이면 확정하지 않음.

기한 동작:
- 수집 응답 `add`의 `due {expr, days, date, msg}`: expr은 해당 메시지에 글자 그대로 있어야 저장. days는 `dueDaysMatch`(내일 1, 모레 2, 글피 3, 오늘/오늘 밤 0, 숫자 경과 표현)와 맞을 때만, date는 expr 안에 있을 때만 남김. 내일모레·며칠 안에·이번 주말은 표현만 보존.
- 위치는 저장하지 않고 매번 계산: 말한 구간(msg가 속한 구간)이 회상이 아니고 시작·끝이 같은 날로 확인될 때만 기준일 + days. 그래서 구간 시간을 고치면 기한도 따라감.
- 상태 left/today/past는 같은 기준점끼리 일 수, 다르면 실제 날짜끼리 비교. 둘 다 안 되면 `확인 필요`. `기한 지남`은 상태(open)를 바꾸지 않으며 화면·주입 모두 "마지막 기록 기준, 어겼다는 뜻 아님"을 붙임. 완료/실패한 약속은 표현만 표시.
- `setManualDue`: 지금 시간이 확인된 경우만 허용. `YYYY-MM-DD`(지금 기준에 실제 날짜가 있을 때) 또는 N일째. 직접 지정은 AI update가 덮지 않고, 내보내기·방 이동·되돌리기에서 유지되며 빈 값으로 해제됨. update의 due 교체는 manual이 없을 때만.

집중 재검토 지점: `temporal.js`의 `resolveDueClaim`, `madeAt`, `dueStamp`, `dueStatus`, `setManualDue`; `core.js applyResult`의 add/update due 처리와 `cleanMem`; `index.js saveEdit`의 사전 검증(복제본에 먼저 적용).

검증: Node 245개 통과(tests/deadline.test.mjs 9개 신설), 브라우저 13개 묶음 전체 통과(신규 deadline.cjs 포함). 실제 모델 호출은 하지 않음.

다음 실제 모델 확인: "내일 만나자" → 다음 날 → 이틀 뒤(기한 지남 표시와 퀘스트 진행 중 유지), "며칠 안에 갚을게"(표현만), "모레까지"(+2), "일주일쯤 뒤"(시간 미확인), 기한 뒤 "몇 주 뒤" 점프(확인 필요). 모델이 days를 직접 계산하거나 날짜를 지어내는지 응답 원문과 함께 볼 것.
