# 단계별 코드 리뷰 인계

## v0.6.4 · 2단계 약속·빚 기한, 대략 표현 차단

기준 커밋: b27215b6acf44740182e9648dfa68b4b3bd3c5dd (v0.6.3). 연표·시작 날짜 지정·실패 응답 임시 보관은 3단계로 남김.

대략 표현 수정 (v0.6.3 리뷰 후속):
- `temporal.js readElapsed`가 쯤/정도/가량/남짓/얼추/거의/안팎, 단위 뒤 넘게/이상/이내/여, nearly/almost/around/more than/less than/or so/over·under+수량을 만나면 일 수를 읽지 않음(null). `advanceQuoteMatches`는 읽은 일 수가 정확히 하나이고 응답과 같을 때만 통과. `다음 날 밤과 그다음 날`처럼 두 단계가 보이면 확정하지 않음.

기한 동작:
- 수집 응답 `add`의 `due {expr, days, date, msg}`: expr은 해당 메시지에 글자 그대로 있어야 저장. days는 `dueDaysMatch`(내일 1, 모레 2, 글피 3, 오늘/오늘 밤 0, 숫자 경과 표현)와 맞을 때만, date는 expr 안에 있을 때만 남김. 내일모레·며칠 안에·이번 주말은 표현만 보존.
- 위치는 저장하지 않고 매번 계산: 말한 구간(msg가 속한 구간)이 회상이 아니고 시작·끝이 같은 날로 확인될 때만 기준일 + days. 그래서 구간 시간을 고치면 기한도 따라감.
- 상태 left/today/past는 같은 기준점끼리 일 수, 다르면 실제 날짜끼리 비교. 둘 다 안 되면 `확인 필요`. `기한 지남`은 상태(open)를 바꾸지 않으며 화면·주입 모두 "마지막 기록 기준, 어겼다는 뜻 아님"을 붙임. 완료/실패한 약속은 표현만 표시.
- `setManualDue`: 지금 시간이 확인된 경우만 허용. `YYYY-MM-DD`(지금 기준에 실제 날짜가 있을 때) 또는 N일째. 직접 지정은 AI update가 덮지 않고, 내보내기·방 이동·되돌리기에서 유지되며 빈 값으로 해제됨. update의 due 교체는 manual이 없을 때만.

집중 재검토 지점: `temporal.js`의 `resolveDueClaim`, `madeAt`, `dueStamp`, `dueStatus`, `setManualDue`; `core.js applyResult`의 add/update due 처리와 `cleanMem`; `index.js saveEdit`의 사전 검증(복제본에 먼저 적용).

검증: Node 245개 통과(tests/deadline.test.mjs 9개 신설), 브라우저 13개 묶음 전체 통과(신규 deadline.cjs 포함). 실제 모델 호출은 하지 않음.

다음 실제 모델 확인: "내일 만나자" → 다음 날 → 이틀 뒤(기한 지남 표시와 퀘스트 진행 중 유지), "며칠 안에 갚을게"(표현만), "모레까지"(+2), "일주일쯤 뒤"(시간 미확인), 기한 뒤 "몇 주 뒤" 점프(확인 필요). 모델이 days를 직접 계산하거나 날짜를 지어내는지 응답 원문과 함께 볼 것.


## v0.6.3 · 흔한 시간 경과 표현 보완, 실제 모델 검사 준비

기준 커밋: 96c4814d516d78ce47536255161d4ec468642b79 (v0.6.2). 변경 범위는 시간 경과 인용의 표현 인식, 요청 안내, 회귀 검사임. 저장 형식·장면 경계·포인트 선택·기한 기능은 변경하지 않음.

- `그다음 날`·`바로다음 날`의 앞부분을 한 표현으로 읽어 기존 복합 숫자 차단에 걸리지 않도록 함.
- 일주일/한 주/a week=7, 보름=15, a fortnight=14. 아라비아 숫자 및 기존 영어 기본 수사로 주·fortnight 단위도 확인함.
- next/following + morning/evening/night, day after=1. day after tomorrow/next는 1일로 읽지 않고 미확인으로 보류함.
- 새 단위에서도 과거(전/ago/before), 대략적인 수량, 숫자 범위, 분수를 확정하지 않음. 글자·숫자 2자와 출처/범위 검사, 일 수 불일치 차단은 유지함.

집중 재검토 지점: `temporal.js advanceQuoteMatches`의 접두부 처리와 숫자/단위 캡처. tests/temporal.test.mjs에 붙여 쓴 표현, 주·보름·fortnight, 잘못된 일 수, 과거·범위·분수·더 긴 복합 표현, 저장/가져오기 흐름을 추가함. 모의 story-time 화면 검사는 `그다음 날`을 편집·방 이동·리와인드 흐름에서 사용하고, `일주일 뒤`가 요청 한 번으로 +7일 연결되는지 확인함.

검증: Node 235개 통과, 이번에 실행한 모의 story-time 브라우저 검사 25개 통과. 실제 모델/사용 중인 SillyTavern 세션은 호출하지 않음. 기존 12개 브라우저 묶음 전체의 마지막 실행 결과는 v0.6.2 절에 기록돼 있음.

다음 실제 모델 확인: 명시 날짜 → 그다음 날 아침 → 일주일 뒤 → 날짜 없는 연기 회상 → 현재 복귀 → 편지 속 과거 날짜 → 몇 주 뒤 → 그다음 날. 설정한 모델로 세이브한 뒤 각 구간의 날짜·확인 수준·원문 인용과 마지막 기록 기준 주입 줄을 비교할 것. 사용한 모델/원문/응답을 함께 남기면 표현 인식 실패와 AI의 의미 오판을 구분할 수 있음. 숫자 일치 검사는 미래 약속·회상·부정문을 모두 판별하는 자연어 분석기가 아니므로 그 구분도 확인 대상임.

## v0.6.2 · 두 번째 리뷰 후속 수정

기준 커밋: df320d47882b9f87e6eb8424db48476592be4408 (v0.6.1).

1. 장면 삭제 후 시간 편집: `editStoryTime`은 수정한 구간/시작·끝을 `recomputeStoryTimes`에 전달함. 수정 전 구간은 그대로 두며, 끝만 편집하면 같은 구간의 시작·중간(via)도 유지함. 전체 재계산에서도 첫 남은 구간의 저장된 기준/일 수와 미확인 경계는 보존함. 삭제된 앞 구간의 advance를 새로 적용하거나 현재 방의 옛 번호로 원문을 찾지 않음.
2. 시간 인용: 글자/숫자 두 자 이상일 때만 비교함. 문자 하나에 따옴표·마침표를 덧붙여도 통과하지 않음. 시간 경과는 `advanceQuoteMatches`에서 읽힌 일 수가 `days`와 일치해야 함. 현재 한국어의 흔한 경과 표현, 영어 기본 수사(a/one–ten), 아라비아 숫자 일 수 위주이며, 지원하지 않는 표현·모호한 수량은 미확인으로 보류함. 전체 이야기 저장은 막지 않음. 약속 조건의 `findQuote`는 그대로임.
3. 📌: 확인한 재현에서는 기존 buildInjection의 최종 중복 제거로 같은 문장이 이미 한 번만 출력됐음. 구조 보완으로 `refreshProvisionalOutlines`에서 📌을 제외해 ●만 남기고, 고정 포인트는 전용 주입 경로로 보냄. 고정/해제/선택 해제 후 개요 갱신과 주입 횟수를 검사함.

재검토 요청:

> v0.6.2에서 첫 장면을 삭제한 뒤 남은 마지막 구간의 시작/끝을 각각 편집해 주세요. 남은 앞 구간과 기준 일 수가 다시 1일째가 되면 안 됩니다. 첫 남은 구간의 시작이 이미 적용된 advance이거나 미확인일 때도 재적용/확정으로 승격되지 않아야 합니다. 다른 방 불러오기·cleanMem·리와인드에서도 확인해 주세요. 짧은 인용에서 한 글자+구두점은 거부하고, `다음 날`+3일처럼 인용과 일 수가 다르면 시간만 미확인으로 저장해야 합니다. 📌은 임시 개요에서 빠지고 고정 영역에 한 번만 주입되며, 해제하면 기존 ●/○ 상태를 따라야 합니다. 수정 전에 재현 조건과 영향부터 알려 주세요.

남은 의미 판단 한계: 숫자 일치 검사는 자연어의 미래 약속·회상·인용·부정·가정을 전부 판별하는 도구가 아님. 실제 모델 응답으로 시간 경과와 단순 언급을 구분하는지도 별도 확인해야 함. 재요청 입력 여유, 반복 시간 표시 축소, 약속 기한·연표·실패 응답 임시 보관은 후속 범위로 유지함.

검증: Node 232개, 로컬 모의 브라우저 12개 묶음의 검사 253개 통과. story-time 묶음에서 실제 편집/삭제/고정 버튼, 앞 장면 삭제 뒤 날짜 보존, 리와인드, 잘못된 일 수 인용을 검사함. 실제 모델과 사용 중인 SillyTavern 세션은 호출하지 않음.
