## 2단계 · 구간별 시간 모델과 저장 경로

변경: temporal.js 전체, core.js applyResult/cleanMem/memDiff/applyDiff, prompts.js OUTPUT_FORMAT/buildExtractPrompt, tests/temporal.test.mjs.

다른 AI에 전달할 요청:

> SavePoint v0.6.0의 temporal.js와 core.js의 시간 통합을 검토해 주세요. 먼저 수정하지 말고 재현 조건·위치·영향을 알려 주세요. 명시 날짜의 인용이 실제 구간 원문에 있는지, 미확인 이후의 상대 연결이 차단되는지, 모호한 점프에서 기준이 분리되는지, 회상이 현재 시간을 바꾸지 않는지 확인해 주세요. 직접 지정 이후의 상대 날짜만 재계산하고 다른 명시 날짜와 직접 지정은 유지해야 합니다. 다른 방의 #0을 현재 방 #0으로 해석하면 안 됩니다. cleanMem과 내보내기/불러오기, diff 되돌리기에서 시간과 기준점이 함께 보존되는지도 확인해 주세요. 같은 장면으로 정규화 병합되는 응답의 중간 시간 변화(via)와 인용이 사라지면 안 됩니다.

- 기준점 ID + 일 수 차이로 보관. 기준 날짜/표현은 레지스트리에서 표시하며 구간의 일 수를 바꾸지 않고 기준에 이름을 붙일 수 있음. 시작 날짜 지정 UI는 후속 범위.
- 코드의 quote 검증은 문자열 존재와 출처/구간 검사. `내일 만나자`가 현재 시간인지 등의 의미는 모델에 의존함. 실제 모델 응답으로 미래 약속·단순 회상·연기하는 회상·가정 문장을 구분하는지도 추가 검토 권장.
- ISO 날짜만 달력 연산. 고유 달력은 표현 + 상대 일 수로 유지하며 월 길이/연도를 추측하지 않음.
- 날짜만 잘못됐을 때 요약/상태 변경의 정상 저장을 막지 않음. 날짜가 정상이라는 이유로 잘못된 포인트 근거를 통과시키지도 않음.

검증: tests/temporal.test.mjs. 기존 Node 검사는 새 모듈을 테스트 샌드박스에 연결한 것 외에는 기대값을 바꾸지 않음.
