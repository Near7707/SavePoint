# 계획 · v0.7.0 기억 저장 분리 (확정, v0.6.64에서 0단계 시작)

0단계(v0.6.64)에서 코드로 옮기며 정한 세부와 계획에 없던 것은 [REVIEW.md](REVIEW.md) v0.6.64의 ★에 있어요. 코드는 `home.js`.

**왜:** 실리태번이 자기 타이밍에 화면 전체를 저장하는 것과의 경쟁(구조 리뷰 P1·P2-3)을 기억 쪽에서 없애기. 직접 채팅 쓰기·화면 기준 자동 재저장은 보류(새 답변·다른 기기 삭제를 덮을 수 있음). 원칙: **서버와 화면이 다르거나 저장 여부가 불명확하면 쓰기를 멈추고, 방을 다시 연 뒤 판단.**

## 무엇이 어디로
| 묶음 | 기능 | 쓰는 곳 |
|---|---|---|
| A. 기억만 | 버튼 편집(★⚓●✎🗑), 퀘스트·보관함·파티, 루팅, 기록 확인 결과, 체크포인트 결과 표시, 번역, 주입 다시 고르기, 슬롯 연결, 예전 형식 정리 | 기억 파일만 (**채팅 저장 0회**) |
| B. 기억 + 숨김 | 체크포인트·퀵세이브·장면 닫기(자동 하이드), 리와인드, 리셋, 같은 방 불러오기, 원문 변경 감지, 👻 수동 하이드 | 기억 파일 + 채팅의 숨김 표시 |
| C. 원문 | 새 방 이어하기 #0 | 채팅 파일 |
- **🔖는 이번에는 메시지에 붙여 둠**(채팅 파일, 숨김과 같은 수준). 🔖 고치기(`repairKeep`)도 지금처럼.
- 채팅 파일 속 예전 기억 사본은 **지우지 않음**(1단계 채팅 저장 0회). 이후 SavePoint는 그 키를 건드리지 않음.

## 파일 (모두 `user/files`, 채팅 파일에는 아무것도 안 씀)
- `mem-<기억ID>`: 기억 + 번호(rev) + 영수증(wid) + 최근 몇 번의 (rev, wid) 목록 + 출처(이전/분기/새 방) + home(방 주소·고유값).
- `room-<방 주소 해시>`: **방 이름표.** 방 주소 = **캐릭터(또는 그룹) 범위 + 채팅 파일 이름**(안에 전체를 적고 읽을 때 대조), 고유값, 기억ID, 원문 지문 몇 개, 상태(`연결`/`이름 바뀜 → 새 주소`).
- `int-<고유값 해시>`: 그 고유값을 가진 방 주소 **목록**. **검색 단서일 뿐, 이것만으로 연결하지 않음**(가져오기·복사본은 같은 값).
- `moved-<원본 방 주소 + 예전 사본 해시>`: **이전 완료 표시.** 옮긴 기억ID, 옮길 때의 번호. 해시만으로 공유하지 않음.
- **기억ID는 정해진 규칙으로**: 이전 = hash(방 주소 + 사본 해시), 분기·새 방 = hash(방 주소 + 고유값). 재시도가 같은 파일을 가리키고, **이름표가 없어도 이름으로 그 방 기억 파일을 찾을 수 있음.**
- **파일 읽기는 네 가지로 구분**(새 함수): 없음(서버가 없다고 답함) / 손상(파싱 실패) / 오류 / 정상. 손상·오류는 절대 "없음"으로 보지 않고 새로 만들거나 덮지 않음.

## 방 열기 판정 순서 (위에서 처음 맞는 줄에서 멈춤)
0. 필요한 파일 중 손상·오류가 있음 → **읽기 실패**(멈춤, 다시 확인만)

이름표가 있을 때
1. 고유값이 둘 다 있는데 다름 → **보류**
2. 채팅 속 예전 사본이 이전 기록과 다름(구버전 기기가 다시 씀) → **보류**, 합치지 않음
3. 같은 방 증명: 고유값 둘 다 같음 / (고유값 없음 또는 이름표에만 없음) 예전 사본 해시가 이전 기록과 같거나 **기록된 지문 1개 이상이 전부 일치**(0개는 통과 아님) / 이름표엔 있고 파일엔 없음 → 보류 / 증명 안 되면 **보류**
4. 같은 방 확인 뒤에만: 지문 일부 다름 → 연결 + 원문 변경 처리

이름표가 없을 때
5. 이 기기에서 확인된 이름 변경(`CHAT_RENAMED`, 실패하면 이 기기 설정에 적어 두고 다음에 재시도) + 고유값 일치 → 이름표 옮기기(옛 이름표는 `이름 바뀜`으로 남김). **원래 이름이 목록에서 사라진 것만으로는 이름 변경으로 보지 않음**(원본 삭제 후 가져오기와 구분 불가).
6. **기존 연결 복구(분기 판정보다 먼저)**: 이 방 주소로 정해지는 기억ID의 파일(또는 이 방을 가리키는 고유값 단서·이전 완료 표시)이 있고, 그 파일이 정상이고 home이 이 방과 같으면 → **그 방의 최신 기억에 이름표만 다시 연결**. 손상·오류면 멈춤.
7. 분기 조건(고유값이 부모와 다름 + `main_chat`이 같은 범위의 연결된 방) → 분기 이어받기(아래). 근거 부족하면 **보류**.
8. 같은 고유값이 다른 방에 연결돼 있음 → **보류**(후보로만 보여 줌)
9. 예전 사본이 다른 방에서 이미 옮긴 것과 같음 → **보류**
10. 예전 사본 있음 → **이전**
11. SavePoint 흔적(예전 사본, SavePoint 숨김 표시) 있음 → **보류**
12. 새 방. 고유값이 서버 파일에 생긴 뒤에만 기억을 만듦. 고유값 없는 옛 채팅은 같은 이름만으로 기존 기억을 붙이지 않음.
- 보류 중에는 어떤 파일도 쓰거나 지우지 않음.
- 0단계 검사: 각 줄 + "윗줄 조건도 같이 맞는 경우"(예: 고유값 다름 + 지문 일부 다름 → 1번 보류).

## 분기 이어받기
1. 부모 기억 파일을 읽어 **사본 위에서** 계산(부모 파일은 안 건드림).
2. 분기방 서버 파일 메시지와 부모 기억의 원문 지문을 비교해 처음 어긋나는 자리를 찾음.
3. 그 자리를 덮는 요약부터 되감음(`rollbackFrom`). 이력이 잘린 곳(`floor`)보다 앞이면 실패.
4. 되감은 결과의 기록된 지문이 **전부** 분기방과 일치해야 함.
5. 실패하면 부모 AUTO·QUICK 중 지문이 전부 맞는 것을 찾음. 없으면 **보류**.
6. 성공하면 새 기억ID로 저장, 되돌리기·검사 결과·슬롯 연결·실패 기록은 비움.
- 검사: 부모 #80 진행 뒤 #20 분기 / 분기 지점 마지막 스와이프 다름 / 이력 부족 ± 맞는 슬롯 / 부모 기억 못 읽음 / 부모가 앞쪽 원문 고침 / 첫 메시지부터 다름 / 분기의 분기 / 그룹 분기 / 실리태번 체크포인트 / **독립적으로 진행한 분기방에서 이름표만 없어짐 → 부모에서 다시 이어받지 않고 그 방의 최신 기억이 그대로 연결됨.**

## 이전과 재시도
- 처음 이전: 기억 파일이 있는지 먼저 확인 → 없으면 본체 → **다시 읽어 확인** → 이전 완료 표시 → 고유값 단서 → 이름표(마지막).
- **연결 복구와 본체 재작성 분리**: 기억 파일이 이미 있으면 본체는 절대 다시 쓰지 않음. 출처(원본 방·사본 해시)가 같으면 이름표만(번호가 더 새로워도 그대로 둠). 출처가 다르거나, 읽지 못하거나, 존재를 확인 못 하면 **멈춤**. 이전 완료 표시는 있는데 본체가 없으면 예전 사본으로 다시 만들지 않고 **보류**(슬롯 복구 안내).

## 저장 순서와 중간 실패 (규칙: "숨겨졌는데 기억에 없음"은 절대 남기지 않음)
- **자동 하이드:** 기억 파일 저장 → 성공 뒤에만 화면에 숨김 표시 → 채팅 저장. 기억 실패 = 아무것도 안 바뀜. 기억 불명 = 다시 읽어 판단, 모르면 그 방 쓰기 멈춤. 기억 OK·숨김 실패 = 기록과 원문이 둘 다 들어감(토큰만 더), 그대로 두고 안내.
- **리와인드·리셋·같은 방 불러오기:** 새 기억 미리 계산 → 더는 안 덮는 메시지 숨김 풀기 → 채팅 저장 → **다시 읽어 확인** → 기억 파일 저장 → (새로 덮은 게 있으면) 숨김. 해제 실패 = 화면 되돌림. 해제 불명 = 기억 안 바꾸고 멈춤. 기억 실패 = 원문 보임 + 예전 기억(겹침), 안내.
- **#0 이어하기:** ① 기억 파일에 "기억만 불러온 상태" + 연결 예정(새 #0 지문) → ② #0 교체 + `tainted` 채팅 저장 → 다시 읽기 → ③ 기억 파일에서 연결 확정. ① 실패 = 그대로. ② 실패 = 기억만 불러온 상태(⏪ 가능). ② 불명 = 멈춤, 나중에 #0 지문으로 판단. ③ 실패 = 다음 차례에 재확정, 끝내 못 하면 그 메시지가 한 번 더 기록될 수 있음(잃는 것은 없음).
- **방을 열 때는 채팅 저장 0회.** 숨김은 계산만: "보이는데 기억에 있음" → 그대로 두고 안내. "숨겨졌는데 기억에 없음" → 안내 + 자동 기록 멈춤. 방 열 때 원문 변경으로 되감아야 하면 표시만 하고 자동 기록 멈춤. `#0` 미확정은 서버 #0 지문으로 확정/취소(기억 파일만).
- **자동 기록 멈춤 조건:** 보류, 읽기 실패, 숨겨졌는데 기억에 없음, 분기로 복사된 숨김을 이어받은 기억이 못 덮음, `#0` 미확정, 원문 변경 되감기 대기. 다시 시작은 사용자가 `원문과 기억 맞추기`(위 순서, 이때는 채팅 저장 허용).
- 사용자가 메시지를 고쳤을 때의 원문 변경 감지는 지금처럼 바로(위 리와인드 순서).

## P2-3 경로 재분류 (모든 기억 변경은 방 대기열 안, 그 차례의 기억으로 계산)
| 경로 | 옮긴 뒤 |
|---|---|
| `noteAuto`·`recordAutoFail`·`settleAutoFail` | 대기열 + 실행이 살아 있을 때만 |
| `autoMark`·`autoHold`·`autoAttemptAt`(시작 시점) | 대기열(시작 때 한 번) |
| 기록 다시 확인 `check` | 결과만 대기열, "진행 중"은 화면에만(저장 안 함) |
| 보관함 알림 `returnTold`, 루팅 개수 예비 경로 | 대기열 |
| `state()` 예전 형식 정리 | 읽을 때 사본으로, 다음 실제 변경 때 함께 저장 |
| 지점 복사 `roomKey` | 없어짐 → 분기 판정이 대신 |
| 원문 변경 감지 `reconcile` | 기억 + 숨김 해제 → 리와인드 순서 |
| 🔖 고치기 `repairKeep` | 메시지 표시 → 지금처럼 채팅 저장 |
- 검사 모드에서는 대기열 밖에서 기억을 바꾸면 오류(빠진 길을 검사가 잡게).
- 기억만 바꾸는 작업은 채팅 파일을 읽지 않음. 체크포인트·퀵세이브는 기록 대상 판단을 위해 서버 채팅 비교(읽기만)는 유지.
- AUTO는 타이머 때의 화면이 아니라 방금 쓴 기억 파일 내용으로.

## 두 기기
- 쓰기 전: 파일의 (rev, wid)가 마지막으로 본 것과 **둘 다** 같아야 씀. 쓴 뒤 다시 읽어 내 wid여야 성공. 같은 번호의 동시 쓰기도 wid로 잡음.
- 방 열 때: 그 방 AUTO 중 기억 파일의 (rev, wid) 목록에 없는 저장이 있으면 "덮였을 수 있어요"(보장 아님).
- **README 알려진 한계에 적을 것:** 먼저 쓴 기기가 저장을 확인한 뒤 다른 기기가 덮으면 새로 연 화면은 알아채지 못할 수 있음. 다음 열기에서 항상 감지된다는 보장 없음. 덮인 내용은 AUTO가 실제로 남아 있을 때만 복구 가능. 읽기~쓰기 사이 짧은 틈은 서버가 막아 주지 않음.
- 검사 `two-device.cjs`: 같은 번호 동시 쓰기, 확인 뒤 덮기, 새로 연 화면 AUTO 단서 있음/없음. 실제 폰·PC로도 확인.

## 답변 막기 (v0.7.0에서 별도 판단)
- 막는 때: 보류·읽기 실패·확인 중 **이면서** SavePoint 흔적이 있는 방. 흔적 없는 새 방과 조용한 생성(SavePoint 요약·다른 확장)은 막지 않음. 확인 중이면 몇 초 기다렸다 판단.
- **일반 전송만 막기 확인창**: `GENERATION_STARTED`(지우기 전)에서 띄우고 결과를 "이 생성 한 번·이 방"에만 붙여 interceptor에서 진행/멈춤. 버튼: `다시 확인`, `취소`, `이번만 그대로 답변 만들기`(+ 후보가 있으면 `이름을 바꾼 방이에요 → 연결`, `원래 방 기억을 복사해서 시작`, `💾 슬롯에서 불러오기`).
  - **창 닫기는 동의가 아님**(일반 전송에서는 취소로 처리).
  - 취소하면 사용자 글은 채팅에 남음. 다시 답변 만들기는 **빈 칸 전송이 아니라 SavePoint 버튼**(`Generate('normal', { automatic_trigger: true })` 방식)으로 — `send_if_empty`가 켜져 있어도 새 사용자 메시지가 추가되지 않는지 확인.
  - 방을 옮기면 이전 방의 대기와 "이번만 허용"은 끝남. 확인창 중 방이 바뀌면 그 생성은 멈춤.
- **재생성·스와이프·이어쓰기는 안전하게 막을 수 있다는 게 확인될 때까지 막지 않고 상태 안내만**(재생성은 ③ 전에 기존 답변이 지워져서 `abort`가 안전하지 않음).
- 상태칸 맨 위에 이유 한 줄 + `다시 확인`. 자세한 화면은 v0.7.1.
- 실제 실리태번 검증(테스트용 방): 일반 전송 × `다시 확인`/`취소`/`이번만 그대로`/창 닫기 → 입력 중복·답변 유실 없음, `send_if_empty` 켠 상태에서 다시 만들기, 대기 중 방 옮기기. 재생성·스와이프·이어쓰기는 안내만 뜨고 동작이 그대로인지. 계획과 다르면 그 경로는 출시 전에 따로 해결.
